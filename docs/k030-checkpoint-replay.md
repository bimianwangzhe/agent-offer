# 检查点与轨迹回放

## 场景提问

你让程序跑一个要调十几次工具的长任务，跑到第九步进程被机器重启打断了。你重新跑，它却从第一步重来：前面几步里已经写出去的记录又写了一遍，已经花掉的调用又花了一遍，更糟的是你想弄明白「第八步到底为什么开始跑偏」，翻遍日志只看到一串散落的打印，前后对不上号。你隐约觉得应该在中间「存一下」，可到底存什么才够从断点接着跑、又该另外记些什么才能把过程重看一遍，两件事搅在一起理不清。

## 破误解

**不是把每轮对话都落盘就叫可恢复，检查点存的是「能接着往下跑的那份状态」，轨迹记的是「怎么一步步走到这儿的过程」，两者目的不同、缺一不可。**

先把两个词分开。检查点（checkpoint，在某一轮结束时把当时的状态完整存一份快照）回答的是「如果现在断了，从哪儿、带着什么继续」。它必须是自足的：光有这份快照，程序就该能重建出当时的状态、接着往下决策，不用回头重算前面所有步骤。轨迹（trace，按时间顺序把每一步的动作、观察、当时的状态记下来的流水）回答的是「到底发生了什么、哪一步开始不对」。它的读者是排查的人、是评测脚本、是想做假设推演的你自己。很多人把两者混为一谈，存了一堆「日志」却没存状态，于是重启后只能从头再来；或者只存了最后状态，出问题时根本说不清是怎么走到这步的。

再说清「回放」到底指什么，这里最容易想岔。回放不是「把发生过的事重新做一遍」，那叫重执行，会把已经产生的副作用再做一次——钱又扣一遍、信又发一遍。回放是「照着记下来的轨迹，把当时每一步的状态重算一遍、核对一遍」，本质是一次只读的推演：状态转移是确定性的、可重复的，所以给同一个起点和同一串动作，就该得到同一个终点。正因为是只读的，它才能安全地用来复现问题、定位「从哪步开始偏」、甚至把某一步的动作换掉看看「如果当时不这么做会怎样」，而不必担心把外部世界再改一遍。

这三件事合起来解决三类现实需求：断点续跑（崩溃或主动中断后从最近检查点接着走，见 [优雅中断与断点恢复](./k110-graceful-resume.md)）、问题复现（线上出了怪结果，拿轨迹在本机重算出来）、假设推演与评测（换一条决策看看会不会更好，对照 [结果评测与轨迹评测](./k089-trajectory-eval.md)）。要做到这些，有个前提绕不过去：状态本身得是能写成纯文本、能从纯文本还原的，也就是 [循环状态该存什么](./k027-loop-state.md) 里强调的「序列化与恢复」；而轨迹里每一步该记哪些字段，[Trace 该记什么](./k094-trace-fields.md) 有更细的清单。

## 生活类比

把它想成一次长途自驾，同车有两个人各记各的本子。副驾手里那张「当前位置、油量、目的地、已走过哪几条路」的便签，是检查点：车临时熄火、换个人来开，看一眼这张便签就能接着走，不必从出发地重开一遍。后座那本逐站记的行程簿，是轨迹：几点上了哪条路、在哪加的油、哪段走了冤枉路，一条条按时间排好，回头算过路费、复盘「为什么绕远了」全靠它。

对应关系要逐项对上。便签上的「当前位置」就是状态里的工作层与控制层（待办、已确认事实、第几轮、还剩多少预算）；「油量」是预算，油量见底就得停，对应 [四个终止条件](./k028-stop-conditions.md) 的判定；「换个人来开也能接着走」就是检查点的自足性——快照不能依赖前一个人脑子里的记忆。行程簿上「几点、做了什么、当时仪表盘读数」对应轨迹每步的动作、观察、状态快照；「复盘哪段绕远」对应定位跑偏的那一步；「如果当时不走那条路会不会更省」对应分叉推演，也就是 [时间旅行、重放与分叉](./k145-time-travel.md) 讲的那套。

这个比喻还点破两处要命的细节。第一，「重看行程簿」不等于「把路再开一遍」：你坐在家里翻本子算里程，车并没有动。回放是只读重算，不去真的再调一次工具、再写一次记录，否则复盘一次就把副作用重放一次。第二，便签要「记得够全」：只写「在高速上」没用，得写清在哪一公里、朝哪个方向、还剩多少油，否则接班的人还是得从头找。这正对应检查点必须是自足的完整状态，而不是一句模糊的进度描述。至于「已经付过的过路费别再付一遍」，靠的是给每笔副作用一个稳定标识，[幂等键与副作用防重](./k038-idempotency-key.md) 会把这件事讲透。

## 自绘示意图

:::figure 从执行到续跑再到回放的链路
@flow
每步记一条轨迹|关键处存检查点|崩溃从快照恢复|只读重放核对状态|换动作做分叉推演
:::

五个格子里，「每步记一条轨迹」和「关键处存检查点」是两件并行的活：前者细、后者粗，前者服务复盘、后者服务续跑。很多人只做了其中一件，结果要么能重看不能续跑，要么能续跑却查不出为什么出错。「只读重放核对状态」这一格是全篇的关键约束——重放时绝不调用真正产生副作用的那一步，它只重算状态、做比对。

:::figure 检查点与轨迹各自该装什么
@stack
检查点::某轮结束的完整状态快照，自足可还原
轨迹步::步号、动作、观察、该步状态、副作用标识
副作用账::已经对外做过的动作清单，回放时只读
起点锚::目标与约束，任何重放都不改它
:::

四栏里最容易漏的是「副作用账」。回放之所以能安全地只读，前提是每一步产生的副作用都被单独记了一笔、且带着唯一标识；重放核对时这份账只被读取、不被追加。「起点锚」则保证换动作做推演时，目标和红线不会被悄悄改掉，这和 [循环状态该存什么](./k027-loop-state.md) 里锚点只读是同一条纪律。

:::figure 两种「重来一遍」的差别
@compare
重执行全部动作::再扣一次款再发一次信|状态可能已变|结果无法复现
只读回放轨迹::外部世界不变|同起点同串动作得同终点|可定位跑偏那步
:::

左边把「重看」误当成「重做」，代价是副作用被重复、而且下游状态早就变了，根本复现不出当时那一幕；右边把状态转移当成可重复的纯计算，只重算不重做。二者的差距就在「有没有把副作用单独隔离出来」。真要判「重算出来的状态对不对」，可以写成一条条能自动检查的性质，思路见 [性质断言](./k088-property-assertion.md)。

## 层层追问

:::ask 那如果回放时那一步要调工具、工具结果当时和现在不一样呢？
:::

这正是「重执行」和「只读回放」必须分开的最硬理由。工具是会变的：查一次库存，当时的余量和现在不同；读一个外部状态，下一秒就被别人改了。若回放时真去再调一次工具，你拿到的不是「当时那一刻」的结果，而是「现在」的结果，用它重算出来的状态自然对不上，问题也就复现不出来。正确做法是把轨迹当成一份已经封存的事实：每一步当时的观察结果连同状态快照都被记了下来，回放时直接读这条记录里的值，而不是重新去取。换句话说，回放重算的是「状态转移这个函数」，它的输入是记下来的动作与观察，不依赖任何此刻的外部世界。这也解释了为什么状态转移最好写成确定性的纯计算——给定相同输入就得到相同输出，重算才有意义。真需要「用当下最新数据再跑一遍」时，那已经不是回放，而是一次新的执行，得走 [幂等键与副作用防重](./k038-idempotency-key.md) 那套标识去重，别把两件事混着做。

:::ask 那检查点存多密才合适？每一步都存不是最保险吗？
:::

这是第二层、也涉及取舍的一问。「最保险」和「最划算」不是一回事。每一步都存确实让续跑的断点最近，但代价是存快照本身要花时间和空间：状态里若有大段内容，频繁序列化会明显拖慢循环，还会堆出一大堆很快就用不上的历史快照。反过来，只在开头存一次，等于没存，崩了几乎要从头再来。合适的做法是按「代价高的节点」来设检查点：一次昂贵的工具调用刚完成、一轮可能产生对外副作用的动作刚落地、一个阶段性的子目标刚达成——在这些地方存，一旦中断，损失的只是这一小段。这里还有个容易踩的边界：检查点必须和「已经发生的副作用」对齐。如果状态存了「第三步已完成」，可第三步对应的那笔外部写入其实还没落稳，恢复后就会以为它做过、直接跳到第四步，于是漏做一笔。要避免这种「状态与副作用错位」，存快照时得连「哪些副作用已经确认落地」一起记，这正是 [幂等落盘](./k107-idempotent-persist.md) 里强调的稳定标识要解决的。至于生命周期更长的历史轨迹怎么留、留多久，属于记忆与日志的取舍，可对照 [记忆不是日志](./k065-memory-vs-log.md)。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，把「确定性状态转移」「每步记轨迹」「关键处存检查点」「只读回放」「换动作分叉」做成一台可独立运行的小机器，用本地构造的动作演示续跑与复现。复制到任意装有 Python 的机器上直接运行即可，不需要第三方包、账号或网络；结尾用一组断言逐条验证性质。

```python
import json


def step_once(state, action):
    """确定性状态转移：给定状态和动作算出新状态，不产生外部副作用。"""
    nxt = dict(state)
    if action["kind"] == "add":
        nxt["total"] = nxt.get("total", 0) + action["value"]
        nxt["seen"] = nxt.get("seen", 0) + 1
    elif action["kind"] == "tag":
        nxt["label"] = action["value"]
    return nxt


def side_effect(action, ledger, effect_ids):
    """模拟一次对外副作用：只在真正执行时调用，回放时绝不调用。"""
    eid = "eff-%d" % (len(effect_ids) + 1)
    effect_ids.append(eid)
    ledger.append((eid, action["kind"], action["value"]))
    return eid


class Recorder:
    """执行一串动作，同时记录轨迹、检查点与副作用账。"""

    def __init__(self):
        self.state = {"total": 0, "seen": 0, "label": "init"}
        self.trace = []
        self.checkpoints = {}
        self.ledger = []
        self.effect_ids = []

    def snapshot(self, state):
        return json.dumps(state, ensure_ascii=False, sort_keys=True)

    def run(self, actions, checkpoint_at):
        for i, action in enumerate(actions, 1):
            self.state = step_once(self.state, action)
            eid = side_effect(action, self.ledger, self.effect_ids)
            self.trace.append({
                "step": i,
                "action": action,
                "state": self.snapshot(self.state),
                "effect": eid,
            })
            if i in checkpoint_at:
                self.checkpoints[i] = self.snapshot(self.state)
        return self.state

    def replay_with(self, step, override=None):
        """只读重放：从检查点状态出发按轨迹重算，可选替换某步动作做分叉。"""
        if step not in self.checkpoints:
            raise KeyError("该步没有检查点")
        override = override or {}
        state = json.loads(self.checkpoints[step])
        ledger_len = len(self.ledger)
        for row in self.trace:
            if row["step"] <= step:
                continue
            action = override.get(row["step"], row["action"])
            state = step_once(state, action)
        assert len(self.ledger) == ledger_len, "回放触发了副作用"
        return state


def main():
    actions = [
        {"kind": "add", "value": 10},
        {"kind": "add", "value": 5},
        {"kind": "tag", "value": "done"},
        {"kind": "add", "value": 7},
    ]
    rec = Recorder()
    final = rec.run(actions, checkpoint_at={2, 4})
    checks = []

    checks.append(("轨迹步数等于动作数", len(rec.trace) == len(actions)))
    checks.append(("轨迹步号连续", [r["step"] for r in rec.trace] == [1, 2, 3, 4]))
    checks.append(("检查点等于该步轨迹状态",
                   rec.checkpoints[2] == rec.trace[1]["state"]))
    checks.append(("检查点自足且含中间进度",
                   json.loads(rec.checkpoints[2])["total"] == 15))
    checks.append(("副作用条数等于动作数", len(rec.ledger) == len(actions)))
    checks.append(("副作用标识互不重复",
                   len(set(rec.effect_ids)) == len(rec.effect_ids)))

    replayed = rec.replay_with(2)
    checks.append(("只读回放得到相同终点", replayed == final))
    checks.append(("回放未追加任何副作用", len(rec.ledger) == len(actions)))

    forked = rec.replay_with(2, override={4: {"kind": "add", "value": 100}})
    checks.append(("换动作分叉得到不同结果", forked != final))
    checks.append(("分叉结果可推算", forked["total"] == 115))

    passed = sum(1 for _, ok in checks if ok)
    for name, ok in checks:
        print(("通过 " if ok else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks)


if __name__ == "__main__":
    main()
```

1. `import json` 只取标准库，`snapshot` 用它把状态写成纯文本、`replay_with` 再用 `json.loads` 还原——这一对操作让检查点能落盘、能跨进程读回，是「自足可恢复」的前提。`sort_keys=True` 让字段顺序稳定，便于两份快照直接比对。
2. `step_once` 是整台机器的确定性来源：给定 `state` 和 `action`，用 `dict(state)` 复制一份再算出新状态，全程不碰外部世界、不记副作用。正因为它是纯计算，同样起点加同样动作必然得到同样终点，回放重算才有意义。
3. `side_effect` 单独模拟「一次对外动作」：生成一个带序号的唯一标识 `eid`，往 `ledger`（副作用账）里记一笔。`run` 里每步都会调它，而 `replay_with` 从头到尾不调它——「只读回放不重做副作用」这条性质，就落在「这个函数在回放路径里一次都没被调用」上，而不是靠一个永远返回空值的假变量。
4. `Recorder` 把四样东西分开存：`state` 是当前状态，`trace` 是每步流水，`checkpoints` 是关键处的状态快照，`ledger` 与 `effect_ids` 是已经对外做过的动作账。这种分栏正是「检查点」与「轨迹」各管一件事的落地。
5. `run` 遍历动作：先 `step_once` 更新状态，再 `side_effect` 记一笔副作用，然后往 `trace` 追加一条含步号、动作、该步状态快照、副作用标识的记录；若当前步在 `checkpoint_at` 里，就把这份状态快照存进 `checkpoints`。注意快照存的是「这一步做完之后」的完整状态，恢复后才能接着往下走。
6. `replay_with` 从指定检查点的快照出发，跳过步号小于等于它的记录，只对其后的每步用轨迹里的动作重算状态；`override` 允许把某一步的动作换掉，做「如果当时不这么做」的分叉推演。函数末尾用 `assert len(self.ledger) == ledger_len` 守住底线：回放一旦意外触发了副作用，断言立刻失败。
7. `main` 用四个构造动作、在第 2 和第 4 步设检查点。断言依次验证：轨迹步数、步号连续、检查点与对应步状态一致、检查点确实含中间进度（`total` 为 15 而非 0，说明不是从头开始）、副作用条数与唯一性、只读回放得到与真实执行相同的终点、回放后账本没增长、换动作分叉得到不同且可手算的结果（把第 4 步的 7 换成 100，`15 + 100 = 115`）。结尾 `print("通过 %d/%d 项" % ...)` 汇总、`assert` 保证任何一条性质被破坏都会以非零状态退出。

有一处要如实说明：这里用四个本地构造的动作代替了真实工具调用，用一份内存里的账本代替了真正的外部写入，为的是让「记轨迹—存检查点—只读回放—分叉」整条链路不依赖联网、账号或第三方包就能独立跑通并手算验证。它演示的是检查点与轨迹的分工、以及回放为什么必须只读，不是任何具体平台上的持久化实现。

## 踩坑与边界

- **把日志当检查点**：现象是重启后能翻出一堆打印，却只能从第一步重跑 → 原因是记的是「发生过什么」，没存「能接着跑的那份状态」 → 在关键节点存一份自足的完整状态快照，并验证光靠它就能还原继续，思路见 [循环状态该存什么](./k027-loop-state.md)。
- **回放时真的再调一次工具**：现象是复盘一次就重复扣款、重复发信，而且拿到的结果是「现在」的、复现不出当时 → 原因是把「重看」做成了「重做」 → 轨迹里封存每步当时的观察与状态，回放只读记录、不重新取数、不调用副作用，见 [幂等键与副作用防重](./k038-idempotency-key.md)。
- **状态与副作用错位**：现象是快照写着「第三步已完成」，可那步的对外写入还没落稳，恢复后直接跳到第四步漏做一笔 → 原因是存状态时没对齐「哪些副作用已确认落地」 → 存快照时连已落地的副作用标识一起记，稳定标识的做法见 [幂等落盘](./k107-idempotent-persist.md)。
- **每一步都存检查点**：现象是循环明显变慢、攒出一堆用不上的历史快照 → 原因是状态里有大段内容，频繁序列化成了负担 → 只在昂贵调用完成、副作用落地、子目标达成这类高代价节点存，别把「最密」当成「最稳」。
- **轨迹字段缺斤少两**：现象是想定位「哪步开始偏」却对不上号，前后状态衔接不起来 → 原因是每步没记全步号、动作、观察、该步状态、副作用标识 → 按固定字段记全，并用同一个步号把检查点与轨迹对齐，字段清单见 [Trace 该记什么](./k094-trace-fields.md)，日志侧的组织方式见 [结构化日志](./k095-structured-log.md)。

还要分清两条边界。「回放」默认假设状态转移是确定性的、观察已被封存；若某步本身依赖不可重现的随机或当下实时数据，能做到的往往只是「照着记录核对」，而不是严格重算出同一结果，别把两者说成同一件事。另外，检查点与轨迹是「记录与恢复」这一层的能力，它不负责评判「这串动作好不好」——把整条过程拿来打分、和结果评测区分开，是 [结果评测与轨迹评测](./k089-trajectory-eval.md) 的事；把回放结果当作回归比对的一道闸，则见 [回归门禁与基线](./k091-regression-gate.md)。

- [ ] 能解释「只读回放」和「重执行」的差别，以及为什么回放不能真去调工具
- [ ] 能说出一条轨迹步至少该记哪些字段，检查点为什么必须自足

## 三句话小结

检查点是在关键处存下的自足状态快照、用来崩溃后接着跑，轨迹是按步记下的动作与观察流水、用来复现问题与做假设推演，两者分工不同。

关键做法是把状态转移做成确定性纯计算、把副作用单独记进带唯一标识的账本，回放只读记录重算状态、绝不重做副作用，并把检查点设在真正高代价的节点上。

当任务一次调用就结束、或每一步都幂等且重跑代价极低时，未必需要这套机制；但只要循环长、有对外副作用、或需要复现线上问题，状态快照与过程轨迹就值得分开存好。
