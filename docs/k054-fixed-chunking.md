# 固定长度切分与重叠：最朴素也最容易切错的一刀

## 标准就写在文档里，偏偏答不出来

你明明把「一线城市每晚 600 元」写进了制度，用户一问，助手却回「未找到依据」。你把召回日志打出来一看，这句话被从中间劈成了两截：前一截落在上一段的末尾「一线城市每晚」，后一截落在下一段的开头「600 元」，哪一段单独看都不成立。你想加一点重叠把断口接上，结果重叠给多了，候选列表里挤满三四段几乎一样的内容，真正有用的片段反而被挤了出去。

## 先破一个误解

**不是检索器漏了，是你在切分那一步把一条完整结论劈成了两半。**

先把词说清楚。切分（chunking）指把长文档拆成一个个可独立检索的片段，每个片段叫一个块（chunk）。固定长度切分是最简单的一种：按字数或按 token（token 指模型读写文本的最小单位，白话叫「字块」）从头往后每满一段就切一刀，不看这里是不是一句话的中途。重叠（overlap）指相邻两块之间故意保留一小段重复内容，让跨在边界上的话有机会完整地落进某一块里。

为什么这一刀这么要紧？因为检索的最小单位就是块：索引按块登记，召回按块打分，拼进上下文的也是块。块一旦切坏，下游再精妙也救不回来。固定切分的真问题往往不是「切得不整齐」，而是切断了语义的自解释性——一个块失去标题和前文指代后，像「上述标准按 80% 执行」这种句子单独拿出来，谁也不知道「上述」指什么、适用于谁、什么条件下生效。重叠正是用来兜住这类断口的：让相邻两块共享一小段，跨边界的结论至少在其中一个块里是完整的。

但重叠是拿冗余换完整，必须算账。重叠越大，块数越多，索引越大，相邻块越像，召回时几个近似重复的块会一起挤进候选，把名额占满；而且同一句话可能被引用两次，答案里出现重复出处。所以两个数字要一起看：块大小决定每块能装多少上下文，重叠决定愿意为接住断口付多少冗余。它们不是越大越好，也不是能抄一个「业界常用值」当常量——得按内容类型分别定，法条、接口文档、代码、散文的合适粒度完全不同。想按自然边界切、少靠重叠硬接，见[语义切分与层级切分](./k055-semantic-chunking.md)；块切好后要带哪些定位信息，见[切分元数据与父块回溯](./k056-chunk-metadata.md)。

## 用给长文分页加便签来理解

把一份长材料想成要装订成册的手稿，固定长度切分就是「每满若干字订成一小册」，重叠就是「每两册之间重复印上前一册末尾的几行」。

为什么重复印几行？因为读者翻到第二册第一页时，若正好是一句话的下半截，没有前因就会读懵；把前一册最后几行再印一遍，这句话就完整了。这跟切分的道理一样：块是检索的最小单位，读者（模型）每次只拿到其中一册，看不到别册的内容。

对应关系：每册的页数是块大小，重复印的那几行是重叠，一句话被分装到两册是语义被切断，册与册内容高度雷同是冗余，书架上摆不下那么多册是索引与候选名额被占。这个比喻也解释了为什么重叠不能贪多：你把每册的一半都重复印，册数是翻倍了，书架上大半是重复内容，真正新的那几页反而没地方放。

:::quote
重叠是拿冗余换「不让结论被劈断」。它只解决块边界上的断口，解决不了块里缺主语、缺条件这些更深的毛病。
:::

## 把切分与重叠画出来

先看一份长文本从进来到成为候选块，经过哪些动作。

:::figure 从长文本到可检索的块
@flow
读入全文|按长度切|加相邻重叠|登记块编号|进入索引
:::

「按长度切」和「加相邻重叠」是两件独立的事，先定块大小再定重叠，别把两个数字混着调。

两个参数各管什么，可以列成一张清单：

:::figure 块大小与重叠各自管什么
@stack
块大小::决定单块上下文够不够、会不会稀释检索精度
重叠::决定跨边界结论能不能完整落进某一块
块编号::决定召回后能否拼回原文顺序与来源
冗余::重叠越大越多近似块，越容易占满候选名额
:::

第四行要盯着：重叠带来的重复块不是「多一份保险」，是实打实占了候选名额。名额是稀缺资源，被近似重复块吃掉，就等于把别的证据挤了出去。

再看两种设法的差别：

:::figure 零重叠，与带适度重叠
@compare
零重叠::不留冗余|跨边界结论易被劈断|答案常缺半句
适度重叠::断口能接住|块数变多|重复块占名额
:::

第二行三个要点是一体的：重叠接住了断口，代价是块数与冗余一起涨。判断重叠够不够的标准很朴素——把那些跨边界的关键结论逐条找出来，看每一条是不是至少完整地落进了一个块。

:::tip 一条立刻见效的规则
先用零重叠跑一遍，把你最在意的几条结论逐条检查「是否完整落在某块里」；只对确实被切断的那些边界补重叠，而不是一上来就给全文统一加一大段重复。
:::

## 再往深问两层

:::ask 那如果块切小一点、重叠给足一点，是不是就万无一失了？
:::

恰恰相反，两个方向拧着来。块太小，向量表征确实干净，但常缺主语、缺限定条件、缺例外条款，模型只能靠猜；块太大，上下文倒是全了，可一整块的语义被「主题平均」掉了，更容易被整章的笼统印象盖过那句具体答案，而且超过嵌入模型能处理的长度时，多出来的部分可能被静默截断——不报错，等于这部分内容根本没进索引。重叠给足则制造大量近似重复块，还会让同一句在答案里被引用两次。所以不存在「越小越保险」，只有按内容类型找拐点：先固定一组评测问题，扫几档块大小，看哪一档该找的片段能被找回来，再定重叠。这个扫法属于[多轮检索与检索质量评测](./k064-rag-eval.md)要反复做的事。

:::ask 再深一层：与其靠重叠硬接断口，有没有更省的办法？
:::

有，思路是换掉「按字数切」这个前提。按标题、段落、句子这些自然边界切，一句话本来就不会被劈开，重叠的需求自然下降；再进一步，把检索用的小块和作答用的大块分开：用小块精准命中，命中后顺着父子编号回溯到它所属的完整章节，把大块送进生成。这样「接住断口」不再靠重复印几行，而是靠命中之后把上下文补全，冗余自然消失。这也解释了为什么同时做大量重叠又做父子回溯是双重浪费——两件事都在补同一份上下文，却付了两遍名额。按自然边界切的做法见[语义切分与层级切分](./k055-semantic-chunking.md)，父子编号怎么存、命中后怎么回溯，见[切分元数据与父块回溯](./k056-chunk-metadata.md)。固定切分不是不能用，而是适合结构不明显的纯文本、或者作为先跑通链路的起点；一旦材料里满是标题、表格、条款，就该让位给更懂结构的切法。

## 一份能跑的对照

下面这段只用标准库，实现固定长度切分与重叠，构造一句正好跨在边界上的关键结论，用断言演示「零重叠时它被劈断、加上重叠后完整落进某块」，并顺带验证重叠带来的块数变化与原文可重建。

```python
# fixed_chunk.py —— 只用标准库，python fixed_chunk.py

TEXT = (
    "差旅制度第一条 员工出差应提前申请。"
    "住宿标准 一线城市每晚 600 元 其他城市每晚 400 元。"
    "报销须在行程结束后七个工作日内提交发票。"
)
KEY = "一线城市每晚 600 元"          # 一句我们要保住的完整结论


def fixed_chunk(text, size, overlap):
    assert 0 <= overlap < size          # 保证每刀都往前走，不会死循环
    out, start = [], 0
    while start < len(text):
        end = min(start + size, len(text))
        out.append(text[start:end])
        if end == len(text):
            break
        start = end - overlap
    return out


def rebuild(chunks, overlap):
    # 去掉相邻块的重叠部分，拼回原文
    s = chunks[0]
    for c in chunks[1:]:
        s += c[overlap:]
    return s


if __name__ == '__main__':
    no_ov = fixed_chunk(TEXT, size=24, overlap=0)
    with_ov = fixed_chunk(TEXT, size=24, overlap=8)

    assert with_ov[0][-8:] == with_ov[1][:8]     # 相邻块正好重叠 8 个字
    assert len(with_ov) > len(no_ov)             # 重叠让块数变多
    assert not any(KEY in c for c in no_ov)     # 零重叠：结论被劈断
    assert any(KEY in c for c in with_ov)       # 加重叠：至少一块完整收下
    assert rebuild(with_ov, 8) == TEXT         # 去重叠后可无损拼回
    print("通过 5/5 项：固定切分、重叠接断口、冗余与无损重建")
```

1. `TEXT` 是本地构造的一段短制度，中间那句 `KEY` 是刻意安排的：它的起点正好落在第 24 个字附近，零重叠时会被上一块的末尾和下一块的开头分走。
2. `fixed_chunk` 是切分主体：`size` 是块大小，`overlap` 是重叠，每轮取 `[start, start+size)`，下一刀的起点回退 `overlap` 个字。开头那条 `assert 0 <= overlap < size` 很要紧，重叠一旦不小于块大小，起点就不再前进，循环会卡死。
3. `rebuild` 把第一块之后的每块去掉前 `overlap` 个字再拼起来，用来验证「重叠只是重复，没有丢字」。能无损拼回，说明切分逻辑没漏内容。
4. 第三条与第四条断言是这段代码的重点：同样是 `size=24`，零重叠时 `KEY` 在任何一个块里都不完整，加上 8 个字重叠后，至少有一个块把整句收下了。这就是重叠唯一该解决的问题。
5. `if __name__ == '__main__':` 五条断言跑完打印通过项数。可以自己把 `size` 调到 20、把 `overlap` 调到 12，看看哪一组既能接住断口、块数又不至于翻倍。

注意这段代码里的「字」是 Python 字符串的一个字符，不是 token。真实系统按 token 计量时会更复杂，中文、数字、符号的换算差异都不小，但「先定块大小、再定重叠、逐条检查关键结论」这套做法不变。

## 踩过的坑

- **按窗口上限而不是按嵌入长度定块**：现象是长块被静默截断，块尾内容根本没进索引 → 原因是把块大小贴着生成模型的窗口走，忽略了嵌入侧的长度限制 → 怎么改：先确认嵌入侧能处理多长，统计入库块的长度分布，超限比例明显就说明参数不匹配。
- **重叠过大挤占候选**：现象是召回前几名几乎都是同一段话的变体，别的证据进不来 → 原因是重叠制造大量近似重复块 → 怎么改：压低重叠，或改用父子回溯补上下文，别两头都做。
- **只调两个数字不看内容**：现象是法条、代码被从条款中间切断 → 原因是固定长度不认结构 → 怎么改：按标题段落等自然边界切，或至少给块带上标题路径。
- **重复引用**：现象是答案里同一依据被标了两次 → 原因是重叠块都进了上下文 → 怎么改：送进生成前按片段编号去重，同一来源只保留一次。
- **把某个推荐值当常量**：现象是换一类文档后召回明显变差 → 原因是块大小存在拐点而非单调最优，抄来的数字不适配新内容 → 怎么改：在固定的一组评测问题上扫几档粒度，按该找的能不能找回来定。

## 三句话

固定长度切分与重叠，是按固定字数把长文切成可检索的块、并让相邻块共享一小段以防结论被劈断的做法。
关键做法是先定块大小再定重叠，逐条检查跨边界的结论是否完整落在某块里，同时盯住重复块占名额。
当材料满是标题、条款与表格时，别靠加大重叠硬接，改用按自然边界切分或父子回溯更省。
