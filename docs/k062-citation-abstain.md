# 溯源、拒答与零召回兜底：答案必须指得回材料

## 引用「能点开」，内容却不支持

助手答了一串条款，末尾规规矩矩标了 `[1] [2]`，用户点开出处一看，`[1]` 讲的是别的产品，`[2]` 干脆是模型编出来的编号。更难堪的是另一类问题：库里根本没有答案，助手却不肯说不知道，凭印象编了一段看似合理的说明。你把提示词改成「请依据材料回答，不确定就说不知道」，它照样有问必答。

## 先破一个误解

**不是提示词写得不够硬，是「有没有依据」这件事根本不该交给模型自己判断。**

先把几个词说清。溯源指答案里每个论断都能指回具体片段，通常写成编号引用，并且这个引用要能被校验：编号真实存在、落在本次给出的证据列表里、而且那段原文确实支持这句论断。拒答指证据不足或重排分数太低时，系统明确返回「未找到依据」，而不是让模型用记住的知识补全。零召回兜底是拒答的一个特例：一条候选都没捞回来时，必须有一条确定的降级路径，比如返回固定话术、转人工核对、或只回原文片段让人工判断。

为什么不能靠一句提示词？因为模型被训练成有问必答，证据不足时它倾向于用参数里的旧知识把话补圆，而且补得很像真的。这里还要分清两类幻觉：一类是检索根本没召回正确证据，模型凭空编；另一类是证据明明就在上下文里，模型却读错、合并、篡改了数字或条件——后者更危险，因为它披着「有出处」的外衣。所以抑制要分几层：把隐式引用变成显式可审计的编号约束，让生成时先摘录原文再作答，答案出来后再把论断逐条拆开做一致性核对。

最靠得住的一道闸门是确定性的分数判断：把重排的最高分与一个阈值比，低于阈值直接走「未找到依据」分支，比让模型自己决定可靠得多。阈值也不能拍脑袋定，正确做法是在一组固定评测问题上，把「精确率」和「拒答率」画成一条取舍曲线，按业务能容忍多少错误来选点。这里有个反直觉的点：拒答率不是越低越好。拒答率与用户追问率一起上升，往往说明召回层或阈值有问题；此时放宽生成约束是最差的选择，只是把看得见的拒答换成看不见的错误。阈值怎么定、精排分从哪来，见[粗排 + 精排与重排后截断](./k061-rerank.md)；评测集里为什么必须放「语料中无答案」的题，见[多轮检索与检索质量评测](./k064-rag-eval.md)。

## 用写带注释的报告来理解

把生成答案想成一位助理替你写一份带脚注的报告，材料就是手边那摞原始文件。

不合格的助理会先洋洋洒洒写完，再随手在段尾补几个脚注编号，编号看着齐整，翻到后面却发现有一页根本不存在，另一页讲的根本不是这回事。合格的做法反过来：每写一句结论，先回到原始文件把那一页找出来、摘录下来，再在句尾标上页码；写完后逐条核对，编号对不对、那一页是否真支持这句话，都对得上才交稿。

要是手边压根没有相关文件呢？合格的助理不会凭印象替你补一段，而会明说「这部分材料里没有，我不敢写」，并把问题记下来请你确认。这比交一份读起来通顺、却无人能负责的报告强得多。

对应关系：原始文件是证据片段，页码是引用编号，摘录再作答是证据绑定，逐条核对是后验一致性校验，「材料里没有」是拒答，一摞文件全不相关就是零召回。这个比喻点出了三件事的顺序：先有原文、再有结论、最后核对，而不是先有结论再补出处。

:::quote
引用能点开不等于内容真的支持该论断。可信的答案要过三关：编号存在、编号在证据列表内、原文确实撑得住这句话。
:::

## 把溯源链路画出来

先看一次回答从证据到可交付文本，经过哪些动作。

:::figure 从证据到带出处可核对的答案
@flow
取回证据|按分数判依据|生成带编号答案|校验引用编号|不足则拒答
:::

第二步「按分数判依据」排在生成之前，是这套设计的要害：先由代码判定有没有资格答，再谈怎么答。

一个可交付答案该满足什么，可以列成清单：

:::figure 答案要过的四关
@stack
编号存在::答案里每个 [n] 都能在证据表里查到
范围合法::编号落在本次给出的证据列表内，不是别的轮次
内容支持::被引原文确实撑得住这句论断，不是相似话题
兜底明确::零召回或分太低时走确定分支，不留空白
:::

第三关最费事也最容易被跳过：编号合法只是形式，内容支持才是实质。

再看两种取向的差别：

:::figure 让模型自己判断，与系统先判再答
@compare
交给模型判断::有问必答|编号可能编造|放宽约束只是藏错
系统先判再答::分数低于阈值即拒|引用可逐条核|宁可说不知道
:::

第二行最后一格常被投诉「什么都答不上来」，但把这条规则删掉，换来的不是更好的答案，而是更难发现的错误。

:::tip 一条立刻见效的规则
把「有没有依据」做成生成之前的一次代码判断：证据为空、或重排最高分低于阈值，就直接返回固定的兜底文本。模型只在通过这道判断之后才被允许作答。
:::

## 再往深问两层

:::ask 那如果证据够、编号也对，答案就一定可信了吗？
:::

还差一层，而且是最容易被「有出处」迷惑的一层。编号合法性与内容支持是两件事：`[2]` 这个编号真实存在、也在本次证据里，但模型可能把两段材料各取一半拼成一句原文没有的话，或者把「每晚 600 元」抄成「每晚 800 元」。这类忠实性问题披着合法引用的外衣，比凭空编造更难发现。所以答案出来后还要做一次核对：把答案拆成若干条独立断言，逐条判断它能不能从被引证据里推出来；涉及金额、期限、比例这类硬数字的断言，值得全量核对，纯流程性描述至少也要把引用编号合法性查一遍——这一步成本几乎为零，却能拦住「编造引用」这种最露馅的错误。多份证据互相矛盾时，别指望生成端自己选，要在检索侧把生效日期、版本号作为元数据带进来并去重，否则面对三条冲突条款，提示词怎么写都只能选一个或全部罗列。冲突怎么裁决见[索引更新、增量与知识冲突](./k063-index-update.md)。

:::ask 再深一层：阈值定高了老拒答、定低了又出错，到底该按什么选？
:::

按「业务能容忍多少错」来选，而不是按「希望拒答率好看」来选。做法是把一组固定评测问题里每条的「重排最高分」和「答对与否」记下来，以分数为横轴扫一遍：阈值取高，答的题少、但留下来的更准，拒答率升；阈值取低，答的题多、错误也跟着多。于是得到一条精确率与拒答率的取舍曲线，选哪个点取决于场景——涉及金额、法条、医疗剂量这类「答错代价极高」的问题，宁可把点往高精确率那侧挪，明确接受更高的拒答率；闲聊式、容错高的问题可以往低阈值挪。选完还要把阈值与提示词版本、模型版本一起记下来，否则语料一变、模型一换，分数分布悄悄漂了，原来的点就不合用了，这类漂移要靠[回归门禁与基线](./k091-regression-gate.md)来守。另外别忘了兜底本身要「确定」：零召回时返回固定话术或转人工，而不是让模型临场发挥一段「可能是……」，也不是抛一个空结果让下游继续编。整套顺序可以从[从这里开始](./00-start-here.md)看起。

## 一份能跑的对照

下面这段只用标准库，做三件事：校验引用编号是否真实存在、在证据不足与零召回时走确定的拒答分支、以及在一组构造数据上扫阈值看精确率与拒答率的取舍。

```python
# cite_abstain.py —— 只用标准库，python cite_abstain.py
import re

EVIDENCE = {"1": "一线城市每晚 600 元", "2": "其他城市每晚 400 元"}


def check_citations(answer, evidence):
    # 挑出编号不存在、或不在本次证据列表里的引用
    used = re.findall(r"\[(\d+)\]", answer)
    bad = [u for u in used if u not in evidence]
    return used, bad


def answer(evidence, best_score, threshold):
    # 先由代码判「有没有资格答」，通过后才允许生成
    if not evidence:
        return "未找到依据，已转人工核对", "零召回兜底"
    if best_score < threshold:
        return "未找到依据，不予作答", "分数不足拒答"
    return "一线城市每晚 600 元 [1]", "正常作答"


# 构造的一组演示数据：(重排最高分, 是否答对)
CASES = [(0.9, 1), (0.8, 1), (0.6, 0), (0.5, 1), (0.3, 0), (0.2, 0)]


def sweep(cases, threshold):
    answered = [c for c in cases if c[0] >= threshold]
    correct = sum(c[1] for c in answered)
    precision = correct / len(answered) if answered else 1.0
    abstain = 1 - len(answered) / len(cases)
    return precision, abstain


if __name__ == '__main__':
    fake = "一线城市每晚 600 元 [1]，其他城市 400 元 [2]，另有说法 [99]"
    used, bad = check_citations(fake, EVIDENCE)
    assert used == ["1", "2", "99"]
    assert bad == ["99"]                    # 编造的编号被挑出来
    assert "600 元" in EVIDENCE[used[0]]      # 引用指得回真实原文

    assert answer({}, 0.0, 0.5)[1] == "零召回兜底"
    assert answer(EVIDENCE, 0.3, 0.5)[1] == "分数不足拒答"
    assert "[1]" in answer(EVIDENCE, 0.9, 0.5)[0]

    p_hi, a_hi = sweep(CASES, 0.8)         # 阈值取高：只答最有把握的
    p_lo, a_lo = sweep(CASES, 0.2)         # 阈值取低：几乎全答
    assert a_hi > a_lo                     # 阈值高，拒答更多
    assert p_hi >= p_lo                    # 但留下来的更准
    assert 0.0 <= a_hi <= 1.0
    print("通过 8/8 项：引用校验、零召回兜底、分数拒答与阈值取舍")
```

1. `EVIDENCE` 是本次给出的证据表，键是编号、值是原文。它模拟的是「这一轮真正递给模型的片段」，编号范围以它为准，别的轮次或别的材料里的编号一律不算。
2. `check_citations` 用 `re.findall(r"\[(\d+)\]", ...)` 把答案里的引用编号全抓出来，再逐个查是否在证据表里。`bad` 就是那些编造或越界的编号。
3. `answer` 体现「系统先判再答」：先看证据是否为空（零召回兜底），再看最高分是否低于阈值（分数不足拒答），两关都过了才返回带编号的答案。注意这两条分支返回的是固定文本，不给模型临场发挥的空间。
4. `CASES` 是本地构造的一组演示数据，`sweep` 以阈值为横轴算精确率与拒答率。它不是任何真实测量的结果，只用来把「阈值往哪挪、代价是什么」这件事算清楚。
5. 八条断言跑完打印通过项数。前几条验证引用校验与两类拒答，后三条验证取舍方向：阈值取高时拒答更多、但留下来的更准。可以自己把 `threshold` 从 0.8 改成 0.5，看精确率与拒答率怎么一起变。

## 踩过的坑

- **靠提示词压拒答**：现象是写了「不确定就说不知道」，模型照样有问必答 → 原因是模型倾向用参数知识补全、且不会自己判断证据强弱 → 怎么改：把有无依据做成生成前的代码判断，低于阈值直接走兜底。
- **只查编号不查内容**：现象是引用合法、数字却被改了或条件被合并了 → 原因是编号存在不等于原文支持该论断 → 怎么改：把答案拆成断言逐条核对，涉及金额期限比例的全量核对。
- **零召回返回空结果**：现象是下游拿着空白继续编出一段话 → 原因是空结果被当成「成功但没内容」 → 怎么改：返回确定的兜底文本或转人工，别留空白。
- **被投诉就放宽拒答**：现象是拒答率降了、错误投诉却升了 → 原因是放宽生成约束把看得见的拒答换成了看不见的错误 → 怎么改：去查召回层与阈值，而不是删规则。
- **阈值不随版本走**：现象是换模型后答案悄悄变松 → 原因是分数分布漂了、阈值还停在旧点 → 怎么改：阈值与提示词版本、模型版本一起记录，接回归门禁。

## 三句话

溯源、拒答与零召回兜底，是让每条论断指回具体片段并逐条校验，证据不足或零召回时走确定的「未找到依据」分支。
关键做法是生成之前先由代码按证据与分数判资格，答案出来后再拆成断言核对内容支持，阈值按业务容错来选。
当问题纯属开放闲聊、根本不要求依据时，不必套引用与拒答这套约束，直接作答更自然。
