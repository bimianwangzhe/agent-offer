# 长期记忆与向量化存储：跨会话留得住，还要取得准

## 场景：上次明明说过，换个会话又问一遍

你给助手加了持久化，用户上周说过「报告一律导出成便携文档格式（Portable Document Format，简称 PDF）」，你也确实写进了文件。这周新会话一开，用户说「把这份整理一下给我」，助手又老老实实问「您想要什么格式」，用户有点恼火：不是说过吗。你查文件，那条记录好好地躺在那里，没丢。再查另一个工单，情况更糟：三个月前用户临时说过一次「这次先给我纯文本」，助手把这句话当成了长期偏好，一直沿用到现在，怎么都改不过来。一个该取回的没取回，一个不该当真的被当真了。存是都存住了，问题全出在「取」这一步。

## 先破一个最常见的误解

**不是存不住，是「存住了」和「取得准」根本是两件事，而旧信息被当真往往是因为取回时少了时效与来源的判断。** 长期记忆指的是跨会话保留下来的稳定事实，它跟短期窗口最大的不同是「会话结束之后还在」。很多人把力气全花在怎么把它写得牢、写得快，却忽略了一个事实：一条存着的记录，只有被本轮取回来才会影响回答；取不回来等于不存在，取回来一条过期的则比不存在更糟。所以真正的难点有两个：一是按「像不像」把相关条目找出来，二是判断找出来的这条现在还算不算数。这里先解释两个词。「向量」是把一段文字转成一组数字的办法，转完之后机器就能用数字比两段话像不像，而不用逐字去对；「余弦相似度」是衡量两组数字方向接不接近的一种算法，结果越接近一越像、越接近零越不像。它们只回答「像不像」，从不回答「对不对、还新不新」——把后面这两个问题也交给相似度，就是旧信息被当真的起点。

## 用生活里的事打个比方：贴着特征标签的旧档案柜

把长期记忆想成一间档案室，里面每张卡片写一条稳定事实。卡片不是按日期排的，而是按「内容特征」贴了一组标签：写「导出」的卡片贴着导出、格式、文件这类标签，写「时区」的贴着时区、地区这类标签。来了一个新问题，管理员不逐张翻，而是先看问题本身带哪些特征，再去比对卡片上的标签，把最像的几张抽出来放到桌上。对应关系逐条对一遍：卡片就是一条事实条目；那组特征标签就是这段文字转出来的向量；比对标签就是算相似度；「只抽几张」就是条数上限，因为桌子（本轮输入额度）就那么大，不能把整柜搬过来。这个比方还顺带露出两个危险。第一，一张三个月前的旧卡片，标签可能贴得跟当前问题很像，可它早失效了；光看「像」就会把它抽出来当真。第二，问题里若完全没出现过卡片上的任何特征，硬要凑几张出来，只会把无关内容塞上桌。所以管理员还得看卡片角落里的小字：什么时候写的、从哪来的、有没有被划掉。那几行小字，就是时间戳、来源与撤销标记。

## 画出来看

先看一条稳定事实从写入到被取回的完整链路，注意「连同来源落盘」这一格——来源与时间必须跟着事实一起存，不能等取回时再补。

:::figure 一条长期事实从落盘到取回
@flow
稳定事实|转成向量|连同来源落盘|按相似度召回|限制条数取回
:::

「限制条数取回」不是可选项。召回出来的是候选，不是结论；候选再多，能摆上桌的也只有少数几条，否则记忆反而把本轮要处理的材料挤没了。再看两种比对方式的差别。

:::figure 两种召回方式的差别
@compare
只比字面::同义说法漏掉|召回偏窄|实现最省
按特征比对::换说法也能命中|要控条数|旧信息需裁决
:::

「换说法也能命中」是向量化存储值得做的理由：用户说「导出」「给我个文件」，和当初写的「报告导出成某种格式」字面上并不一样，按特征比对却能对上。但右边那行最后一个要点同样重要——越容易命中，越容易把一条过期条目也命中回来，于是裁决机制一步都不能省。

## 再往下追两层

:::ask 追问一
那相似度排在第一的，是不是就可以直接当事实用了？
:::

不行，这是最该警惕的一步。相似度只说明「两段话像」，不说明「这条现在成立」。一条三个月前临时改过的格式、一次工具报错里带出来的旧取值、甚至某段被外部内容带偏的记录，都可能因为字面相近而排到前面。要压下这个风险，得让每条事实带着三样东西一起存：写入时间、来源、以及权威级别。新旧打架时按版本与权威裁决，而不是简单地用新的覆盖旧的，见[冲突消解与版本](./k071-conflict-resolution.md)；过了期、被标错、涉及敏感字段的，要有明确的退出通道，见[遗忘、过期与 TTL](./k073-forgetting.md)；写入前还要挡住不该记的东西，见[写入判定：什么时候该记](./k070-write-decision.md)。换句话说，召回给的是候选名单，能不能用，得再过一道裁决。

:::ask 追问二
那要不要把这套数字比对做得特别复杂？
:::

对讲清机制来说不需要，对工程落地来说另说。下面那段代码手写的词频向量只是为了把「转数字、算相似、限条数」这三步演示成可运行的东西，它构造了几条数据、跑了几条断言，不证明任何方法上的优劣。真正要守住的是三条性质：召回只是候选、条数要有硬上限、零召回时要有明确的兜底而不是硬凑一条出来。至于取回之后按什么顺序摆、怎么避免记忆反过来污染本轮输入，是[召回排序与相关性](./k072-memory-recall.md)的事；而「全存下来为什么也不叫记忆」，可以回到[记忆不是日志](./k065-memory-vs-log.md)再对一遍。这套东西跨会话留住的稳定事实，最终落在[工作 / 情景 / 语义三层记忆](./k066-memory-types.md)里的语义层。

## 一段能直接跑的代码

下面这段只用标准库，不联网、不装第三方包、不需要账号，用纯 Python 手写「文字转词频向量、算余弦相似度、按相似度取回并限制条数」的全过程。所有数据都是手工构造的，结尾用断言验证跨会话取回与零召回兜底。复制成 `.py` 直接运行会打印命中结果。

```python
import math
import re


def tokens(text: str) -> list:
    # 中文按字、英文数字按词切，够用来做确定性的相似度演示
    return re.findall(r"[a-z0-9]+|[\u4e00-\u9fff]", text.lower())


def vector(text: str) -> dict:
    v = {}
    for t in tokens(text):
        v[t] = v.get(t, 0.0) + 1.0
    return v


def cosine(a: dict, b: dict) -> float:
    dot = sum(a.get(k, 0.0) * b.get(k, 0.0) for k in set(a) | set(b))
    na = math.sqrt(sum(x * x for x in a.values()))
    nb = math.sqrt(sum(x * x for x in b.values()))
    if na == 0 or nb == 0:
        return 0.0
    return dot / (na * nb)


class LongTermStore:
    """把稳定事实连同向量一起存，查询时按相似度取回。"""
    def __init__(self):
        self.items = []

    def save(self, fact_id: str, text: str):
        self.items.append((fact_id, text, vector(text)))

    def recall(self, query: str, top_k: int = 2):
        q = vector(query)
        scored = [(cosine(q, v), fid, text)
                  for fid, text, v in self.items]
        scored.sort(key=lambda x: x[0], reverse=True)
        return [(fid, round(score, 3))
                for score, fid, text in scored[:top_k]
                if score > 0]


if __name__ == '__main__':
    store = LongTermStore()
    # 模拟「上一次会话」写入的两条稳定事实
    store.save("F1", "用户偏好把报告导出成 PDF 文件")
    store.save("F2", "用户所在的时区是东八区")

    # 模拟「新会话」里的一次召回
    hits = store.recall("导出报告想要 PDF 格式", top_k=1)
    assert hits and hits[0][0] == "F1", hits          # 跨会话仍取回相关事实
    assert len(hits) == 1                             # 条数限制生效
    assert store.recall("今天午饭吃什么", top_k=2) == []  # 无关查询不硬凑
    top = store.recall("时区 东八区", top_k=2)
    assert top[0][0] == "F2", top                       # 另一条事实也能命中
    print("导出查询命中：", hits, "；时区查询命中：", top)
    print("通过 4/4 项")
```

1. `tokens` 用 `re.findall`：把中文按单字、英文数字按连续词切开，并统一转小写。这只是为了让下面的演示可复现，不涉及任何外部资源。
2. `vector` 统计每个字或词出现的次数，得到一个「字或词 → 次数」的字典：这就是那组特征标签，也就是把一段文字转成的一组数字。
3. `cosine` 手写余弦相似度：先算两组数字对应项乘积之和，再各除以自身长度，得到零到一之间的一个值。任一组为空时直接返回零，避免除零。
4. `LongTermStore.save` 把编号、原文、向量一起存成一项：对应「连同来源落盘」。示例里只存了编号，真实使用还应带上时间戳与来源，裁决时才有依据。
5. `recall` 先给每条算相似度、按分降序排，再用 `scored[:top_k]` 截断，最后用 `if score > 0` 把完全不相关的挡掉——这一句就是零召回兜底，不让系统硬凑一条结果出来。
6. `if __name__ == '__main__':` 下的四条断言：分别钉住「换个会话、换个说法仍能取回」「条数上限生效」「无关查询返回空」「另一条事实也能按特征命中」。末尾 `print` 把命中编号与相似度打出来，肉眼可核对。

## 踩过的坑与边界

- **把召回结果直接当事实**：现象是三个月前临时改过的格式被一直沿用 → 原因是相似度只回答像不像，不回答还成不成立 → 让时间、来源、权威级别跟着事实走，取回后再过一道裁决。
- **零召回时硬凑一条**：现象是问了个完全无关的问题，助手却搬出一条旧记录强行作答 → 原因是没有相似度下限、也没有明确的空结果处理 → 设下限、返回空、由上层按「不知道」处理。
- **不限制取回条数**：现象是记忆条目越攒越多，本轮要处理的材料反而没位置 → 原因是把「存得多」当成了「给得多」 → 召回一律带硬上限，只把最相关的少数几条摆上桌。
- **只存正文、不存来源与时间**：现象是新旧事实打架时无从判断该信谁 → 原因是落盘时省了那几行小字 → 每条连同时间戳、来源、版本一起存，冲突按版本裁决而非覆盖。
- **把整柜卡片都搬进本轮输入**：现象是上下文被历史占满、成本随条目数涨 → 原因是没分清「长期存着」和「本轮要带」 → 长期事实按需取回，见[短期记忆与滑动窗口](./k067-short-term.md)里对篇幅的讨论。

边界也讲清楚：这套做法是为「跨会话仍要生效的稳定事实」准备的。若某条内容只在本次会话内有用，或者属于敏感字段、外部带进来的内容，就别往长期记忆里放——前者交给短期窗口，后者的门槛见[隐私脱敏、同意与记忆污染](./k074-memory-privacy.md)。

## 三句话小结

长期记忆是跨会话保留稳定事实，按内容特征比对来召回，难点在取得准、别把旧信息当真。
做法是让时间、来源、权威级别跟着事实一起存，召回只当候选，再过裁决并限制条数。
内容只在本次会话内有用、或属于敏感与外部带进来的信息时，不该放进长期记忆。
