# 压缩后信息丢失怎么验证

## 场景提问

你给长任务做了压缩，上下文确实短下来了，可跑着跑着 Agent 开始用错工单编号、把「只统计近一年」当成「主要看近一年」、还把一个早先确认过的金额说成「大约两百多」。你有点慌，于是把压缩后的那段摘要连同一句「你有没有漏掉或改动任何重要信息」一起又问了模型一遍，它很肯定地回你「没有遗漏，信息完整」。你信了，结果下一轮它照样把那个编号写错。明明做了确认，为什么还是查不出丢在哪？更让你为难的是，就算你怀疑丢了，也说不清「到底是哪一项、原来是什么、现在变成了什么」，更没法回答「从第几轮开始不对的」。

## 破误解

**不是压缩一定会把东西弄丢，是你把「验证有没有丢」交给了会自证的那一方，而不是拿原文做一次确定性的逐项核对。**

先把这层窗户纸捅破：问模型「你漏了没」，得到的答案和「到底漏没漏」之间没有必然关系。压缩后的文本就是它眼前唯一的依据，原文早被挪走了；让它对着自己的产物自评，它没有可对照的尺子，只能给出一个听起来合理的判断。这不是模型不诚实，是任务本身没法这么验——**验证必须有独立于被验证对象的锚点**。放到压缩这件事上，锚点只能是压缩前的原文，或者从原文里事先抽好、单独存起来的一组「不能丢的项」。

本文把这类「不能丢的项」叫做探针（probe）：从原文里按规则抽出来的、需要精确保留的键值，比如工单编号、金额、截止日期、硬约束、已定的决策。做法是三步：压缩前先从原文抽一份探针集合存好；压缩后从压缩文本里用**同一套规则**再抽一份；把两份逐项比对，凡是缺失的、值被改写的、凭空多出来的，都写进一份带定位的差异报告——哪个键、原值是什么、现值是什么、属于什么严重程度。发现缺失，不用让模型「再改一遍措辞」，而是按原文锚点把那一项回填，然后重新验证一遍直到报告清零。

这里有个关键设计：探针要**规范化成键值再比值，不比措辞**。如果只做「大意是否还在」的判断，「318」被写成「大约三百多」大概算过关；可下游要拿这个数字去核算，差一点就是错的。把值抽成结构化字段逐字比对，措辞怎么花哨都糊弄不过去。至于如何判断「哪些项压根不能压」，那是 [写选压隔四类操作与不可压缩项](./k139-context-ops.md) 里不可压缩清单的活；本文假定这份清单已经存在，专注讲「压完之后怎么查、查出来怎么补」。触发压缩的时机在 [压缩触发阈值与时机](./k047-compression-trigger.md)，压缩内容怎么变短在 [摘要式压缩](./k044-summary-compression.md)，三件事各管一段，别指望用其中一件顶替另一件。

## 生活类比

把它想成搬家时的打包清点。靠谱的做法不是卸完车问搬运工一句「东西都齐了吧」，而是装箱前先按房间列一张清单：易碎花瓶一只、保修卡一张、螺丝一袋、合同原件三份，每样记下数量和特征；封箱时把「不许拆、不许换包装」的箱子单独贴标签；到了新家，照着**同一张清单**逐项开箱点货，少了哪样、哪样被换成了别的、哪样是清单上根本没有却冒出来的，都单独记一笔；最后照原清单把缺的补上，再点一遍才算完。

对应关系很具体：装箱前那张清单，就是压缩前从原文抽出的探针集合；「同一张清单」强调比对必须用同一套抽取规则，规则一变，比出来的差异就没意义；逐项点货，就是压缩后再抽一次探针并逐键比对；「少 / 换 / 多」三类记录，对应差异报告里的缺失、改写、新增三种条目；贴了标签不许拆的箱子，就是不可压缩清单，压缩函数必须原样放过；照原清单补货，就是按原文锚点回填；补完再点一遍，就是重新验证直到报告清零。而「问搬运工齐不齐」，恰恰就是让模型自评那种做法——他不是故意骗你，他手边根本没有那张清单。

这个比喻还点出两处容易被省掉的细节。第一，清单要**先于**搬运写好，事后再凭记忆补一张，等于用已经可能出错的状态当基准，验了也白验；放到系统里，就是探针必须在压缩之前抽取并留存，不能压完再回头「猜原文大概有什么」。第二，原文不能真扔：清单只列了关键项，真发现某样东西对不上，还得回原箱、回原始单据去核对，所以压缩前的原文要落盘可查，回填取的值必须来自原文而不是压缩文本。这也是为什么 [结构化状态摘要](./k046-structured-state.md) 强调「状态与轨迹都该留」——有了可回放的原文，验证才有落脚点。

## 自绘示意图

:::figure 压缩前后逐项核对的顺序
@flow
原文抽探针|执行压缩|重抽探针|逐项比对|回填复验
:::

五格里最容易被跳过的是第一格和最后一格。很多人一上手就写「比较压缩前后像不像」，可探针没在压缩前单独存下来，比较就没有基准；也有人查出缺失就完事，不做回填后的二次验证，结果补进去的值又被下一轮压缩改掉，问题原地复活。「原文抽探针」必须严格早于压缩，「回填复验」必须作为收尾闸门，两头都不能省。

:::figure 探针该覆盖的几类东西
@stack
标识类::工单编号、用户标识，逐字不可动
数值类::金额、数量、比例，要精确不要大概
时间类::截止日期、生效日，格式与值都要对
约束类::不得、必须、只允许，丢了边界就松
决策类::已定的选项与否决过的方案，别被翻案
:::

五行里「约束类」和「决策类」最容易被漏，因为它们在原文里往往不是整齐的 `键=值`，而是一句话。抽不全时不要指望正则兜住一切，更稳的做法是把这类项显式写进不可压缩清单、由代码原样常驻，抽取只当补充防线。这也说明为什么探针的类型要分开对待：标识比逐字、数值比精确、约束比的是「这句话还在不在」。

:::figure 两种验证姿势的差别
@compare
问模型漏没漏::没有独立锚点|措辞变化查不出|答不出丢在哪
原文探针逐项比对::对照压缩前原文|比值不比措辞|报告带键值定位
:::

左边省事，但它验的是「模型觉得如何」，不是「事实是否如此」；右边多了抽取、比对、报告三步，换来的是能定位、能分级、能回填。二者差距全在「有没有一把独立于被验证对象的尺子」。

## 层层追问

:::ask 那如果模型把「工单总数 318」写成「大约三百多」，意思差不多，也算丢吗？
:::

算，而且这类「意思差不多」恰恰是最该被抓出来的。原因不在措辞，在用途：下游要拿这个数去核算、去和别的数字对账，一旦变成模糊说法，精确性就没了，后面所有依赖它的判断都跟着歪。探针之所以要规范化成键值再比对，就是为了把判断从「大意像不像」拉回到「值等不等」：`318` 和 `大约三百多` 逐字不等，报告里就会同时出现「原值 318」和「现值大约三百多」，谁看了都知道该回填成哪一个。演示代码里专门构造了这一组，验的就是「换说法也算丢失」。

再往下一层：那把措辞都规范化成数值不就行了？不行，因为不是所有「值」都能归一成数字。硬约束是「不得编造工单编号」这样一句话，决策是「退款单列、不并进物流」这样的选择，否定句「不再使用旧口径」里的「不再」更是关键，硬套数值规范化反而会把语义抹平。所以探针按类型分别抽取、分别比：标识比逐字、数值比精确、时间比格式与值、约束与决策比「这句还在不在」；实在抽不稳的，就别靠抽，直接进不可压缩清单由代码保护。还有个更细的坑：同一个键可能出现多条（比如两条约束），比对时要按列表整体比，而不是只取第一条——演示代码用「键到值列表」的结构，正是为了这个。

:::ask 那如果探针本身就没抽全，漏掉的东西不就照样验不出来了吗？
:::

这一问戳到了单点防线的软肋，答案是：验证不该只靠抽取这一层。抽取是兜底之一，不是全部。稳的做法至少三层叠起来。第一层是**不可压缩清单**：把系统约束、当前目标、不可变标识这类「丢了就出事」的项显式声明，压缩函数逐条跳过、原样常驻，它们根本不参与「抽没抽到」的赌博，白名单要短、每条写清理由、可审计，这在 [写选压隔四类操作与不可压缩项](./k139-context-ops.md) 里展开。第二层是**结构层先过一遍**：压缩完先查字段齐不齐、类型对不对，连槽位都缺了就别急着比值，这和 [结构层校验](./k017-structure-check.md)、[性质断言](./k088-property-assertion.md) 是同一路思路——先守住「形状」，再守「内容」。第三层才是**探针逐项比对**，加上原文落盘可回填。

再追一层：怎么知道这份清单和探针规则本身没写错？靠一组固定的、构造好的用例反复跑，把「故意删一条、故意改一个数字、故意新增一个无据值」都做成断言，每次改动规则都重跑一遍，这属于 [回归门禁与基线](./k091-regression-gate.md) 要管的「改动不能把守门规则自己改松了」。换句话说，验证体系也得被验证。这里还有个分工值得记住：探针是「这一轮有没有丢」的现场核对，而 [结构化事实抽取与记忆命名空间](./k143-fact-extraction.md) 讲的是「把确认过的事实长期存成可更新的条目」，一个管压缩现场，一个管长期记忆，别把两者合成一套。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，把「原文抽探针、模拟有损压缩、逐项比对生成差异报告、不可压缩项保护、按原文锚点回填并复验」完整串起来。原文是手工构造的一行行文本，压缩用确定性的行替换来模拟，复制即跑，不需要第三方包、账号或网络。

```python
import json
import re

# 一行一条的原文：带"键=值"的是可抽探针的事实，其余是过程叙述
ORIGINAL = """\
目标=整理近一年售后工单
约束=只统计近一年
约束=不得编造工单编号
工单编号=GD-2025-0917
工单总数=318
退款金额=249.50
截止日期=2026-01-31
用户ID=U-0042
先拉了一份工单列表，看着数量挺多。
归类时把退款和物流混在一起了，后来又拆开。
准备明天再复核一次数字。
"""

# 不可压缩清单：这些键一旦被改写或删除都算严重问题
PINNED = ("目标", "约束", "工单编号", "用户ID")

# 用规则描述文本模式的工具（正则表达式）逐行识别"键=值"
PROBE_LINE = re.compile(r"^([^=\n]+)=([^=\n]+)$")


def normalize(text):
    """规范化：去掉空白、统一逗号，让比对看值不看排版。"""
    return text.strip().replace(" ", "").replace("，", ",")


def extract_probes(text):
    """从文本抽出规范化探针：键 -> 值列表（同一键可有多条，如两条约束）。"""
    probes = {}
    for line in text.splitlines():
        m = PROBE_LINE.match(line.strip())
        if m:
            key = normalize(m.group(1))
            value = normalize(m.group(2))
            probes.setdefault(key, []).append(value)
    return probes


def compress(text, mutations, protect=PINNED):
    """模拟一次有损压缩：mutations 把某些行改写或删掉（值为 None 表示删）。"""
    out = []
    for line in text.splitlines():
        s = line.strip()
        if not s:
            continue
        if s in mutations:
            m = PROBE_LINE.match(s)
            key = normalize(m.group(1)) if m else None
            if key in protect:
                out.append(s)            # 受保护项原样放过，不许改写
                continue
            replacement = mutations[s]
            if replacement is None:
                continue                 # 模拟这条被压缩丢了
            out.append(replacement)      # 模拟被改写成别的说法
        else:
            out.append(s)
    return "\n".join(out)


def verify(original_text, compressed_text, pinned=PINNED):
    """比对压缩前后探针集合，返回带定位的结构化差异报告。"""
    before = extract_probes(original_text)
    after = extract_probes(compressed_text)
    report = []
    for key in sorted(before):
        want = sorted(before[key])
        got = sorted(after.get(key, []))
        if want == got:
            continue
        report.append({
            "key": key,
            "severity": "严重" if key in pinned else "一般",
            "before": want,
            "after": got,
            "missing": [v for v in want if v not in got],
            "changed": [v for v in got if v not in want],
        })
    for key in sorted(set(after) - set(before)):
        report.append({
            "key": key,
            "severity": "新增",
            "before": [],
            "after": sorted(after[key]),
            "missing": [],
            "changed": sorted(after[key]),
        })
    return report


def repair(original_text, compressed_text):
    """按原文锚点把全部探针行原样重建，叙述部分保留，得到可复验的文本。"""
    probes = extract_probes(original_text)
    narrative = [l.strip() for l in compressed_text.splitlines()
                 if l.strip() and not PROBE_LINE.match(l.strip())]
    lines = []
    for key in sorted(probes):
        for value in probes[key]:
            lines.append("%s=%s" % (key, value))
    return "\n".join(lines + narrative)


def main():
    checks = []
    before = extract_probes(ORIGINAL)
    checks.append(("探针覆盖全部关键键", set(before) >= {
        "目标", "约束", "工单编号", "工单总数", "退款金额", "截止日期", "用户ID"}))
    checks.append(("探针只取结构化行", len(before) == 7))
    checks.append(("同一键可容纳多条", len(before["约束"]) == 2))
    checks.append(("探针抽取可复现", extract_probes(ORIGINAL) == before))

    # 一、无损压缩：只合并叙述，探针不动
    lossless = compress(ORIGINAL, {
        "先拉了一份工单列表，看着数量挺多。": "已拉取工单列表。",
        "归类时把退款和物流混在一起了，后来又拆开。": None,
        "准备明天再复核一次数字。": None,
    })
    checks.append(("无损压缩无差异", verify(ORIGINAL, lossless) == []))
    checks.append(("无损压缩不冒出无据值", not any(
        x["severity"] == "新增" for x in verify(ORIGINAL, lossless))))

    # 二、删掉一条普通事实：能查出缺失，并带原值定位
    lost = compress(ORIGINAL, {"退款金额=249.50": None})
    rep = verify(ORIGINAL, lost)
    item = [x for x in rep if x["key"] == "退款金额"][0]
    checks.append(("删事实能被查出缺失", item["missing"] == ["249.50"]))
    checks.append(("差异报告带原值与定位", item["before"] == ["249.50"] and item["after"] == []))

    # 三、精确数字被换成同义说法：比值不比措辞，仍算丢失
    reworded = compress(ORIGINAL, {"工单总数=318": "工单总数=大约三百多"})
    rep3 = verify(ORIGINAL, reworded)
    item3 = [x for x in rep3 if x["key"] == "工单总数"][0]
    checks.append(("换说法也算丢失", item3["missing"] == ["318"] and item3["changed"] == ["大约三百多"]))

    # 四、受保护项不许被删改
    attacked = compress(ORIGINAL, {"工单编号=GD-2025-0917": None,
                                   "用户ID=U-0042": "用户ID=未知"})
    after4 = extract_probes(attacked)
    checks.append(("不可压缩项原样保留",
                   after4["工单编号"] == ["GD-2025-0917"] and after4["用户ID"] == ["U-0042"]))

    # 五、一旦保护被绕过，受保护项丢失要定为严重；新增无据值单独标记
    raw = "\n".join(l for l in ORIGINAL.splitlines() if "工单编号" not in l)
    rep6 = verify(ORIGINAL, raw)
    checks.append(("受保护项丢失被定为严重", any(
        x["key"] == "工单编号" and x["severity"] == "严重" for x in rep6)))
    invented = compress(ORIGINAL, {"准备明天再复核一次数字。": "来源=外部猜测"})
    checks.append(("新增无据值被单独标记", any(
        x["severity"] == "新增" for x in verify(ORIGINAL, invented))))

    # 六、报告可落盘，回填用原文锚点，之后复验必须清零
    checks.append(("差异报告可序列化成 JSON",
                   json.loads(json.dumps(rep3, ensure_ascii=False))[0]["key"] == "工单总数"))
    fixed = repair(ORIGINAL, lost)
    checks.append(("回填后重新验证无差异", verify(ORIGINAL, fixed) == []))
    checks.append(("回填值来自原文而非压缩文本",
                   extract_probes(fixed)["退款金额"] == before["退款金额"]))

    # 七、键与值先规范化再比对，排版变化不算丢失
    spaced = ORIGINAL.replace("工单总数=318", "工单总数 = 318")
    checks.append(("规范化后排版变化不算丢", extract_probes(spaced)["工单总数"] == ["318"]))

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `ORIGINAL` 被刻意写成「一行一条」：`键=值` 的是事实，其余是过程叙述。`PINNED` 是不可压缩清单，`PROBE_LINE` 是一条正则表达式（用规则描述文本模式的工具），逐行识别哪些是结构化事实行。把原文做成可逐行处理的形式，是为了让「丢了哪一行」能定位、能手算。
2. `normalize` 只去掉空白、统一逗号，**不动数值和措辞**，所以它能消掉排版差异，却不会把 `318` 和 `大约三百多` 抹成一样——这正是「比值不比措辞」的落点。`extract_probes` 用同一套规则抽成「键到值列表」的字典，同一键允许多条，避免只比第一条就放过被删的第二条约束。
3. `compress` 用 `mutations` 模拟有损压缩：值为 `None` 表示这一行被丢了，别的值表示被改写成别的说法。关键在中间那层判断——凡是命中不可压缩清单的键，**原样放过、不执行改写**，把「不许压」做成代码里的硬分支，而不是一句提示词。
4. `verify` 是整套做法的心脏：对原文和压缩文本各抽一次探针，按 `sorted(before)` 逐键比对，值列表不等就记一条带 `before / after / missing / changed / severity` 的报告；再单独检查 `set(after) - set(before)`，把凭空冒出来的无据值标成「新增」。它完全不调用模型，纯确定性比对，因此「问模型漏没漏」那种自证问题根本不会出现。
5. `repair` 演示兜底：不靠模型重写措辞，而是用**原文**的探针把全部结构化行原样重建，叙述部分保留。回填值取自原文而非压缩文本，是这条最重要的一句——否则等于拿可能已经错的值去补另一个错。
6. `main` 分七组收集断言：无损压缩不该报差异；删一条金额能查出缺失且带原值；把 318 改成「大约三百多」仍算丢失；受保护项删改无效；保护被绕过时定为「严重」、无据新值标「新增」；报告可落成 JSON、回填后复验清零、回填值来自原文；排版变化经规范化后不算丢。
7. 结尾 `assert` 保证任何一条性质被破坏都会以非零状态退出。`json.dumps(rep3)` 那条顺带说明差异报告是可落盘、可审计、可接入门禁的数据结构，而不只是打印给人看的一段话。

有一处如实说明：真实压缩不会乖乖按「行」来，它会把多轮对话改写成一段话，探针也未必长得像 `键=值`。这里用行替换来模拟有损，是为了把「抽—压—比—补—复验」这条链完整跑通且可手算；它演示的是验证的结构，不是任何具体压缩算法的实现。

## 踩坑与边界

- **让模型自评有没有丢**：现象是问「有没有遗漏」得到「信息完整」，下一轮照样用错编号 → 原因是验证没有独立于被验证对象的锚点，压缩后原文已不在它眼前 → 压缩前抽好探针单独存，压缩后逐项比对，原文落盘可查。
- **只比大意不比值**：现象是「318」变成「大约三百多」被认为没问题，后面核算全歪 → 原因是判断落在「意思差不多」上 → 探针规范化成键值逐字比对，数值比精确、标识比逐字，报告里给出原值与现值。
- **同一键只比第一条**：现象是两条约束被删掉一条，比对却通过了 → 原因是把探针存成了「一键一值」 → 存成「键到值列表」，按列表整体比，见 [结构化状态摘要](./k046-structured-state.md) 里事实槽的做法。
- **把不可压缩项交给抽取去碰运气**：现象是硬约束写在一句普通叙述里，没被正则抽到，压完就消失了 → 原因是把最不能丢的项寄托在「抽没抽全」上 → 显式列不可压缩清单由代码原样常驻，抽取只当补充防线，见 [写选压隔四类操作与不可压缩项](./k139-context-ops.md)。
- **查出来不回填、也不复验**：现象是差异报告写得很清楚，下一轮压缩又把补进去的值改掉，问题原地复活 → 原因是把「发现」当成了「收尾」 → 按原文锚点回填后必须重新验证到报告清零，并把这条复验做成收尾闸门。

还要守住一条边界：验证能查出「丢了什么」，但不能替你决定「什么值得留」。探针清单和不可压缩清单本身是人定的，定漏了，再严的比对也验不出来；所以它们要和一组固定用例一起维护，每次改规则都重跑，这属于 [回归门禁与基线](./k091-regression-gate.md) 的范围。另一头，验证是有成本的：每压一次都要抽两次探针、比一遍、可能还要回填，压得越频繁这笔开销越大，所以别把它当成可以无限触发的动作，触发时机仍要受 [压缩触发阈值与时机](./k047-compression-trigger.md) 约束。还有一类问题它管不着：内容明明一项没丢、却因为塞得太多被模型忽略，那是 [上下文膨胀与中间遗失](./k049-context-bloat.md) 要处理的「在不在」之外的「看没看到」，得靠预算与排布解决，不是靠比对能查出的。

## 三句话小结

压缩后信息丢失怎么验证，是在压缩前先从原文抽出一组独立探针，压缩后按同一套规则重抽并逐项比对，用带定位的差异报告指出缺了什么、改了什么、多了什么，再按原文锚点回填复验。

关键做法是比值不比措辞、不可压缩项由代码原样放过、回填取原文而非压缩文本、报告可落盘可审计、并把整套验证纳入固定用例反复回归。

当任务很短、压根没做压缩，或所有内容都是一次性叙述、没有需要精确保留的键值时，不必上这套核对；但只要压缩会改写历史、且下游依赖精确值或硬约束，就不能只靠一句自评收尾。
