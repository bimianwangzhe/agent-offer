# 一次请求拆成五块：地址、鉴权、消息体、参数、返回

## 一、昨天还好好的脚本，今天报错了

一个昨天跑得好好的脚本，今天突然不干活了。你盯着那一长串调用代码，从第一行看到最后一行，改了提示、换了说法、调了参数，折腾半天，最后发现只是凭证过期了。还有一次，你想把本地跑通的那套挪到另一处环境里，结果地址、消息格式、返回字段全得跟着动，牵一发而动全身。

问题往往不在某一行写错了，而在整件事被写成了一坨：你没法一眼看出"这次到底由哪几样东西凑成"，于是排查只能靠猜，替换只能靠重写。

## 二、先破误解

**不是一次调用就是"发个请求、等回话"这一句话，它是五块能各自独立检查、独立替换的东西；混成一坨，排查就只能靠猜。**

把五块逐一摆开。第一块是地址（endpoint），指这次调用送到哪个入口；用统一资源定位符（Uniform Resource Locator，URL，表示资源位置的一串标识）来定位，本篇只用占位，不写任何具体网址。第二块是鉴权（auth），证明"我是我"的凭证，它只说明身份，不参与内容。第三块是消息体（messages），本轮带进去的那一整段对话，按[消息角色与对话拼装](./k007-message-roles.md)讲过的规矩拼好。第四块是参数（params），长度上限、随机程度这类旋钮，见[采样参数与不确定性](./k004-sampling.md)。第五块是返回（response），模型给回的文字，外加一块常跟着一起回来的用量数据，见[用量统计与计费口径](./k010-usage-billing.md)。

拆开的好处有两个，都很实在。一是逐项排查：把"失败"细化成"哪一块空了、哪一块格式不对"，上面那个查了半天的凭证过期，本该在第一分钟就被"鉴权为空或失效"挡下。二是逐项替换：换入口、换真正把请求送出去的那段实现、换解析方式，都只动对应的一块，业务那几步不用跟着改。要留神，"五块"说的是一次调用由哪五样东西组成，不是五个先后走过的步骤，别把它读成一条流水线。

:::tip
先能说出"这次调用由哪五块组成"，再谈排查；说不出，就说明代码还糊在一起。
:::

## 三、生活类比：寄一件东西要凑齐五样

寄一件东西，其实得凑齐五样。写收件地址（送到哪儿）、贴身份凭证（谁寄的、有没有权限用这项服务）、把要寄的东西装进包裹（真正的内容）、在单子上勾服务选项（限重、能不能代收、要不要回执）、最后等一张回执（对方签收了什么、这单记了多少费用）。少一样都办不成，而每样坏了的表现完全不同：地址错了根本送不到，凭证过期当场被拒收，包裹空了没内容可送，选项填错送到了却不合规矩，回执没看就不知道花了多少。

对应关系逐条摆出来：

- 收件地址，是第一块"地址"；
- 身份凭证，是第二块"鉴权"；
- 包裹里的东西，是第三块"消息体"；
- 单子上的服务选项，是第四块"参数"；
- 签收后的回执，是第五块"返回"；
- 寄之前逐样核对，是校验；
- 换一家快递但包裹不变，是替换实现而不动业务。

这个类比最好用的地方，是它让"报错"变得具体。你不会在包裹被拒收时去改包裹里的东西，也不会因为回执没写费用就怪地址填错了；五块分开之后，每一类失败都指向固定的一处，排查不再是从头翻到尾。

## 四、画出来：五块各是什么

先看一次调用到底由哪五块组成，它们职责互不相干：

:::figure 一次调用的五块
@stack
地址::送到哪个入口，一个占位标识
鉴权::证明身份的凭证，不参与内容
消息体::按角色拼好的一整段对话
参数::长度上限、随机程度这类旋钮
返回::给回的文字，附带用量数据
:::

五行里最容易混的是第三、第四块：消息体是"这次说了什么"，参数是"这次希望它怎么算"，前者是内容，后者是设置，别把长度限制写进对话文字里。最容易漏的是第五块附带的用量，它常常不是正文，却正是后面记账要用的东西。

再把两种写法摆在一起：

:::figure 混成一坨与拆成五块
@compare
混成一坨::报错靠猜|改一处动全身|换实现要重写
拆成五块::逐项定位|各块独立校验|替换不动业务
:::

左边那行的代价全在"分不开"上：出事不知道查哪儿，改一处牵动别处，换个环境就得重写。右边那行多了一层结构，反而更省事。

:::steps 一次调用的检查顺序
1. 地址在不在、是不是本次该用的入口；
2. 鉴权有没有、有没有失效；
3. 消息体是否非空、角色顺序是否合规；
4. 参数是否齐、有没有越过允许范围；
5. 发出去之后，返回能不能解析、用量有没有带回来。
:::

两张图加这份顺序合起来，其实给出了一套很朴素的排障法：从第一块往下逐项过，卡在哪块就修哪块，而不是整段重读一遍碰运气。

## 五、顺着追问两层

:::ask 那如果五块都校验过了，是不是这次就一定成功？
:::

不是。校验能保证的是"该带的带了、格式对得上"，它保证不了对方此刻是否可用，也保证不了回来的内容合不合你的要求。请求发出去之后还有一整段路：可能等太久、可能被限住、可能只回来半截文字，也可能文字回来了但格式根本解析不了。所以第五块不能只当"收到了就完事"，还得再分两小步——先确认它完整、能解析，再确认该有的字段在、值是否合法。这跟[流式输出与首字延迟](./k009-streaming.md)里要处理"半截内容与中断"是同一类问题，也跟[采样参数与不确定性](./k004-sampling.md)里"别把一句请求当保证"同源：能校验的边界要自己划清楚，别留给运气。

:::ask 那如果我想把本地那个桩换成另一套实现，业务代码要动多少？
:::

理想情况下只动一处。前提是两头的约定不变：这边"消息体怎么拼"不变，那头"返回怎么读"不变；那么变的只是"真正把请求送出去"的那一步。做法是把这一步当参数传进调用，而不是写死在函数体里——下面代码里的 `call(req, transport)` 就是这么设计的，换实现只换传进去的那个 `transport`，`validate` 和拼装逻辑一行不动。这也回答了开头第二个麻烦：之所以"挪到另一处就牵一发动全身"，正是因为把地址、送出的动作、解析方式全焊在了业务里。顺带说清第五块附带的那份用量：它是返回里独立的一小块，换实现时也要按同一口径带回来，否则账就断了，这正是[用量统计与计费口径](./k010-usage-billing.md)能记准的前提。整条线从哪起步，可以看[从这里开始](./00-start-here.md)。

## 六、跑一段代码，把五块摸实

下面这段只用标准库，不联网、不装包、不要账号。它用一个本地桩模拟"把请求送出去"，演示逐块校验和替换实现。地址与凭证都只是占位，不含任何真实网址或密钥。

```python
from dataclasses import dataclass


@dataclass
class Request:
    endpoint: str        # ① 地址：请求发到哪个入口
    auth: str            # ② 鉴权：证明"我是我"的凭证
    messages: list       # ③ 消息体：本轮带进去的对话
    params: dict         # ④ 参数：长度上限、随机程度等


@dataclass
class Response:
    text: str            # ⑤ 返回：模型给的文字
    usage: dict          #    附带用量，便于单独统计


def validate(req):
    if not req.endpoint:
        raise ValueError("① 地址为空")
    if not req.auth:
        raise ValueError("② 鉴权为空")
    if not req.messages:
        raise ValueError("③ 消息体为空")
    if "max_tokens" not in req.params:
        raise ValueError("④ 参数缺 max_tokens")
    return True


def local_transport(req):
    """可替换的本地桩：不联网，按消息体长度造一个确定返回。"""
    n = sum(len(c) for _, c in req.messages)
    return Response(text="本地桩收到 %d 字" % n, usage={"input": n, "output": 8})


def call(req, transport):
    validate(req)
    return transport(req)


if __name__ == '__main__':
    checks = 0
    req = Request(
        endpoint="local-chat",                       # 本地占位，非真实网址
        auth="demo-credential",                      # 占位凭证，非真实密钥
        messages=[("user", "你好")],
        params={"max_tokens": 64},
    )

    # 1) 五块齐全时，校验通过并拿到返回
    resp = call(req, local_transport)
    assert validate(req) is True
    assert isinstance(resp, Response) and "本地桩" in resp.text
    checks += 1

    # 2~5) 逐块挖空，定位到具体是哪一块出问题
    for field, value, tag in [
        ("endpoint", "", "①"),
        ("auth", "", "②"),
        ("messages", [], "③"),
        ("params", {}, "④"),
    ]:
        broken = Request(**{**req.__dict__, field: value})
        try:
            validate(broken)
            raise AssertionError("应当抛错")
        except ValueError as e:
            assert tag in str(e)
        checks += 1

    # 6) 第五块"返回"可替换：换一个桩，结果就变，业务代码不用改
    def alt_transport(r):
        return Response(text="备用桩", usage={"input": 0, "output": 2})

    assert call(req, alt_transport).text == "备用桩"
    checks += 1

    # 7) 返回里的用量单独成块，可直接拿去记账
    assert isinstance(resp.usage["input"], int) and resp.usage["output"] >= 0
    checks += 1

    print("通过 %d/%d 项" % (checks, 7))
```

逐段看它在做什么：

1. `Request` 用 `dataclass`（标准库里用来省掉样板代码的小工具）把前四块收在一起，`Response` 把第五块和附带的用量收在一起。两个结构一分开，"请求里有什么"和"回来有什么"就不会搅着。
2. `validate` 逐块检查，而且每句报错都带上编号：哪块空了、哪块缺字段，报错一眼能定位，不是笼统一句"失败"。这正是开头那个查了半天的凭证问题该被挡住的地方。
3. `local_transport` 是"真正把请求送出去"的本地替身：不联网，按消息体长度造一个确定返回，并带上 `usage` 两个数字。它代表的正是可替换的那一块。
4. `call` 先校验再把 `transport` 当参数调用。注意 `transport` 是传进来的，不是写死在函数里的——这就是"换实现只换一处"的关键。
5. 断言一验证五块齐全能跑通；那个 `for` 循环把四块逐一挖空，每次都确认报错里带着对应的编号，等于把"逐项定位"跑了一遍。
6. 断言六换上 `alt_transport`，同一份 `req` 得到不同文字，而 `call`、`validate` 一行没改；断言七确认返回里的用量是可以直接拿去记账的独立一块。

要守住边界：`local-chat`、`demo-credential` 都只是占位，代码里没有任何真实地址或凭证，也不联网；那两个用量数字是本地桩造的，不代表任何真实计费。它只演示"五块怎么分、怎么逐块查、怎么替换"。消息体里那一段该怎么按角色拼，回看[消息角色与对话拼装](./k007-message-roles.md)；回来的是一片片到达时又该怎么处理，接着看[流式输出与首字延迟](./k009-streaming.md)。

## 七、踩坑与边界

- **把凭证硬写进业务代码**：现象是过期了全站一起挂、还不好找 → 原因是它和逻辑缠在一起 → 单列成鉴权一块，集中校验与更新。
- **校验只报"失败"不说哪块**：现象是排查靠从头翻代码 → 原因是错误信息没带位置 → 每块独立检查，报错指明是哪一块。
- **消息体与参数混在一段文字里**：现象是长度限制写了却没生效 → 原因是设置被当成内容送进去了 → 内容归消息体、旋钮归参数，分开存。
- **换实现就改业务**：现象是挪个环境要重写一大片 → 原因是送出的动作被写死 → 把这一步当参数传入，替换只换实参。
- **忽略返回里的用量块**：现象是月底算不出账 → 原因是那块数据没被取出来落账 → 解析返回时把用量单独取出来记录，见[用量统计与计费口径](./k010-usage-billing.md)。

## 九、三句话小结

一次调用由地址、鉴权、消息体、参数、返回五块组成，每块能独立检查、也能独立替换。
要紧的做法是逐块校验并让报错指明位置，再把"送出去"那一步隔成可替换的实现。
当你需要排查一个笼统失败、或想把调用挪到另一处环境时，别整段重读碰运气，按五块逐项过一遍。
