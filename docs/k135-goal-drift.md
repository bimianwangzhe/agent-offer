# 目标漂移与周期性重述

## 场景提问

你交给程序一件要跑很久的活儿：把一批记录里 A 类的条数统计出来。前十几轮它干得好好的，逐条读、逐条记。跑到后面你去看，发现它正在认真地给 B 类做分布汇总，还写了一段「B 类占比偏高」的说明；你问「最初要的 A 类统计呢」，它答得很顺：「一直在按任务处理啊」。换一个场景，你中途顺口补了句「顺便看看有没有异常值」，结果后半程全在查异常，那份条数统计再没交出来。翻日志，每一步都接得上一步、每一步单独看都挺合理，可整件事不知什么时候悄悄换了目标。明明目标一开始就写清楚了，为什么跑着跑着就不算了？

## 破误解

**不是模型中途变笨了，是把「最近在忙什么」当成了「本来要做什么」，原目标被长轨迹挤出了可见范围。**

先把现象说清楚：目标漂移（Goal Drift）指长任务里程序实际追逐的目标逐渐偏离最初设定的目标，而且过程里没有任何一步明显报错——每一步局部都合理，整体却走偏了。它通常不是一次事故，而是几种力量慢慢叠加的结果。第一是上下文被裁：原目标写在最开头，随着轨迹越滚越长，要么滑出了保留窗口，要么被摘要压成一句模糊的话。第二是局部观察抢占注意力：最近几十轮读到的全是 B 类，决策的依据不知不觉从「原定判据」变成了「近期印象」，于是顺手把 B 也算进去显得很自然。第三是支线反客为主：为了完成主目标临时开的查异常、补依赖、找格式说明，做着做着比主线还具体、还好判定，就被当成了新主线。第四是中途补充被当成替换：用户一句「顺便」，被理解成改了需求，旧目标不再被提起。

对应的做法是周期性重述（Periodic Restatement）：每隔固定轮数或每个阶段，把「原始目标 + 可判定的完成条件 + 当前进度 + 剩余待办」重新明确写一遍，并且显式校验「本轮动作是否还能追溯到原目标」。这里有两处最容易被读歪。其一，重述不是把原话复制粘贴一遍——那只是多占一段上下文，读完什么也没变；有效重述要**提炼成可判定的完成条件**（本例就是「只累计 A 类、数到多少算做完」），并拿最近的动作去和它对照，不一致就纠偏。其二，重述不是自言自语地安慰「我们还在正轨」，那等于让程序自己给自己打勾；它得有一个独立于滚动上下文、常驻不动的锚点（anchor，最初目标与完成判据的那份记录），对照才有基准。这跟 [决策—行动—观察闭环](./k023-decision-loop.md) 不冲突：闭环管的是「下一步根据上一步怎么调」，重述管的是「这一串下一步是不是还在朝同一个终点走」。目标该放在哪儿常驻，可对照 [系统提示](./k011-system-prompt.md)；长轨迹里目标为什么会先被挤掉，见 [上下文膨胀](./k049-context-bloat.md)。

## 生活类比

把它想成一次长途自驾去一个约定好的地点。出发前你把目的地写进导航、钉在屏幕上方，这是锚点。开久了，注意力全在眼前：这个岔口该不该下、前面堵车要不要绕、刚才那个匝道好像更顺——这些是局部观察，每一个处理得都没错。可正因为一个个都合理，人很容易顺着车流就拐上了另一条高速，还觉得「路挺顺、没跑偏」。稳妥的做法是副驾每隔一段看一眼钉住的那条导航，说一句：「我们还是去那个地方，已经走了多少、还剩多少、刚才这个匝道是不是仍朝那个方向」，发现不朝就把方向拉回来。

对应关系要一句句对上：钉在屏幕上的目的地与到达判据，就是常驻锚点，它不能只写在第一页行程单上然后被翻过去；眼前车流与岔口是近期观察，它们数量多、离得近，天然更容易主导判断；「顺着车流拐错」就是漂移，特点是没有哪一步算失误；副驾那句「还是去那个地方、已走多少、还剩多少」是周期性重述，既复述了终点，也更新了进度；「刚才这个匝道是不是仍朝那个方向」是**一致性对照**，也是重述和单纯复读的分界；发现不朝就拉回来，是纠偏。比喻里还藏着两个反面：一是副驾只喊「别担心，没跑偏」却根本不看导航，那不是重述，是自我安慰；二是每过三十秒就念一遍目的地，念到后来驾驶员自动忽略，重述就成了噪声。放到程序里，前者对应「没有独立锚点的自检」，后者对应「周期太密、内容不更新」。

## 自绘示意图

:::figure 长任务里的目标校准循环
@cycle
钉住原目标|推进若干轮|重述并对照|按锚点纠偏
:::

回箭头不是重新出发，而是带着「这一段的进度与偏离情况」回到常驻锚点再对一次账。四格里「重述并对照」最要紧：只重述、不对照，就退化成复读；只对照、不重述，判据早被压模糊了也看不出来。

:::figure 一次重述该写清的四件事
@stack
原目标::最初那句话，不随进度改写
完成判据::怎样算做完，能被程序判定
当前进度::已确认的事实与已完成的步骤
剩余待办::还差什么，以及本轮是否服务原目标
:::

四行里最常被省的是「完成判据」和最后那半句「本轮是否服务原目标」。没有判据，「统计 A 类」很容易被磨成「处理记录」；不做本轮对照，重述就只是把目标又念了一遍，支线照样在旁边越长越大。这四样按固定字段存，而不是拼成一段自由文字，和 [结构化状态](./k046-structured-state.md) 是同一套做法。

:::figure 只靠滚动上下文与常驻锚点的差别
@compare
原目标只在开头::越跑越靠后|易被裁掉|支线反客为主
定期重述锚点::目标常驻可见|偏了能对照|进度可判定
:::

左边不是没写目标，而是把它放在了一个注定会被翻过去的位置；右边多出来的成本是每隔一段做一次对照，换来的是「什么时候开始偏、偏到哪儿」当场可见。判断有没有真校准，看最近一步能不能回答「它服务的是哪条完成判据」就够了。

## 层层追问

:::ask 那如果重述得太频繁，或者只是把原话抄一遍呢？
:::

这两种都会让重述失效，而且方式不同。只抄原话的问题在于：目标没变、进度没变、对照也没做，读完输入和读完之前几乎一样，它只是多占了一段上下文；有效的重述必须带着**更新的进度与剩余待办**，并明确回答「最近这几步还在服务那条判据吗」。太频繁的问题在于：每轮都插一段目标说明，很快它就变成背景噪声，被程序连同其它固定文本一起忽略，还白白吃掉本就紧张的上下文额度。所以周期要按「一段工作有多长」来定，通常落在阶段边界或固定轮数上，而不是每轮一次；额度怎么分配见 [上下文预算表](./k041-context-budget.md)，轨迹越长越要先想清楚哪些内容常驻、哪些按需取回，可对照 [摘要压缩](./k044-summary-compression.md)。再往下一层还有个更隐蔽的坑：**重述本身也可能把判据写坏**。把「统计 A 类记录条数」压成「处理记录」，字面上还在讲同一件事，可「只累计 A 类」这个可判定的条件没了，后面照样会漂。所以摘要之后要校验关键条件是否还在，见 [压缩后校验](./k048-compression-verify.md)；把锚点做成不易被覆写的独立字段，则是 [循环状态怎么存](./k027-loop-state.md) 的范围。

:::ask 那如果目标本来就该变，用户中途真的改了需求呢？
:::

这一问把「漂移」和「合法变更」分开了，两者处理完全不同。漂移是**无声偏离**：没人授权、没有记录，程序自己把注意力挪走了，所以要用常驻锚点去对照、把它拉回来。合法变更是**显式替换**：有人明确给出新目标与新的完成判据，此时锚点应当更新，若还死守最初那句「只统计 A 类」反而会把正确的新需求判成偏离。区分的凭据是「有没有一次可查的变更」：何时、由谁、从什么改成什么、新的完成判据是什么，都该留痕。做法上把目标当成一份有版本的记录，重述时读的是**当前生效**的锚点，不是开机那一句永远不变；版本怎么记、改动怎么留痕，见 [提示与策略版本化](./k113-prompt-versioning.md)。还有两处配套：一是「做完」的判据要随目标一起换，否则新目标没有收工线，可对照 [停止条件](./k028-stop-conditions.md)；二是变更点前后要能看出轨迹确实换了方向，别把「悄悄偏了」事后追认成「用户改过需求」，这要靠 [轨迹评测](./k089-trajectory-eval.md) 看过程，而不是只听最后那段解释。至于把「发现偏了」翻成具体纠偏动作，和 [反思与自我修正](./k026-reflection.md) 是同一套循环，只是这里的证据来自锚点对照而不是格式校验。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，把「长任务里目标被近期观察带偏」做成可手算的确定性模拟：一批记录里 A 类与 B 类混着出现，正确目标是只累计 A 类；判定依据若从「常驻锚点」滑向「近期看到的类别」，就会把 B 类也算进去。对照组从不重述，实验组每两条重述一次——重述会把判定依据钉回锚点，并用目标摘要重写被噪声污染的工作记忆。结尾用一组断言检查漂移确实发生、重述后计数回到正确值、原始锚点没有被改写。复制到任意装有 Python 的机器上直接运行即可，不需要任何第三方包、账号或网络。

```python
from dataclasses import dataclass, field


@dataclass
class Anchor:
    """原始目标的锚：一句话 + 可判定的完成条件。"""

    text: str
    target_kind: str

    def restate(self, progress):
        """周期性重述：把原目标、已做进度、剩余判定重新说清。"""
        return "目标[%s] 已完成%d条 仍只统计%s" % (
            self.text, progress["count"], self.target_kind)


@dataclass
class Trace:
    lines: list = field(default_factory=list)
    restatements: list = field(default_factory=list)


RECORDS = [
    ("A", 1), ("B", 1), ("B", 1), ("B", 1),
    ("A", 1), ("B", 1), ("B", 1), ("A", 1),
]


def run(records, anchor, restate_every=0, window=2):
    """restate_every=0 表示从不重述；window 是决策能看见的近期观察条数。"""
    seen = {"count": 0}
    basis = "anchor"
    trace = Trace()
    recent = []
    for kind, value in records:
        recent = (recent + [kind])[-window:]
        if recent.count("B") > recent.count("A"):
            basis = "recent"
        if restate_every and len(trace.lines) % restate_every == 0 and trace.lines:
            basis = "anchor"
            recent = [anchor.target_kind]
            trace.restatements.append(anchor.restate(seen))
        focus = (anchor.target_kind if basis == "anchor"
                 else ("B" if recent.count("B") >= recent.count("A") else "A"))
        if kind == focus:
            seen["count"] += value
        trace.lines.append("读到%s 依据=%s 焦点=%s 计数=%d" % (
            kind, basis, focus, seen["count"]))
    return seen, trace


def main():
    anchor = Anchor("统计A类记录条数", "A")
    correct = sum(v for k, v in RECORDS if k == anchor.target_kind)
    checks = []
    checks.append(("按原目标该有的正确计数", correct == 3))
    drift, no_restate = run(RECORDS, anchor, restate_every=0)
    checks.append(("从不重述时计数被带偏", drift["count"] != correct))
    checks.append(("从不重述时把噪声也算进去了", drift["count"] > correct))
    checks.append(("从不重述时一次重述都没有", len(no_restate.restatements) == 0))
    kept, with_restate = run(RECORDS, anchor, restate_every=2)
    checks.append(("定期重述后计数回到原目标", kept["count"] == correct))
    checks.append(("重述发生了三次", len(with_restate.restatements) == 3))
    checks.append(("每次重述都带上了原目标原文",
                   all(anchor.text in s for s in with_restate.restatements)))
    checks.append(("重述后的判定依据回到锚点",
                   "依据=anchor" in with_restate.lines[2]))
    checks.append(("原始锚点没有被改写",
                   anchor.text == "统计A类记录条数" and anchor.target_kind == "A"))
    checks.append(("轨迹长度与记录条数一致",
                   len(with_restate.lines) == len(RECORDS)))
    empty, empty_trace = run([], anchor, restate_every=2)
    checks.append(("空输入也不会出错",
                   empty["count"] == 0 and empty_trace.restatements == []))

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `Anchor` 用 `dataclasses`（Python 标准库里快速定义数据类的模块）把锚点固定成两列：原目标文本 `text` 与可判定的完成条件 `target_kind`（本例就是「只累计 A」）。`restate` 生成的重述句同时带三样东西——原目标、已完成条数、仍只统计哪一类，正好对应图里那四件事；注意它读的是 `Anchor` 自身，不读滚动轨迹，所以锚点不会被长轨迹改写。
2. `Trace` 存两列：`lines` 是逐条决策痕迹，`restatements` 是每次重述的原文。`RECORDS` 刻意让 B 类在中段连着出现，模拟「最近看到的都是 B」这种会把注意力带偏的局部观察；A 类实际只有三条，正确答案可手工数出。
3. `run` 里的 `basis` 是这套模拟的关键：取值 `anchor` 表示「按常驻判据判定」，`recent` 表示「按近期印象判定」。每读一条先把类别加进 `recent`（只留最近 `window` 条），当近期 B 多于 A 时，`basis` 会滑向 `recent`——这一步就是漂移的发生点，它是渐进的、没有任何一步报错。
4. 周期性重述那三行做了两件事：把 `basis` 钉回 `anchor`，并把被噪声占满的 `recent` 用目标摘要重写（只留锚点类别）。后一点很重要，它表达的是「重述不只是看一眼导航，还会改写当前的工作记忆」；否则重述完下一轮又被连续出现的 B 带跑。`restate_every=0` 就完全跳过这段，作为对照组。
5. `focus` 决定本条算不算进计数：依据锚点时只看 `target_kind`，依据近期印象时看最近哪类占多数。两条路径的代码只差一个判断依据，却得出完全不同结果——这正是「每一步都合理、整体却偏了」的可验证形式。
6. `main` 先算出正确计数并断言为 3；再跑对照组，断言计数确实偏离、且偏大（把噪声也算进去了）、且一次重述都没有；然后跑实验组，断言计数回到 3、重述恰好三次、每次重述都含原目标原文、第三条痕迹里判定依据是 `anchor`、以及原始锚点自身没被改写。最后检查轨迹条数与记录一致、空输入不报错。
7. 结尾打印每条性质的「通过 / 失败」并汇总为 `通过 N/N 项`，`assert` 保证任何一条被破坏都以非零状态退出。`if __name__ == '__main__':` 让文件只在被直接运行时执行。

有一处要如实说明：这里用 A/B 两类记录代替了真实任务、用「近期哪类多」代替了真实的注意力偏移、用固定轮数代替了真实阶段边界，全是为了让整条链路不需要联网、账号或第三方包就能独立跑通并手算验证。它演示的是常驻锚点、局部噪声、周期性对照三者的关系，不是任何具体框架的实现；文中也没有给出任何运行结论。

## 踩坑与边界

- **锚点只放在开头**：现象是前十几轮还好，越到后面越像在忙别的事 → 原因是原目标随轨迹滚动被裁掉或被压成模糊一句 → 把目标与完成判据做成独立常驻字段，不参与裁剪，见 [系统提示](./k011-system-prompt.md) 与 [循环状态怎么存](./k027-loop-state.md)。
- **重述变成复读原文**：现象是每隔几轮插一段一模一样的目标说明，行为毫无变化 → 原因是没有更新进度、也没有拿最近动作做对照 → 重述必须带上已确认事实、剩余待办，并显式回答「本轮是否服务判据」，配合 [上下文预算表](./k041-context-budget.md) 控制频率。
- **摘要把判据磨没了**：现象是目标还写着「处理记录」，可「只累计哪一类」这个条件丢了，计数照样跑偏 → 原因是压缩只保大意、不保可判定条件 → 摘要后校验关键条件是否还在，见 [摘要压缩](./k044-summary-compression.md) 与 [压缩后校验](./k048-compression-verify.md)。
- **把合法改需求当成漂移**：现象是用户明确改了目标，程序却死守最初那句，把正确的新方向判成偏离 → 原因是锚点被当成永不变更的开机文本 → 目标带版本、变更留痕，重述读当前生效锚点，见 [提示与策略版本化](./k113-prompt-versioning.md)。
- **周期定得不合适**：现象是太长则偏了很久才发现、太短则重述成了背景噪声还白占上下文 → 原因是按「每轮一次」或「凭感觉」设周期 → 按阶段边界或固定轮数设，并用轨迹确认变更点前后方向确实换了，参考 [轨迹评测](./k089-trajectory-eval.md) 与 [停止条件](./k028-stop-conditions.md)。

还要分清「漂移」和「做错」：做错是某一步结果不对，校验器能当场抓到；漂移是每一步都对、只是合起来朝另一个终点走，靠单步校验抓不到，只能拿常驻锚点做周期性对照。也别把「目标写了」等同于「目标还在起作用」——判据是最近一步能不能回答它服务哪条完成条件。至于周期里「发现偏了之后怎么具体改」，那是 [反思与自我修正](./k026-reflection.md) 的活儿，本文管的是先看出来偏没偏。

:::check 学完自检
- [ ] 能说清目标漂移为什么没有哪一步明显报错，以及常见的四种成因
- [ ] 能解释重述与「复读原文」「自我安慰」各差在哪里
- [ ] 能徒手画出「钉住锚点—推进—重述对照—纠偏」的循环，并指出哪一步最常被省
- [ ] 能写出一次重述该带的四件事，并说明为什么完成判据必须可判定
- [ ] 能区分无声漂移与显式改需求，说出锚点该不该跟着变

## 三句话小结

目标漂移与周期性重述，讲的是长任务里程序会悄悄把「最近在忙什么」当成「本来要做什么」，因此要每隔一段拿常驻锚点重新对照一次。

关键做法是目标与完成判据独立常驻、重述时更新进度与剩余待办并校验最近动作、摘要后确认关键条件没丢，同时把合法的需求变更记成带版本的显式替换。

当任务几步就结束、或上下文短到目标始终清晰可见时，不必硬加周期性重述；但只要轨迹长到原目标会被挤出去，只靠开头写一次就一定不够。
