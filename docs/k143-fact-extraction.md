# 结构化事实抽取与记忆命名空间

## 场景提问

你给助手加了「记性」，让它在多轮对话里别忘了用户说过什么。做法很直接：每轮结束把整段对话原话存进一个列表，下轮再把列表一股脑贴上。跑了几天问题接连冒出来：用户明明先说「我常用语言是中文」、后来改成「还是用英文吧」，助手却经常答成中文，因为两句话都躺在列表里，模型分不清哪句更新；两个不同用户都叫「小周」，一个人的时区被另一个人的设置盖掉了；你想查「刚才那条口味偏好是从哪句话来的」，翻遍那一大坨原话也指不出出处。更麻烦的是，列表越攒越长，每轮都要重读一遍，明明只是想记住几个小事实，却背上了整本聊天记录。明明是「记性」，怎么越记越乱、越记越重？

## 破误解

**不是记的内容不够多，是你把「整段原话」直接当成了「记忆」，既没拆成可精确取用的结构，也没给不同归属划清边界。**

先把两样东西分开：日志和记忆。日志是「发生过什么」的流水，按时间一条条堆，适合事后回看；记忆是「现在成立的事实」，是要被下一轮直接拿来用的结论，见 [记忆与日志的区别](./k065-memory-vs-log.md)。把整段原话当记忆，等于每用一次都得让模型重新读一遍流水、再现场推断哪句还算数——既费篇幅，又给「分不清新旧」「张冠李戴」留足了空间。这跟 [记忆的类型](./k066-memory-types.md) 里把「事实」和「过程」分开是同一条道理：一条能用的事实，应该是「谁、哪方面、是什么」这样拆好的一小条，而不是一整段带着语气词和闲聊的话。

于是有了结构化事实抽取：把一句话里真正值得记的部分，抽成「主体—属性—值」这样的三元组（白话就是「说的是谁、说的是哪方面、具体是什么」），外加来源和顺序号。比如「小周的常用语言是中文」抽出来是「小周 / 常用语言 / 中文」，「小周喜欢清淡」抽出来是「小周 / 喜欢 / 清淡」。这一小条自带结构，取用时按「主体 + 属性」这个键一查就到，不必重读整段。这里有个要守的分寸：能由确定性规则拆开的部分，就用代码拆，别让模型自由发挥改写数字或措辞，见 [数字完整性](./k124-number-integrity.md) 与 [结构化输出约束](./k015-json-schema.md)；模型该做的是判断「这句值不值得记」，不是重新编一句概括，见 [写入决策](./k070-write-decision.md)。

光拆成三元组还不够，得给它们划归属，这就是命名空间（namespace，白话是「给记忆分区的名字前缀」，比如按用户、按会话、按项目各占一区）。同一个键「小周 / 常用语言」，在「用户甲」这一区和「用户乙」这一区是两条互不相关的事实，谁也不该盖掉谁；而同一区内同一个键，后来的新值才更新旧值，并且要留住「来自哪句话」以便追溯。没有命名空间，所有事实挤在一张平表里，同名主体必然串味；有了它，隔离、更新、追溯这三件事才各自有着落。检索时按命名空间先框定范围再取，也和 [元数据过滤](./k060-metadata-filter.md) 的思路相通。

## 生活类比

把它想成一个档案柜，而不是一本流水账本。前台听到一句「3 号房间的客人爱喝清淡的茶」，不会把这句话原封不动抄进账本了事，而是抽成一张小卡片：卡片上分栏写着「对象：3 号房间」「项目：口味」「内容：清淡」，背面注明「哪天、哪位客人亲口说的」。然后她把卡片放进标着「3 号楼」的那个抽屉——这个抽屉标签就是命名空间。下次有人问「3 号房间口味是什么」，她直接抽这张卡片念内容，不用把整本账从头翻一遍。

对应关系很具体：那句原话，就是对话里的一个句子；卡片上「对象 / 项目 / 内容」三栏，就是主体、属性、值这个三元组；卡片背面的注明，就是来源与顺序号，事后能追到原文；「3 号楼」那个抽屉，就是命名空间，它保证同名房间在别的楼里也有一张独立卡片、互不相干。同一格子里后来递来一张新卡片说「口味改成微辣」，前台就把旧卡片换下来、把新的放进去，并在背面记上新日期——这是同键更新且留痕；但旧卡片她并不扔掉，而是归进留存盒，出问题时还能查「当初到底写的是什么」，这就是历史留痕。

这个比喻还点出两处最容易翻车的细节。其一，如果前台懒得拆卡片，直接把整本账原样复印一份塞进抽屉，那么每次查一条口味都要重读整本，且两句矛盾的口味并排躺着、谁新谁旧全靠猜——正是「整段原话当记忆」的毛病。其二，如果所有楼共用同一个抽屉、卡片上又不写楼号，那么「3 号房间」在两栋楼各有一份，前台一不留神就把 A 楼的口味填给了 B 楼——正是没有命名空间的串味。把这些合起来看，「结构化」解决的是取得准不准，「命名空间」解决的是归得对不对，两件事缺一不可。

## 自绘示意图

:::figure 一句话变成一条可复用记忆的顺序
@flow
听到一句话|拆成三元组|标命名空间|按键落库|按区取回
:::

五格是一条链，重点在「拆成三元组」和「标命名空间」这两格：前者把一整段话压成能按属性精确取用的一小条，后者给这一小条划定归属。少了前者，取用就得重读原话；少了后者，不同来源的同名事实会挤在一起互相盖。最后「按区取回」强调读的时候也要带着命名空间，不能在全库里乱捞。

:::figure 一条结构化事实该带齐的五样
@stack
主体::这条事实说的是谁，别和同名的别人混
属性::说的是哪方面，语言还是口味还是时区
值::具体是什么，同一属性允许被更新
来源::来自哪句话，事后能追到原文
命名空间::归给哪个用户哪段范围，用来隔开
:::

五行里最常被省掉的是「来源」和「命名空间」。没有来源，答案出了错只能说「记着是这样」，指不出是哪句话记错的；没有命名空间，同名主体必然串味。而「主体、属性、值」这三行是能被精确按键查到的前提，任何一行含糊，这条事实就退回了「一整段话」的状态。

:::figure 两种记忆写法的差别
@compare
整段原话塞进去::取用要重读一遍|同名信息互相盖|串味了查不出
抽三元组按区存::按键精确取用|同键才更新且留来源|跨区互不干扰
:::

左边是把日志当记忆，写起来最省事，代价全花在「每次取用」和「出错排查」上；右边在写入时多拆一步、多标一个区，换来的是取得准、归得对、追得到。二者差距不在存了多少，而在存进去的东西有没有结构和边界。

## 层层追问

:::ask 那如果模型很会总结，让它读完对话自己写一句「用户偏好小结」，不是比拆三元组更省事吗？
:::

听起来省事，却把最不该交给「改写」的一环交了出去。一句自由发挥的小结是自然语言，里面哪个词对应哪条事实、哪条更新了哪条，全都糊在一起：用户把语言从中文改成英文，小结可能写成「中英文都可以」，一个原本清楚的更新被抹成了含糊的并存；数字、日期、专有名词也可能被顺手改错，而记忆库根本不知道它错了。更根本的问题是，小结没法按「属性」精确取用——想知道时区就得把整句小结再读一遍、再推断一次，等于绕回老路。稳妥的分工是：结构和值用确定性代码原样拆、原样存，模型只判断「这句值不值得记」「属于哪个命名空间」，见 [写入决策](./k070-write-decision.md) 与 [属性断言](./k088-property-assertion.md)；确实需要把很多条事实压成一段概览时，也该另存一份、且能追回原始条目，见 [实体摘要](./k069-entity-summary.md)。

再往下一层：那如果一句话里压根没有明确事实，比如「今天天气真不错」「可能大概是这样吧」，也要硬抽一条吗？不该。抽取要有「抽不出来就返回空」的自觉：闲聊、反问、猜测、带「可能 / 也许」的不确定表述，都不该被写成一条板钉钉的事实，否则库里会慢慢积出一堆伪事实，取用时反而污染判断。宁可少记，也别把猜测记成结论，这和 [属性断言](./k088-property-assertion.md) 里「能被确定性检查的才断言」是同一条分寸。要不要记、记多久、什么时候该让它淡出，可对照 [遗忘与淘汰](./k073-forgetting.md)。

:::ask 那如果同一个用户在两个不同会话里说了互相矛盾的话，到底该以哪条为准？
:::

这一问把「命名空间该划多细」推到了明处。先把两种「矛盾」分清：一种是真更新——同一区、同一主体、同一属性，用户后来明确改口了，那当然以新为准，但旧值不能悄悄删掉，要留进历史并带上各自来源，这正是 [冲突消解](./k071-conflict-resolution.md) 要管的；另一种其实不是矛盾，而是「归属本就不同」——工作会话里说「回复用英文」、私人会话里说「聊家常用中文」，两条各自成立，谁也不该盖谁。后一种若被塞进同一个命名空间，就会被误判成「互相矛盾」，然后粗暴地留一条丢一条。所以命名空间不必只按用户划，还可以按用户 + 会话 + 项目这样的组合划到够用的粒度：先让归属不同的事实各待各的区，再在同一区内谈新旧。判定新旧的依据必须是可靠的顺序号，而不是「哪条消息来得晚」——迟到的一步不该把已经更新的值改回去。

再往下一层：那命名空间划得太细，取用时会不会漏掉本该用到的记忆？会，所以「按区取回」之外还要一层「按相关度召回」：先由当前任务和身份框定该看哪几个区，再在这些区里挑相关的条目，必要时跨区合并但绝不跨区覆盖，见 [记忆召回](./k072-memory-recall.md)。还有一条不能松的线：跨区读取要受身份约束，A 用户不该读到 B 用户的事实，见 [记忆隐私](./k074-memory-privacy.md) 与 [会话隔离](./k105-session-isolation.md)。一句话：命名空间既要把「不是一回事」隔干净，又要让「该一起用」找得到，粒度要按「哪些事实可能互相盖」来定，而不是越细越好。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，把「从句子抽三元组—按命名空间分区—同键更新且留来源—跨区隔离—按区取回」完整演示一遍，结尾用一组断言逐条验证。所有句子、顺序号、命名空间都是手工构造的定值，结果可以逐条手算、完全可复现；复制到任意装有 Python 的机器上直接运行即可，不需要任何第三方包、账号或网络。它演示的是结构化与隔离这几条性质，不是任何真实记忆组件的实现。

```python
import json
from dataclasses import dataclass, asdict


@dataclass
class Fact:
    namespace: str      # 归属范围，如 user:u1 / project:p2
    subject: str        # 主体：这条事实说的是谁
    attr: str           # 属性：说的是哪方面
    value: str          # 值：具体是什么
    source: str         # 来源：来自哪句话
    seq: int            # 顺序号：用于判新旧


def extract_facts(utterance, namespace, source, seq):
    """确定性抽取桩：只认两种句式，把一句话拆成结构化三元组。"""
    facts = []
    for clause in utterance.split("；"):
        clause = clause.strip()
        if not clause:
            continue
        if "的" in clause and "是" in clause:
            left, value = clause.split("是", 1)
            subject, attr = left.split("的", 1)
            facts.append(Fact(namespace, subject.strip(), attr.strip(),
                              value.strip("。 "), source, seq))
        elif "喜欢" in clause:
            subject, value = clause.split("喜欢", 1)
            facts.append(Fact(namespace, subject.strip(), "喜欢",
                              value.strip("。 "), source, seq))
    return facts


class Memory:
    """按命名空间分区的记忆库；每个 (主体, 属性) 只留最新一条，带来源。"""

    def __init__(self):
        self.store = {}    # namespace -> {(subject, attr): Fact}
        self.history = []  # 全部写入留痕，含被覆盖的旧值

    def write(self, fact):
        bucket = self.store.setdefault(fact.namespace, {})
        key = (fact.subject, fact.attr)
        old = bucket.get(key)
        if old is None or fact.seq >= old.seq:
            bucket[key] = fact
        self.history.append(fact)

    def read(self, namespace, subject, attr):
        return self.store.get(namespace, {}).get((subject, attr))

    def dump(self, namespace):
        bucket = self.store.get(namespace, {})
        return sorted("%s.%s=%s" % (s, a, f.value)
                      for (s, a), f in bucket.items())


def main():
    mem = Memory()
    u1 = [
        ("小周的常用语言是中文", 1, "msg-001"),
        ("小周喜欢清淡", 2, "msg-002"),
        ("小周的时区是东八区", 3, "msg-003"),
        ("小周的常用语言是英文", 4, "msg-004"),  # 同一键，明确改口
    ]
    facts = []
    for text, seq, src in u1:
        facts.extend(extract_facts(text, "user:u1", src, seq))
    for f in facts:
        mem.write(f)

    checks = [
        ("抽到四条事实", len(facts) == 4),
        ("首条三元组正确",
         (facts[0].subject, facts[0].attr, facts[0].value)
         == ("小周", "常用语言", "中文")),
        ("喜欢句式归一成属性",
         facts[1].attr == "喜欢" and facts[1].value == "清淡"),
        ("每条都带命名空间", all(f.namespace == "user:u1" for f in facts)),
        ("每条都带来源", all(f.source.startswith("msg-") for f in facts)),
        ("同键取到更新后的值",
         mem.read("user:u1", "小周", "常用语言").value == "英文"),
        ("同键覆盖不新增条目", len(mem.store["user:u1"]) == 3),
        ("更新保留新来源",
         mem.read("user:u1", "小周", "常用语言").source == "msg-004"),
        ("历史仍留着旧值",
         any(f.value == "中文" and f.namespace == "user:u1"
             for f in mem.history)),
    ]

    # 另一个命名空间写同主体同属性，值不同，互不干扰
    b = extract_facts("小周的常用语言是法文", "user:u2", "msg-101", 1)
    for f in b:
        mem.write(f)
    checks.append(("u2 抽取成功", len(b) == 1))
    checks.append(("u2 读到自己的值",
                   mem.read("user:u2", "小周", "常用语言").value == "法文"))
    checks.append(("u1 未被 u2 污染",
                   mem.read("user:u1", "小周", "常用语言").value == "英文"))
    checks.append(("不存在的区读不到",
                   mem.read("user:u9", "小周", "常用语言") is None))
    checks.append(("读不存在的区不留空桶", "user:u9" not in mem.store))
    checks.append(("dump 只列本区",
                   mem.dump("user:u2") == ["小周.常用语言=法文"]))
    checks.append(("u1 的清单恰好三条", len(mem.dump("user:u1")) == 3))

    # 顺序号更小的消息迟到，不该把新值改回去
    late = extract_facts("小周的常用语言是德文", "user:u1", "msg-000", 0)
    mem.write(late[0])
    checks.append(("迟到的旧消息不改新值",
                   mem.read("user:u1", "小周", "常用语言").value == "英文"))
    checks.append(("迟到消息仍进历史", late[0] in mem.history))
    checks.append(("无匹配句式返回空",
                   extract_facts("今天天气不错", "user:u1", "msg-x", 9) == []))
    checks.append(("事实可序列化为快照",
                   "常用语言" in json.dumps(
                       [asdict(f) for f in mem.history], ensure_ascii=False)))

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `Fact` 用 `dataclass`（数据类，标准库里按字段声明自动生成构造与比较方法）定义一条结构化事实，六个字段就是前面图中那五样加一个顺序号：`namespace` 定归属，`subject`、`attr`、`value` 构成三元组，`source` 记出处，`seq` 判新旧。把「一条事实」做成有明确字段的对象，而不是一整段字符串，是整段代码的起点。
2. `extract_facts` 是确定性抽取桩：按中文分号 `；` 拆句，只认两种句式。含「的」和「是」的（如「小周的常用语言是中文」）按 `split("是", 1)` 分出左右、再按 `split("的", 1)` 拆出主体与属性；含「喜欢」的（如「小周喜欢清淡」）把「喜欢」本身当作属性。两句都不匹配的（如「今天天气不错」）就返回空列表——刻意不硬抽，正是「宁可少记，别把猜测记成结论」。`value.strip("。 ")` 去掉句号与空格这类噪声。
3. `Memory.write` 是落库：`setdefault` 按命名空间取到该区的字典，键用 `(主体, 属性)` 这个元组，所以同主体同属性天然只占一格。只有当旧值不存在、或新事实的 `seq` 不小于旧值时才覆盖；无论覆不覆盖，都无条件 `history.append(fact)` 留痕。这一行同时实现了「同键更新」「旧值可追」「迟到不改新值」。
4. `Memory.read` 用两级 `.get`，查不到就返回 `None`。这里特意用普通字典的 `.get` 而不是会自动建空桶的结构，为的是「读一个不存在的区」不会凭空多出一个空命名空间——断言里专门验了这一点。`dump` 只遍历指定区、按 `主体.属性=值` 排序输出，保证「按区取回」看到的就是这一区的内容。
5. `main` 第一组断言验证抽取与更新：四句各抽一条、首条三元组逐字段正确、「喜欢」被归一成属性、每条都带命名空间与来源；「常用语言」先中文后英文，`seq` 更大的英文覆盖中文，`user:u1` 这一区仍只有三条（语言、喜欢、时区），且来源更新为 `msg-004`、旧的「中文」仍躺在 `history` 里。
6. 第二组验证隔离：在 `user:u2` 写同主体同属性的「法文」，断言 u2 读到自己的值、u1 仍是「英文」、不存在的 `user:u9` 读到 `None` 且不留下空桶、`dump("user:u2")` 只列出它自己那一条、`dump("user:u1")` 恰好三条。这几条把「跨区互不干扰」钉死。
7. 第三组验证边界：一条 `seq=0` 的迟到消息「德文」被写入，但因顺序号小于当前值而不改新值、却仍进了历史；无匹配句式返回空；最后用 `json`（JavaScript Object Notation，一种纯文本的数据表示格式）配合 `asdict` 把历史序列化成快照，确认结构可落盘。结尾 `passed` 统计通过项、逐条打印结果，再以 `assert` 保证任何一条性质被破坏都会以非零状态退出。

有一处要如实说明：这里用两种固定句式代替了真实抽取器、用普通字典代替了持久化存储、用手工编的顺序号代替了真实时间线，全是为了让整条链路不需要联网、账号或第三方包就能独立跑通并逐条手算。它演示的是「拆成结构、按区隔离、同键更新且留来源」这几条性质，不是任何真实记忆库或抽取模型的实现；代码本身经过逐行静态复核到「复制即跑、逻辑自洽」，并未在此环境里实际启动执行。

## 踩坑与边界

- **整段原话当记忆**：现象是每轮都要重读一大坨聊天记录，新旧两句偏好并排躺着、模型分不清 → 原因是把日志当成了结论 → 抽成主体-属性-值三元组按属性精确取用，见 [记忆与日志的区别](./k065-memory-vs-log.md) 与 [记忆的类型](./k066-memory-types.md)。
- **让模型自由改写小结**：现象是「中文改英文」被写成「中英文都行」，数字日期还被顺手改错 → 原因是把结构化拆解交给了自然语言生成 → 结构与值用确定性代码拆、模型只判值不值得记，见 [写入决策](./k070-write-decision.md) 与 [数字完整性](./k124-number-integrity.md)。
- **所有事实挤一张平表**：现象是两个同名用户的事实互相盖，A 的时区被 B 的设置顶掉 → 原因是没划命名空间 → 按用户、会话、项目划到够用的粒度，读取也带区，见 [记忆隐私](./k074-memory-privacy.md) 与 [会话隔离](./k105-session-isolation.md)。
- **更新时把旧值删了**：现象是答案错了想追「当初写的是什么」，怎么也查不到 → 原因是覆盖即丢弃、没留来源 → 同键更新只换当前值，旧值连同来源进历史，见 [冲突消解](./k071-conflict-resolution.md) 与 [实体摘要](./k069-entity-summary.md)。
- **闲聊和猜测也硬抽**：现象是库里慢慢积出一堆「可能 / 也许」的伪事实，取用时污染判断 → 原因是抽取没有「抽不出来就返回空」的自觉 → 只记明确事实，不确定表述不落库，见 [属性断言](./k088-property-assertion.md) 与 [遗忘与淘汰](./k073-forgetting.md)。

还要说清一条边界：这套做法不是所有「记性」都需要。如果只是为了事后回看「刚才到底聊了什么」，老老实实存日志更好，硬拆成三元组反而丢了语气和上下文；它真正值钱的地方，是「下一轮要拿一条明确事实用」的时候。另一个分寸是命名空间的粒度：划得太粗会串味，划得太细又会让该一起用的事实散落在各处，所以要按「哪些事实可能互相盖」来定，并配一层按相关度的召回把该用的找回来，见 [记忆召回](./k072-memory-recall.md)。最后，抽取出来的结构最好能有个固定的字段约定，别让每条事实长得都不一样，见 [结构化状态](./k046-structured-state.md)；这份约定本身也该能核查，见 [结构化输出约束](./k015-json-schema.md)。

## 三句话小结

结构化事实抽取与记忆命名空间，是把「整段原话」拆成带主体、属性、值、来源与顺序号的一小条事实，再按归属分区存放，让下一轮能按键精确取用、且不同来源互不串味。

关键做法是结构与值用确定性代码原样拆、模型只判断值不值得记、同键更新只换当前值并把旧值连同来源留进历史、读取始终带着命名空间、抽不出来的句子宁可不记。

当需求只是事后回看聊天流水、或内容全是闲聊与推测时，不必硬套三元组与分区；但只要下一轮要拿一条明确事实来用，就别再把整段对话原样塞进记忆。
