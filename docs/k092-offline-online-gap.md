# 离线好、线上差的成因

## 场景提问

你花了一周攒出一批评测用例，本地跑下来分数很漂亮，几乎条条通过，于是把提示词、工具定义和模型版本一起发布给了真实用户。第二天却收到一堆反馈：有人问一句带错别字的话就答非所问，有人连着追问两轮后 Agent（智能体，能自己拆解任务、调用工具、循环推进的程序）把上一轮的结论忘了，还有人明明看到「已完成」的回复、事情其实根本没办成。你翻开评测记录，同一套代码在那批用例上依旧满分。分数没变、代码没改，怎么换到真实用户手里就处处不对？

## 破误解

**不是模型突然退化了，也不是评测分数造假，而是「离线这把尺子」和「线上这摊事」根本不是同一批东西，中间还隔着一整条会悄悄变味的链路。**

先把两个词说清。离线评测（offline evaluation，用一批事先准备好的固定用例，在发布前给系统打分）量的是「在这些见过的题上表现如何」；线上（online，真实用户请求进入正在运行的系统）量的是「此刻这摊杂事有没有办成」。这两件事之间至少隔着四层不对齐，任何一层出错，都会出现「分数很高、体感很差」。第一层是样本不对齐：评测集（一批带标准答案或判定规则的用例）往往干净、均衡、类别集中，真实输入却错别字、多意图、超长、空内容、冷门请求混在一起，所谓分布（各类型输入出现的比例和花样）完全不同。第二层是链路不对齐：离线多为单轮、下游稳定、无并发、不触发超时，线上是多轮、下游会抖、缓存时好时坏、还带着上一轮的会话状态。第三层是口径不对齐：离线常按「产出字段和标准答案是否一致」判分，线上用户只认「事情办没办成、等了多久、花了多少」。第四层是版本不对齐：离线测的那套提示、模型版本、工具描述、检索内容，和线上此刻真正加载的组合未必是同一套。还有个更隐蔽的前提：如果线上没有留下可复现的记录，你连「到底差在哪一条、当时用的是哪套」都答不上来，落差就永远补不回来。所以这件事的关键不在「再多测几条」，而在把四层不对齐逐条拆开、定位，再把真实失败带回离线；否则你只是在用一把越来越精致、却始终没对准目标的尺子反复量自己。

## 生活类比

把它想成驾校考试和真正上路。考场里是固定那几条路线，路面平整、大晴天、副驾坐着教练，练的就是要考的那几个动作，考官手里有标准答案，打方向早半秒晚半秒都按同一把尺子扣分。练得熟了，几乎人人满分。可真上了路：晚高峰、下暴雨、有人突然横穿、导航地图还是半年前的、车上还坐着要赶时间的乘客，没有标准答案，只有「到没到、安不安全、乘客骂不骂、油钱花得值不值」。

对应关系要逐条对上才有用。固定路线和晴天，就是评测集里干净、均衡、见过的输入；练的就是考的，对应拿同一批用例反复调参、把分数刷到虚高；考官按标准答案打分，就是离线按字段一致性判分，它量不到「这一路是不是绕了远、急刹了几次」；晚高峰和暴雨，就是线上的并发、超时和下游抖动；导航没更新，对应版本漂移（组合随时间悄悄变化）——离线测的那套提示与模型，和车上此刻装着的那套已经不是一回事；乘客的体感，才是线上真正该看的指标；而行车记录仪，就是每条请求留下的轨迹（一次任务里每一步动作、工具调用与结果按时间串起来的记录）。这个比喻还点出最要命的一处：最怕的不是考砸，是出了刮蹭却没装记录仪，事后再也复现不出当时那一路到底怎么回事。放到系统里，就是「线上没留字段、没存版本」，于是任何抱怨都无法变成一条能重跑的用例。还有一层：把某一段真实路况录下来、搬回训练场反复练，正是后面要讲的回收闭环，落差不是靠多考几次消掉的，是靠把路上的意外一条条变成考场里的题消掉的。也别忘了，考场满分只说明那几条路线开得熟，它从来不是「什么天气都能开好」的证明——把两者划等号，正是这个误解最顽固的地方。

## 自绘示意图

:::figure 同一套系统两种处境
@compare
离线评测::输入干净且均衡|单轮下游稳定|按标准答案算分
线上运行::长尾与脏输入多|并发下游会抖|按任务办没办成判定
:::

左边是发布前那把尺子，右边是发布后那摊事。两行刻意只写三格：差别不在「题更多」，而在输入的干净程度、链路的稳定程度、以及判分认的是什么，三样全变了。任何一样没对齐，分数与体感就会各说各话。

:::figure 落差落在哪四层
@stack
样本落差::离线集均衡干净，线上长尾、脏输入、多意图混杂
链路落差::离线单轮无并发，线上多轮、超时、下游状态会变
口径落差::离线按标准答案算分，线上按任务是否办成判定
版本落差::离线测的组合与线上真正加载的组合不是同一套
:::

四格里最容易被跳过的，是最后那格。前三格再怎么补，只要离线测的是一套提示与模型、线上跑的是另一套，比对就失去意义；所以排查要先看版本，再看别的。另一个常被忽略的顺序是：先得有记录能看见这四层，才谈得上分辨是哪一层，否则四格都只是猜测。

:::figure 把落差补回来的循环
@cycle
线上留全轨迹|筛出失败请求|归因到某一层|回灌评测集|重跑门禁再发布
:::

这五个节点画成环，是因为它不是一次性体检。线上先留下能复现的记录，才谈得上筛出失败请求；归因到具体某一层，回灌（把真实失败补进评测集）才有方向；补进去之后要重跑门禁（发布前必须全过的一组固定检查），确认旧题没被带坏、新题确实被守住，再发布。少一环，下一次翻车还是从头猜。把这条环真正跑起来的分级与筛选办法，是 [Badcase 回收闭环与分级评测](./k093-badcase-loop.md) 要讲的事。

## 层层追问

:::ask 那如果我把评测集铺到几万条、把花样都覆盖齐，是不是就没落差了？
:::

覆盖得再广，也追不上三件事。第一，真实分布是活的：节假日、新活动、新一批用户会带来上个月根本不存在的说法，长尾（出现次数少但花样多的冷门请求）没有尽头，靠事先枚举永远补不齐，这类比例怎么搭配才不至于自欺，可以对照 [用例配比](./k087-case-mix.md)。第二，覆盖越广越容易撞上数据泄漏（本该只用来检验的用例，被反复拿来调提示和选模型，等于提前背了题）：分数是被这批题喂出来的，换一批同难度的新题就往下掉，评测集一旦既当练习题又当考卷，高分就说明不了泛化，这层要靠 [评测数据集](./k086-eval-dataset.md) 里把题目分卷、留出从不参与调参的那一批来治。第三，也是最根本的：口径和链路不是靠样本数量能补的。离线判「字段对不对」，线上判「事办没办成、绕没绕远路」，哪怕输入一字不差，两种判法也会给出不同结论，只看终稿不看过程可以对照 [轨迹评测](./k089-trajectory-eval.md) 与 [属性断言](./k088-property-assertion.md)；而超时、下游抖动、多轮上下文这类状态，压根不属于「题面」，加再多静态用例也造不出来。所以把题铺广是必要的，但它是缩小落差的补法之一，不是让落差消失的开关。更实际的做法是承认分布会一直变，把力气花在「让新出现的失败能被看见、能被收进来」这件事上，而不是幻想一次性穷举完所有输入。

:::ask 那如果分数和体感明显对不上，我该先查哪一层，能不能直接归咎于模型不行？
:::

先别急着换模型，按一个固定顺序查，能省掉大量瞎试。第一步查版本：把这条线上请求当时用的提示、模型版本、工具描述、检索内容逐样和离线测的那套对一遍，组合不同就先对齐，否则后面全是无意义的比对，这套做法在 [提示与策略版本化](./k113-prompt-versioning.md) 和 [版本漂移与升级策略](./k084-version-drift.md) 里展开。第二步查观测：这条请求能不能被完整复现——输入原文、每一步工具调用、返回、耗时、最终判分在不在，缺字段就先补 [轨迹字段](./k094-trace-fields.md) 与 [结构化日志](./k095-structured-log.md)，没有记录就没有归因，这一条经常是整个排查的瓶颈。第三步查样本：把这条输入放回评测集比一比，是不是压根没见过的类别、是不是带脏字符或多意图，属于样本落差就回灌。第四步查链路：是不是多轮里丢了状态、下游超时被重试掩盖、并发下改了别人的数据，这类要看过程而不是终稿。第五步才谈口径与模型：离线那把尺子是不是太松，比如用大语言模型（Large Language Model，缩写 LLM，让另一个模型给输出打分的做法）当评委时偏爱长答案、把「看起来完整」当成「办成了」，这在 [大模型评判](./k090-llm-judge.md) 里有细讲；也可能真就是能力不足。把顺序倒过来，一上来就换模型，往往是把版本错配或缺失的字段误当成能力问题，换了模型分数照样对不上。查清是哪一层之后，还要把这条失败固化成一道门禁用例，见 [回归门禁与基线](./k091-regression-gate.md)；至于该盯哪几类线上指标、为什么不按每次调用算账，可对照 [按成功任务核算成本](./k096-metrics-cost.md)。还有一句要记牢：排查的产出不该只是「这次修好了」，而该是「下次同类问题会被门禁挡住」，否则同一个坑会反复踩。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，用本地确定性桩函数（一段写死的、用来代替真实模块的本地模拟代码）造出两份输入，演示「离线满分、线上掉分」，并把掉分逐层拆开：每次只把一层的条件改回离线状态，看重跑分数回升多少，回升幅度就是这一层的贡献；最后把线上失败请求回收成用例，看评测集覆盖的类别怎么变化。全程不联网、不要账号、不装任何第三方包，复制到装有 Python 的机器上直接运行即可。

```python
from collections import Counter


SEEN_KINDS = ("查订单", "改地址", "问退换")
ALL_KINDS = SEEN_KINDS + ("开发票", "催退款", "改签")


def make_offline_cases(n=300):
    """离线评测集：类别均衡、输入干净、单轮、下游稳定。"""
    cases = []
    for i in range(n):
        cases.append({
            "id": "off-%03d" % i,
            "kind": SEEN_KINDS[i % len(SEEN_KINDS)],
            "dirty": False,
            "downstream_ok": True,
            "multi_turn": False,
            "retried": False,
            "version": "v1",
        })
    return cases


def make_online_cases(n=300):
    """线上流量：含未见类别、脏输入、下游抖动、多轮与绕远路。"""
    cases = []
    for i in range(n):
        cases.append({
            "id": "on-%03d" % i,
            "kind": ALL_KINDS[i % len(ALL_KINDS)],
            "dirty": (i % 5 == 0),
            "downstream_ok": (i % 11 != 0),
            "multi_turn": (i % 7 == 0),
            "retried": (i % 9 == 0),
            "version": "v2",
        })
    return cases


def agent_ok(case):
    """本地确定性桩：模拟只在见过的干净单轮类别上稳定的能力。"""
    if case["kind"] not in SEEN_KINDS:
        return False
    if case["dirty"] or not case["downstream_ok"] or case["multi_turn"]:
        return False
    if case["version"] == "v2" and case["kind"] == "改地址":
        return False
    return True


def score(cases):
    """离线口径：产出与标准答案对上就算通过。"""
    if not cases:
        return 0.0
    return sum(1 for c in cases if agent_ok(c)) / len(cases)


def goal_score(cases):
    """线上口径：还要求没绕远路重试，才算任务真的办成。"""
    if not cases:
        return 0.0
    return sum(1 for c in cases if agent_ok(c) and not c["retried"]) / len(cases)


def fix_factors(cases, factors):
    """把指定落差层还原成离线条件，返回修好后的请求副本。"""
    patched = []
    for c in cases:
        d = dict(c)
        if "样本落差" in factors:
            d["kind"] = SEEN_KINDS[0]
            d["dirty"] = False
        if "链路落差" in factors:
            d["downstream_ok"] = True
            d["multi_turn"] = False
        if "版本落差" in factors:
            d["version"] = "v1"
        patched.append(d)
    return patched


def collect_badcases(cases, known_kinds):
    """回收：挑出做失败、且类别不在离线集里的请求。"""
    return [c for c in cases if not agent_ok(c) and c["kind"] not in known_kinds]


def coverage(known_kinds, badcases):
    """回灌后评测集覆盖到的类别集合。"""
    return set(known_kinds) | {c["kind"] for c in badcases}


def main():
    offline = make_offline_cases()
    online = make_online_cases()
    offline_rate = score(offline)
    online_rate = score(online)
    online_goal = goal_score(online)

    lifts = {}
    for factor in ("样本落差", "链路落差", "版本落差"):
        lifts[factor] = score(fix_factors(online, [factor])) - online_rate

    fully_fixed = score(fix_factors(
        online, ["样本落差", "链路落差", "版本落差"]))
    badcases = collect_badcases(online, SEEN_KINDS)
    kinds_after = coverage(SEEN_KINDS, badcases)
    counts = Counter(c["kind"] for c in badcases)

    checks = [
        ("离线评测集分数为满分", offline_rate == 1.0),
        ("线上分数明显低于离线", online_rate < offline_rate - 0.3),
        ("线上分数处于可定位区间", 0.0 < online_rate < 0.5),
        ("换任务口径后分数再降一截", online_goal < online_rate),
        ("样本落差修好后有正回升", lifts["样本落差"] > 0),
        ("链路落差修好后有正回升", lifts["链路落差"] > 0),
        ("版本落差修好后有正回升", lifts["版本落差"] > 0),
        ("三层全部修好回到满分", fully_fixed == 1.0),
        ("回收到非空的失败样本", len(badcases) > 0),
        ("回灌后覆盖类别数增加", len(kinds_after) > len(set(SEEN_KINDS))),
        ("回灌后覆盖到全部六类", len(kinds_after) == len(ALL_KINDS)),
        ("回收样本按类别可统计", set(counts) == set(ALL_KINDS) - set(SEEN_KINDS)),
        ("两次构造的线上流量一致", make_online_cases() == online),
    ]

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == '__main__':
    main()
```

1. `SEEN_KINDS` 是离线集见过的三类，`ALL_KINDS` 是线上会出现的六类。`make_offline_cases` 造出干净、均衡、单轮、下游稳定、版本为 `v1` 的三百条；`make_online_cases` 用取模造出含未见类别、错别字、下游抖动、多轮、重试痕迹、版本为 `v2` 的三百条。用固定的取模而不是随机数，是为了每条请求落在哪个条件上都能手工推算、结果完全可复现。
2. `agent_ok` 是本地桩，把「只在见过的干净单轮类别上稳定」这条能力写死：类别没见过就失败，输入脏、下游坏、多轮任一为真就失败，且 `v2` 会让「改地址」这一类悄悄退化。最后那一条正是版本落差——同一段代码，换个加载的组合就少做对一类事。
3. `score` 是离线口径，只看 `agent_ok`；`goal_score` 是线上口径，额外要求没有 `retried`（绕远路重试过）。于是会出现「字段对了、事却没真办成」的请求，被更严的口径扣掉，这就是口径落差如何单独拉低分数。
4. `fix_factors` 做分层归因：传入哪一层，就只把那一层的条件改回离线状态，其余原样保留。样本层把类别与脏输入还原，链路层把下游与多轮还原，版本层把 `v2` 拨回 `v1`。它用的是 `dict(c)` 复制，不会改动原始请求，因此各层可以独立重算、互不影响。
5. `collect_badcases` 挑出「做失败且类别不在离线集」的请求，`coverage` 用集合并运算算出回灌后覆盖到的类别。两者对应循环图里「筛出失败请求」和「回灌评测集」两格。
6. `main` 先算离线分、线上分与任务口径分，再对三层各算一次 `lifts[factor] = 修好后的分数 - 线上基线`，也就是逐层回升幅度；随后算三层全修的结果、回收样本数与回灌后的类别集合，`Counter` 只用来统计回收样本按类别各有几条。
7. 十三项断言逐条验证：离线满分而线上明显掉分、换口径再降一截、三层各自都有正回升、三层全修回到满分、回收样本非空且把覆盖类别从三类补到六类、两次构造流量完全一致。结尾 `assert` 保证任何一条性质被破坏都会以非零状态退出，打印的「通过 N/N 项」便于一眼看出是全过还是有漏。

有一处要如实说明：这里用写死的类别和模数代替真实分布、用本地桩代替真实模型、用「改回条件看回升」代替真实归因，全是为了让整条链路不需要联网、账号或第三方包就能独立跑通，且每个数值可手工推算。它演示的是分层定位的顺序与回升的含义，不是任何真实系统的统计结果，也不是对某个具体平台的实现。

## 踩坑与边界

- **拿同一批用例反复调参**：现象是离线分数越调越高、线上却毫无起色，换一批同难度新题立刻掉 → 原因是评测集既当练习题又当考卷，发生了数据泄漏 → 把题目分卷，留出一批从不参与调参的用例只用来终检，见 [评测数据集](./k086-eval-dataset.md)。
- **评测集只放干净短输入**：现象是本地条条通过，真实用户一打错字、一次提两个需求就答非所问 → 原因是样本分布与真实输入不对齐，长尾压根没进过考卷 → 按真实比例补进脏输入、多意图、超长与空内容，并让类别搭配可解释，参考 [用例配比](./k087-case-mix.md)。
- **线上不留版本与轨迹**：现象是收到差评却复现不出、说不清当时用的哪套提示和模型，「想查都无从查起」 → 原因是只记了最终回复，没记组合与过程 → 每条请求落全输入、逐步动作、耗时与版本标识，见 [轨迹字段](./k094-trace-fields.md) 与 [结构化日志](./k095-structured-log.md)。
- **只判终稿不判过程**：现象是回复看着完整、字段也对，事情却没办成，或是靠反复重试绕出来的 → 原因是离线按标准答案判分，量不到过程是否合理 → 把轨迹里的步骤、重试、越权一并纳入判定，对照 [轨迹评测](./k089-trajectory-eval.md)。
- **一掉分就换模型**：现象是模型换了、成本上去了，分数和体感依旧对不上 → 原因是把版本错配、缺失字段这类问题误当成能力不足 → 按版本、观测、样本、链路、口径的顺序逐层排除，最后才动模型，并把结论固化成 [回归门禁与基线](./k091-regression-gate.md) 里的一道用例。

还要分清两件容易混的事：落差与退化。落差是尺子和事情不对齐，往往一直存在、只是发布后才暴露；退化是同一把尺子下分数真的往下走，属于改动把旧题做坏了。前者要补观测、补样本、对齐版本与口径，后者要定位是哪次改动引入的。另外，把改动先放在只观察不执行的位置看清差异、再决定放不放量，是 [影子模式、灰度与回滚](./k112-shadow-canary.md) 的做法；给线上目标预先写明一条可守护的量化线，可对照 [健康检查与服务等级目标](./k114-health-slo.md)，其中 SLO 指服务等级目标（Service Level Objective），即给可用性等指标事先定好的线。把「这次修好了」变成「下次同类问题会被挡住」，才是补落差真正的终点。

## 三句话小结

离线好、线上差，指的是用固定用例打出的分数与真实用户体感之间的落差，成因是样本、链路、口径、版本四层不对齐，而不是模型突然变差。

关键做法是先对齐版本组合、补齐可复现的轨迹字段，再按版本、观测、样本、链路、口径的顺序逐层归因，把真实失败回灌成评测用例并重跑门禁。

当系统只产出离线结果、根本没有真实流量可比时，不必硬追这套落差分析；但只要一次改动会改变对外行为，就不该把离线分数当成线上会同样好看的保证。
