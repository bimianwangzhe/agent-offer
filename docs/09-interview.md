# Agent 开发岗面试考点与追问链

Agent 岗的面试有个特点：**第一轮问概念，第二轮全在追问「你线上怎么处理的」**。只会背概念的人，在第二轮会集中露馅。

## 高频考点分布

| 模块 | 典型问题 | 考察点 |
|---|---|---|
| 基础边界 | Agent 和 Workflow 区别？什么时候不该用 Agent？ | 工程判断，不是背定义 |
| 循环与状态 | 循环怎么终止？服务重启了怎么办？ | 终止条件、检查点、幂等 |
| 上下文 | 上下文爆了怎么办？工具很多怎么塞？ | 预算、分层、压缩、动态装载 |
| 工具 | 参数幻觉怎么防？重复调用怎么办？ | Schema、幂等、权限 |
| RAG | 召回不准怎么定位？怎么防幻觉？ | 排查顺序、溯源校验、弃权 |
| 协议 | MCP 解决了什么？没解决什么？ | 边界清晰，别吹成银弹 |
| 框架 | 为什么选它？换掉成本多大？ | 解耦、可观测、决策能力 |
| 评测上线 | 怎么证明没变差？成本怎么控？ | **分水岭** |
| 安全 | 文档里夹了恶意指令怎么办？ | 提示注入、权限、HITL |

## 追问链：面试官真正想听的

同一道题，追问会一层层往工程深处走。举四条最典型的链：

**链 1 · 从 RAG 到可靠性**
```
「你做了 RAG 吗？」→「召回不准你怎么定位？」
→「是切分问题还是检索问题，怎么区分？」
→「答案里有原文没有的内容，怎么挡？」
→「改了一版之后，怎么确认没有把老问题弄坏？」
```
最后一句才是分水岭。答「人工试了几个 case」和答「50 条评测集 + 回归门禁」，是两个档位。

**链 2 · 从循环到生产**
```
「用了 ReAct 吗？」→「最大轮数设多少？」
→「工具一直报错会怎样？」→「跑到一半进程挂了呢？」
→「高危动作怎么控制？」
```
对应：预算上限、错误回传、检查点 + 幂等、HITL + 最小权限。

**链 3 · 从 MCP 到安全**
```
「接了 MCP 吗？」→「接了几个 Server、多少工具？」
→「工具描述占多少 token？」→「动态装载怎么做？」
→「Server 返回的内容里夹了指令，你怎么办？」
```
对应：上下文成本、外部内容不可信、权限兜底。

**链 4 · 从框架到判断**
```
「用的什么框架？」→「为什么不用 XX？」
→「框架替你做了什么？」→「哪些事它没替你做？」
→「如果明天要换掉，成本在哪？」
```
想听的是「领域逻辑留在自己函数里，框架只管编排」。

## 讲项目的五段式

不要按时间顺序讲「我先搭了环境……」。用这个结构，15 分钟讲完且能接住追问：

```
1. 背景与约束   什么业务、多少 QPS、成本上限、什么不能错
2. 方案与决策   为什么是 Agent/Workflow、为什么选这个框架
3. 关键设计     上下文分层、状态与幂等、评测集、护栏
4. 数据         成功率（口径！）、单任务成本、P95、上线后 bad case 数
5. 复盘         哪个决策后来被推翻了、为什么
```

**第 4 步的数字必须有口径**（「成功率」是评测集上的还是线上的？样本多少？）。没有口径的数字，一追问就塌。

## 反直觉加分点

- 主动说「这块我们最后用了 Workflow 而不是 Agent」——比强行 Agent 化更显判断
- 主动说「先单 Agent，多 Agent 的复杂度不值得」——反住了追新词的冲动
- 主动说「这版 Prompt 改完评测分掉了，回滚了」——证明你真的有回归机制
- 主动说「提示词防不住的用权限防」——安全理解到位

## 别踩的坑

- 通篇讲框架 API，不讲自己的决策
- 把「调通 Demo」说成「上线」
- 用「效果还不错」代替数字
- 被问到没做过的部分就硬编——直接说「这块当时没做，如果补我会先做 X」，反而加分

## 验收点

- 任挑一条追问链，能连续答到第四层
- 用五段式讲完项目，且每个数字都能说出口径
- 至少准备一个「被推翻的决策」的复盘
