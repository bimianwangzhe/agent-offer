# 为什么需要 RAG：把知识放在能更新的地方

## 一句报价引发的追问

你给客服写了个问答助手，用户问「设备质保多久」，它张口就答「两年」，可公司上个月刚把政策改成三年。你试着把新制度贴进提示词让它照着念，头两轮还准，制度一多就开始张冠李戴，账单也悄悄涨了一截。有人提议「干脆让模型把制度学进去」，你一问才知道那要重新训练一轮，而且以后每改一次规定都得再来一次。

## 先破一个误解

**不是模型记性差，是你把「会变的事实」放进了「不会变的地方」。**

先把词说清楚。RAG 是 Retrieval-Augmented Generation（检索增强生成）的缩写，白话讲就是：不指望模型自己记住资料，而是在回答之前先从外部材料里找出相关的几段，把这几段连同问题一起递给模型，让它照着材料作答。这里「检索」指按问题去材料里翻找，「增强」指把找到的东西补进这次输入，「生成」才是模型最后写答案。它跟另一个概念要分开：幻觉（hallucination，指模型把话接得太像真的、编出了没有依据的内容）是模型固有的倾向，靠一句「请如实回答」压不住，必须由系统外部补上依据，这正是[幻觉为什么必然存在](./k005-hallucination.md)讨论过的事。

给一份外部知识找位置，掰开数其实只有三种放法，各有各的账。

第一种是塞提示词：把材料原文整段拼进每轮输入。好处是零额外设施，材料少且固定时最省事；代价是每轮都要为全部材料付一遍长度的钱，材料一旦接近窗口上限就放不下，而且片段挤成一团，当前这个问题反而被埋没，答案也没有可以指认的出处。第二种是改权重：通过继续训练把知识写进参数。它擅长改行为、改语气、改输出格式，却不擅长记事实——知识固化在训练那一刻，规定一变就得重来，没法按条更新，更没法溯源，而且「支持退货」和「不支持退货」这种只差一字的句子，在参数里极易被抹成同一个印象。第三种就是检索：材料进来时整理成一份可查的目录，提问时按问题取回少数片段，再让模型照着片段回答。材料随改随用，答案能指回具体某一段，代价是多出一条要维护的链路。

这三种不是谁替代谁，而是缺口不同：要补的是「可变的、要出处的事实」，检索几乎无可替代；要补的是「稳定的行为与表达习惯」，改权重才对路；材料总共三五页、一年不动，塞提示词反而最划算。真正的判据是三件事——材料变不变、要不要逐条出处、体积离窗口上限还有多远——而不是别人都在用什么。把这三种放法摆在同一组小材料上跑一遍，差别会非常直观，下面那段代码做的就是这件事。整套材料的组织脉络可以从[从这里开始](./00-start-here.md)顺着看下去。

## 用一场开卷考试来理解

把模型想成进考场的考生，外部材料是想带进去的书，用户的提问是考题。三种放法正好对应三种备考方式。

改权重相当于把整本书背下来再进考场：张口就来，速度最快，可考纲一换，脑子里仍是旧版，你问他「这话第几页」，他答不上来。塞提示词相当于把整本书抄进答题卡：卷面就那么大，抄到后面字挤成一片，自己都找不着重点，抄不下时干脆交白卷。检索相当于允许带一本带目录的书：先看题目，顺着目录翻到那一页，只把那一页摊开照着答，顺便在答案后面标个页码。

对应关系要一一对上才有意思：目录是索引，翻页这个动作是召回（recall，指把该找的片段找出来），摊开的那几页是送进上下文的片段，标的页码是出处，考题就是查询。开卷考试真正的好处不是「书更厚」，而是「翻得到、翻得准、还能报页码」。这也顺带点出了检索这条路隐含的三个前提：答案确实写在某一页上、那一页能被翻到、考生确实照着它答。三处任何一处断了，表面看都是同一副样子——编得像真的一样。所以答不准时别急着怪考生，先分清是「没翻到」还是「翻到了却读错」，这是[多轮检索与检索质量评测](./k064-rag-eval.md)要处理的事。

:::quote
外部知识不是「要不要给」的问题，是「什么时候给、给哪几页、能不能指回去」的问题。检索一次把这三件事都办了。
:::

## 把三种放法画出来

下面这张图把一条完整链路摊开。注意前两个动作发生在材料进来的时候，后三个发生在用户提问的时候，中间那道分界正是这套办法最值钱的地方。

:::figure 一次带检索的回答经过哪些动作
@flow
材料入库|建立目录|问题到来|按题取片段|照片段作答
:::

五个节点里，前两个跟「用户问什么」毫无关系，可以慢慢做、做错重做；后三个必须当场完成，直接决定这一轮的答案。把两者拆开，才谈得上分别优化，具体怎么拆见[离线索引与在线检索两段](./k052-index-query-two-stage.md)。

三种放法各自要付的账，可以并排列在一张清单里：

:::figure 三种放法各自要付的账
@stack
塞提示词::每轮为全部材料付长度，放不下就答不了
改权重::更新要重训，且说不出依据在哪一段
做检索::材料随改随用，多一条链路要维护
:::

最后一行那个「多一条链路」不是客套，是实打实的成本：多一份目录要建、要更新、要处理脏数据，还要有人盯着检索准不准。所以判据里才留了「材料少且固定就直接塞」这一档——收益盖不过这条链路的维护量时，别硬搭。

再把「只依赖参数」和「外挂一份可查材料」两种做法放到一起看：

:::figure 只依赖参数，与外挂一份可查的材料
@compare
只靠背下来的::规定一变就旧|说不出第几页|更新要重训
外挂可查材料::材料随改随用|答案指得回片段|多一条链路要养
:::

这两行不只是风格不同。前者出问题时你只能反复调提示词、换个更大的模型，后者至少能先把「这一轮到底递了哪几段」打印出来，排查路径完全不一样。

:::tip 一条立刻见效的规则
任何要求「给依据」「能追责」「数字不许编」的问题，都别指望靠一句「请根据材料回答」压住。把相关片段找出来、连同它的编号一起递过去，再让答案标回编号，比反复调提示词有用得多。
:::

## 再往深问两层

:::ask 那如果材料就三五页、一年也不改一次，是不是根本不用检索？
:::

基本对，而且这个判断该由你主动做，不要因为别处都在讲检索就默认要搭一整套。材料少、固定、不需要逐条出处时，整段塞进提示词的实现最短、出错点最少。但要把话说全：这里的「少」是相对窗口上限而言，不是相对你的耐心；三五页纯文本没问题，三五页里若夹着几张大表，长度估算很容易翻车，这时候还是得先按结构拆一拆，见[文档解析与清洗](./k053-doc-cleaning.md)。另外「不改」也要打个问号，只要存在改的可能，就得留一条能重来的路，否则第一次改规定就要把整套问答推翻重做。

:::ask 再深一层：把资料训练进参数、再叠一层检索，是不是就两全了？
:::

可以叠，但先想清楚各自在补什么，否则会花两遍钱补同一个洞。改参数动的是「怎么说话」：语气、格式、领域行话、稳定偏好，这些每轮都一样，固化下来最省；检索补的是「此刻的事实」：会变、要出处、按权限可见。把会变的事实也塞进参数，等于给它判了「一改就作废」的命，还丢了出处。反过来，用检索去教模型固定的输出格式，是每轮重复付一遍本可以一次付清的账。两条路各管一段，叠加是分工不是保险。真正容易出事的是把「没答准」一律归因为「参数不够」，于是不停重训，而证据其实早就躺在库里只是没被翻到——那种情况下该修的是目录，不是考生；目录怎么跟着材料变动，见[索引更新、增量与知识冲突](./k063-index-update.md)。

## 一份能跑的对照

下面这段只用标准库，把三种放法摆在同一组自己构造的小材料上跑一遍。它不连任何服务、不需要模型，用一个写死的桩函数代表「参数里的旧知识」，复制成文件直接运行就能看到三者的差别。

```python
# why_rag.py —— 只用标准库，python why_rag.py
import re

DOCS = [
    "员工出差住宿标准：一线城市每晚 600 元，其他城市每晚 400 元。",
    "差旅报销需在行程结束后七个工作日内提交发票。",
    "设备型号 XJ-2200B 的质保期为三年，含上门检修。",
    "请假流程：在内部系统发起申请，由直属主管审批。",
]
OLD_ANSWER = "每晚 400 元"          # 桩：写死在参数里的旧知识
QUESTION = "一线城市住宿每晚多少钱"


def bigrams(text):
    segs = re.findall(r"[\u4e00-\u9fff]+", text)
    out = []
    for seg in segs:
        out += [seg[i:i + 2] for i in range(len(seg) - 1)]
    return set(out)


def stuff_all(docs, question):
    # 方式一：把全部材料塞进提示词
    return "参考资料：\n" + "\n".join(docs) + "\n问题：" + question


def parametric(question):
    # 方式二：指望模型记住知识，不提供任何材料
    return OLD_ANSWER


def retrieve(docs, question):
    # 方式三：只挑与问题词面最相干的片段
    keys = bigrams(question)
    return max(docs, key=lambda d: len(keys & bigrams(d)))


if __name__ == '__main__':
    p_all = stuff_all(DOCS, QUESTION)
    p_hit = retrieve(DOCS, QUESTION)
    a_old = parametric(QUESTION)

    assert len(p_hit) < len(p_all)                 # 检索只带一段，输入更短
    assert "600" in p_hit                         # 命中写有一线城市标准的那段
    assert "600" not in a_old                     # 不给材料时只能吐旧口径
    assert "住宿" in p_hit                         # 命中片段与问题主题一致
    assert all(d in p_all for d in DOCS)           # 塞全部时每段都进上下文
    print("通过 5/5 项：塞全部 / 靠参数 / 按需检索三种放法的差异")
```

1. `DOCS` 是本地构造的四段小材料，全部写在文件里，不读磁盘、不联网、不装任何包。用自己造的小集合，是为了让每个结果都能心算复现。
2. `OLD_ANSWER` 是那个「模型桩」：一个常量，代表固化在参数里、不会随材料变化的旧数额。它演示的是改权重这条路若不重新训练，问法怎么换都只会吐同一个旧答案。
3. `bigrams` 把连续的汉字两两成词，当作最朴素的词项。真实系统会有专门的分词器，这里只求说明「怎么算相干」，不追求分词质量。
4. `stuff_all` 把四段全拼起来；`retrieve` 则先数每段与问题共用了多少词项，取最多的那一段。注意「先选片段、再拼输入」这两步的先后，它就是检索这件事的骨架；返回的是一个片段加一个来源，天然可以标注出处。
5. `if __name__ == '__main__':` 里五条断言分别验证：检索带进去的文本更短、命中现行标准、参数桩停在旧口径、命中片段与主题一致、塞全部时每段都在。跑完打印通过项数。

自己动手改一改会更直观：把第一段里的 `600` 改成 `700`，全量法与检索法都会跟着变，而 `a_old` 纹丝不动——这就是「材料可更新」与「参数不可更新」的分界。把 `DOCS` 扩到四十段，检索法带进去的长度几乎不变，全量法的长度却一路涨，长材料挤占窗口的现象不用解释就能看见。这些结论都出自这份代码构造的场景，可复现，不依赖任何外部数据。

## 踩过的坑

- **把答不准一律归给模型**：现象是反复换更大的模型、不停改提示词，答案依旧错 → 原因是证据根本没被取回，模型只能拿参数里的旧知识补 → 怎么改：先把这一轮递进去的片段打印出来，确认里面有答案，再谈生成侧。
- **拿相似度当正确性**：现象是「支持退货」和「不支持退货」都排得很靠前，答案挑了错的那句 → 原因是语义相近不等于与任务相关 → 怎么改：把出处、版本、生效时间当硬条件带进筛选，别让一个分数独自决定用哪段。
- **材料少也硬搭一整套**：现象是三五页固定文档却建了目录、写了召回、配了重排，维护量远超收益 → 原因是没先算这笔账 → 怎么改：用「变不变、要不要出处、离窗口多远」三条判一次，不够就直接塞。
- **用继续训练去记会变的事实**：现象是政策一改答案立刻过期，且拿不出依据 → 原因是知识固化在训练那一刻，无法按条更新 → 怎么改：会变、要出处的内容一律走检索，训练只用来调行为与格式。
- **全量塞进提示词还以为能溯源**：现象是被问「第几页写的」时只能把答案重说一遍 → 原因是拼接时丢掉了片段边界与编号 → 怎么改：至少保留片段编号，让答案能标回具体某段。

## 三句话

RAG 是先把材料整理成可查目录、再按问题取回片段、让模型照着片段作答的一种知识注入方式。
关键做法是先按「变化频率、溯源要求、体积」决定用哪种放法，取回片段时连编号一起递过去。
当材料很少、长期不变、也不要求出处时，直接塞进提示词比搭一整套检索更划算。
