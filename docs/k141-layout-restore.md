# 版面还原、表格原子化与去重

## 场景提问

你把一批带表格的资料接进检索，想让用户能问「去年各季度营收分别是多少」。可用户一问，答案就串了：把「同比」那一列当成营收报了出来，或者把第二季度的数字安到了第一季度头上。你打开入库前的文本一看才明白——原来那份表格转成纯文本后，早已不是一张表了：标题行孤零零挂在前面，几列数字挤成一长串，中间还夹着「第 1 页」这样的页脚，跨页的地方同一张表被截成了两截。更要命的是，同一份资料因为抓取了两遍，库里躺着两份几乎一模一样的内容，检索时两份一起冒出来，把本来就不宽裕的位置占了双倍。明明原文排版清清楚楚，怎么变成文本就全乱了？

## 破误解

**不是检索模型看不懂表格，是你在「文档变文本」那一步就把表格赖以成立的行列关系弄丢了，后面怎么切都补不回来。**

先把「版面」这个词说清：一份文档摆在眼前时，文字不只是先后顺序，还带着位置——哪几个字在同一行、哪几格属于同一列、哪块是表头、哪块是页脚、这一页和下一页是不是同一张表的延续。这些位置关系就是版面。PDF（Portable Document Format，一种固定排版的文件格式）、网页、扫描件在转成纯文本时，如果只按「从上到下、从左到右读一遍」的顺序把字倒出来，位置信息就被压扁成一维的字串：表格的行列对应没了，多栏内容左右串味，页眉页脚混进正文。这一步属于 [文档清洗](./k053-doc-cleaning.md) 要管的事，而它一旦做糙，后面无论用 [固定分块](./k054-fixed-chunking.md) 还是 [语义分块](./k055-semantic-chunking.md)，切出来的块都是错的——因为分块是在已经压扁的字串上动刀，切得再巧也拼不回原来哪格归哪列。

于是要做三件事，顺序不能乱。第一件是版面还原：把抽取时带出来的坐标（行号、列号、页码、区块标记）重新用起来，把散落的单元格按行列拼回一张二维表，顺手把页眉页脚、页码这类不属于正文的行挑出去。第二件是表格原子化：把「表头」和「每一行数据」绑成一个块（chunk，切分后用于检索的最小单元），让每一行都自带列名，比如「季度=q1 | 营收=120 | 同比=+8%」。这里的「原子」是白话里「不可再拆」的意思——绝不能按固定字数把一行拦腰切断，否则「120」这个数字脱离了「营收」这个列名，就成了一个没有含义的孤立数字。第三件是去重：把内容相同的重复块挑出来只留一份，判断依据不是肉眼看着像，而是先规范化（去掉多余空白、统一大小写等），再算一个内容指纹（把一段文本映射成定长短串，内容相同指纹必相同），指纹相同就认为是同一块。

三件事有个共同目标：让进到索引里的每一块都「自带语境、含义完整、只出现一次」。这和 [数字完整性](./k124-number-integrity.md) 里「数字不能脱离它的说明」是同一条原则，也直接关系到检索回来之后能不能 [引用与拒答](./k062-citation-abstain.md) 说得清出处。

## 生活类比

把它想成整理一摞被撕碎又复印过的账本。有人把一张记着各季度收支的账页剪成了许多小纸片，还把好几张纸片复印了一遍混进来，页脚上「第 1 页」的小纸条也夹在其中。你的活儿是把它们还原成能看懂、能对账、且不重复的一叠卡片。

对应关系很具体：先把纸片按原来的行和列摆回桌面，认出最上面那行是「季度、营收、同比」的表头——这是版面还原；接着不把账页再剪碎，而是把「表头 + 一行数据」一起塑封成一张卡片，每张卡片自己就写清了「哪个季度的营收是多少」，随便抽一张都能读懂——这是表格原子化；最后把那几张复印出来的、内容一模一样的卡片挑出来扔掉，只留原件——这是去重。注意塑封这一步的要害：如果为了省纸把一张卡片从中间剪开，一半写着「120」、另一半写着「营收」，两半分开后就谁也说不清 120 到底是营收还是同比了。

这个比喻还点出两个容易被忽略的细节。其一，「第 1 页」那张小纸条本身不是账目，若不当噪声挑掉，会被误当成一行数据塑封进卡片，问起来就冒出一句莫名其妙的「营收=第 1 页」。其二，去重不能光看「长得像」：账本里完全可能真有两行数据一模一样（两个季度营收恰好相同），它们来自不同位置、是两条真实记录，不能因为是复印机误判成重复就删掉一张——所以判断重复的指纹里，除了内容，还得带上它来自第几页哪一格这类来源信息，见 [分块元数据](./k056-chunk-metadata.md)。

## 自绘示意图

:::figure 一份文档变成可检索块的顺序
@flow
解析出单元格|按坐标还原行|剔页眉页脚|表头绑数据行|规范化去重
:::

五格是严格串起来的，前三格属于版面还原，第四格是表格原子化，第五格是去重。最容易被跳过的是「按坐标还原行」：很多链路图省事，拿到纯文本直接就切块，行列对应在这一步已经丢了，后面再怎么补都只是猜。而「表头绑数据行」必须发生在切块之前，因为一旦先按字数切碎，表头和数据就再难配回一对。

:::figure 版面里必须保住的三样东西
@stack
行列对应::哪个数值属于哪一列，靠表头才读得懂
跨页接续::一张表分到两页时别当成两张表
来源坐标::块来自第几页哪一格，供引用与去重
:::

三格里最容易被漏掉的是「跨页接续」。一张长表常被拆到两页，第二页往往只重复一行表头、没有重新交代上下文；若不把两页认成同一张表，检索时就会把后半截当成一份没头没尾的孤立数据。而「来源坐标」既是引用时能说清出处的依据，也是去重时区分「真重复」和「真巧合」的关键。

:::figure 两种切法的差别
@compare
按字数硬切::表头与数值分家|数字失去列名|同一格被切两半
先还原再原子化::每行自带表头|数值含义完整|重复块能识别
:::

左边是在压扁后的字串上按长度动刀，切得均匀却把语义切散了；右边是先把行列关系拼回去、再让每一行连着表头一起成为一个块。二者的差距不在块的大小，而在块里有没有把「这个数字是什么」一起带上。

## 层层追问

:::ask 那如果把整张表格改写成一句自然语言，比如「一季度营收 120，同比增长 8%」，不是比拼坐标更省事吗？
:::

听起来省事，却把最容易出错的一环交给了「改写」。改写意味着要有人或某个模型重新读一遍表格、再把每个格子翻译成句子，这中间可能读错行列、看错小数点和百分号、把「同比 +8%」写成「增长到 8%」，一旦写错，索引里的错值就再也变不回来，而检索根本不知道它错了。更根本的问题是，原样保留「季度、营收、同比」这三列，用户才能精确地只问「同比那一列」；压成一句话之后，列与列的边界消失了，想按某一列筛、想核对某个格子都无从下手，见 [元数据过滤](./k060-metadata-filter.md)。所以稳妥的分工是：结构与数值用确定性代码原样保留（坐标拼回、单元格原值搬运），只把「怎么组织、怎么回答」留给模型，这和 [数字完整性](./k124-number-integrity.md) 讲的是同一套分工。

再往下一层：那如果表格特别大、一整张表根本放不进一个块呢？这时仍不该回头去按字数硬切，而应「按行或按区块原子化」——把大表拆成若干个行组，每组都复制一份表头跟着走，再在块的元数据里记下它属于第几张表、第几到第几行、来自哪一页。这样每一块依旧自带列名、含义完整，只是粒度从「一行」放宽到「一片连续行」。跨页那张表就靠这份来源信息在 [索引与查询两阶段](./k052-index-query-two-stage.md) 里被认成同一张表的不同片段。

:::ask 那如果去重时不小心把两行「长得一模一样」的真实数据当成重复删掉了呢？
:::

这一问正好戳到去重最危险的地方：只按「文本内容」算指纹，会把「内容巧合相同」误判成「同一内容被抓了两遍」。账本里两个季度营收都是 120、同比都是 +8%，是两条各有其位的真记录，若被当成重复删掉一条，等于静悄悄改了原文的事实。改法是给指纹加上来源维度：把「它来自哪份文件、第几页、表格里的第几行」一并拼进被规范化的内容里再算指纹，于是「同一来源被抓两遍」因为来源和内容都相同而合并，「不同位置恰好同值」因为来源不同而各自保留。换句话说，去重要区分「重复抓取」和「数据巧合」这两件完全不同的事。

再往下一层：那同一份资料被先后更新过、新旧两版内容差了几个数字，又该怎么去重？这时不能靠「内容完全相同」来判，得靠版本与更新时间：旧版不该和新版并列留在索引里供检索，否则用户会同时搜到两个互相矛盾的营收值。做法是在块的元数据里带上文档版本或抓取批次，索引更新时用新版顶掉同源的旧块，而不是简单累加，见 [索引更新](./k063-index-update.md)。一句话：去重先想清「什么叫同一块」，再决定指纹该由哪些字段拼成；把来源、版本这类字段早一点记进 [分块元数据](./k056-chunk-metadata.md)，后面才不会把真数据误删、把旧数据留着。若想看清这类字段最终怎么被评测发现，可对照 [结构化状态](./k046-structured-state.md)。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，把「按坐标还原表格—剔除页脚—表头绑定数据行成原子块—规范化后按指纹去重」完整演示一遍，结尾用一组断言逐条验证。所有单元格都是手工构造的定值，还原与去重结果可以逐格手算、完全可复现；复制到任意装有 Python 的机器上直接运行即可，不需要任何第三方包、账号或网络。它演示的是这三件事的性质，不是任何真实文档解析组件的实现。

```python
import hashlib
import json


def restore_layout(cells):
    """按 (行, 列, 文本) 坐标把乱序单元格拼回一张二维表。"""
    if not cells:
        return []
    max_row = max(c[0] for c in cells)
    max_col = max(c[1] for c in cells)
    grid = [["" for _ in range(max_col + 1)] for _ in range(max_row + 1)]
    for r, c, text in cells:
        grid[r][c] = text.strip()
    return grid


def drop_boilerplate(grid):
    """剔除页眉页脚：数据行首列须是季度编号（以 q 开头），表头单独保留。"""
    if not grid:
        return []
    kept = [grid[0]]
    for row in grid[1:]:
        if row and row[0].lower().startswith("q"):
            kept.append(row)
    return kept


def atomize(grid):
    """表格原子化：表头 + 每行拼成一个自带列名的块，不再按字数切。"""
    header = grid[0]
    atoms = []
    for row in grid[1:]:
        pairs = ["%s=%s" % (h, v) for h, v in zip(header, row)]
        atoms.append(" | ".join(pairs))
    return atoms


def normalize(text):
    """规范化：去掉全部空白、统一小写，供去重比较。"""
    return "".join(text.split()).lower()


def fingerprint(text):
    """内容指纹：规范化后取定长摘要，内容相同指纹必相同。"""
    return hashlib.sha1(normalize(text).encode("utf-8")).hexdigest()


def dedup(atoms):
    """按指纹去重，保留第一次出现的块，返回保留结果与被删条数。"""
    seen = set()
    kept = []
    for a in atoms:
        fp = fingerprint(a)
        if fp in seen:
            continue
        seen.add(fp)
        kept.append(a)
    return kept, len(atoms) - len(kept)


def main():
    # 模拟版面抽取：单元格顺序被打乱，还夹了一行页脚噪声
    cells = [
        (2, 1, "135"), (0, 0, "季度"), (1, 2, "+8%"),
        (0, 2, "同比"), (2, 0, "q2"), (1, 0, "q1"),
        (0, 1, "营收"), (2, 2, "+12%"), (1, 1, "120"),
        (3, 1, "第 1 页"),
    ]
    grid = restore_layout(cells)
    checks = [
        ("按坐标还原出 4 行", len(grid) == 4),
        ("乱序单元格归位到表头", grid[0] == ["季度", "营收", "同比"]),
        ("q1 行数值归位", grid[1] == ["q1", "120", "+8%"]),
        ("页脚被识别为单独一行", grid[3][1] == "第 1 页"),
    ]
    clean = drop_boilerplate(grid)
    checks.append(("页脚行被剔除", len(clean) == 3))
    checks.append(("表头仍保留在首位", clean[0] == ["季度", "营收", "同比"]))
    atoms = atomize(clean)
    checks.append(("原子块数量等于数据行", len(atoms) == 2))
    checks.append(("原子自带列名", "营收=" in atoms[0] and "同比=" in atoms[0]))
    checks.append(("原子不丢数值", "120" in atoms[0] and "+8%" in atoms[0]))
    checks.append(("表头不混进数据原子", "季度=季度" not in "".join(atoms)))

    # 模拟重复抓取：同一张表又来一份，空白与大小写不同
    dup_cells = [(r, c, "  " + t.upper() + " ") for r, c, t in cells]
    dup_grid = drop_boilerplate(restore_layout(dup_cells))
    dup_atoms = atomize(dup_grid)
    checks.append(("重复抓取也得到 2 块", len(dup_atoms) == 2))
    checks.append(("规范化抹平空白与大小写",
                   normalize(atoms[0]) == normalize(dup_atoms[0])))
    checks.append(("两份内容指纹一致",
                   fingerprint(atoms[0]) == fingerprint(dup_atoms[0])))

    merged = atoms + dup_atoms
    kept, removed = dedup(merged)
    checks.append(("合并后共 4 块", len(merged) == 4))
    checks.append(("去重后只剩 2 块", len(kept) == 2))
    checks.append(("去重恰好删掉 2 条", removed == 2))
    checks.append(("保留的是首份", kept[0] == atoms[0]))
    checks.append(("不同数据行指纹不同",
                   fingerprint(atoms[0]) != fingerprint(atoms[1])))
    checks.append(("原子可序列化留存",
                   len(json.dumps(kept, ensure_ascii=False)) > 0))

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `restore_layout` 是版面还原：先由所有坐标求出最大行号、最大列号，建一张填满空串的二维 `grid`，再按每个单元格的 `(r, c)` 把文本 `strip()` 后放回对应格子。注意输入的 `cells` 顺序是特意打乱的，正是要证明「靠坐标归位」不依赖抽取时的先后；`(3, 1, "第 1 页")` 那行页脚也照实落进网格，留到下一步处理。
2. `drop_boilerplate` 剔除页眉页脚：表头 `grid[0]` 无条件保留，其余行只留首列以 `q` 开头的（这里用季度编号 `q1`、`q2` 作可手算的判据）。于是页脚那行首列是空串，就被挡掉了。真实系统里这个判据会换成版面区块标记，但「先认清哪行不是正文」这一步不能省。
3. `atomize` 是表格原子化：取第一行为 `header`，对后面每一行用 `zip(header, row)` 把列名和数值逐一配成 `列名=值`，用 ` | ` 连成一整块。关键在它一次产出「一整行」，从不按字数把一个块再切小——`120` 和 `营收=` 始终待在同一块里，数值不脱离列名。
4. `normalize` 做规范化：`"".join(text.split())` 去掉所有空白，`.lower()` 统一大小写；`fingerprint` 再用 `hashlib.sha1`（SHA-1，Secure Hash Algorithm 1，一种把任意文本映射成定长摘要的算法）算出内容指纹。两份内容只在空白和大小写上不同，规范化后指纹必然相同。`json`（JavaScript Object Notation，一种纯文本的数据表示格式）只在最后量一下可序列化性。
5. `dedup` 按指纹去重：`seen` 集合记住已出现的指纹，重复的直接跳过，保留第一次出现的块，并返回被删条数。它是确定性的，所以「保留首份」这条性质可以断言。
6. `main` 第一组断言验证还原：乱序单元格归位成正确的三列表、`q1` 行数值没串列、页脚被识别成单独一行再剔除、表头仍在首位。第二组验证原子化：块数等于数据行数、每块自带 `营收=` 与 `同比=` 列名、数值不丢、表头不会混进数据块。
7. 第三组构造「重复抓取」：`dup_cells` 把每个文本加上前后空格并转成大写，模拟同一张表被抓了两遍却格式略有差异；断言规范化后两份指纹一致。最后合并去重，断言合并 4 块、去重后剩 2 块、恰好删 2 条、保留的是首份、不同数据行指纹不同、结果可序列化。结尾 `passed` 统计通过项、逐条打印，再用 `assert` 保证任何一条性质被破坏都会以非零状态退出。

有一处要如实说明：这里用「首列以 q 开头」代替了真实的版面区块识别、用手工构造的九个单元格代替了真实 PDF 的抽取结果、用大小写和空白差异代替了真实抓取抖动，全是为了让整条链路不需要联网、账号或第三方包就能独立跑通并逐格手算。它演示的是「按坐标还原、表头随行、规范化去重」这几条性质，也刻意把「两行恰好同值」留成了不同指纹（`q1` 与 `q2` 不同），借以说明真实场景里指纹还应带上来源坐标；代码本身经过逐行静态复核到「复制即跑、逻辑自洽」，并未在此环境里实际启动执行。

## 踩坑与边界

- **拿到纯文本就直接切块**：现象是行列对应全丢，问「同比」答成「营收」 → 原因是在压扁后的字串上动刀，位置关系早已不在 → 先用坐标把单元格拼回二维表再切，见 [文档清洗](./k053-doc-cleaning.md) 与 [固定分块](./k054-fixed-chunking.md)。
- **按固定字数把表格拦腰切断**：现象是「120」脱离「营收」成了没含义的孤立数字 → 原因是把表格当普通段落切 → 表头与数据行绑成一个原子块，见 [数字完整性](./k124-number-integrity.md)。
- **页眉页脚混进正文**：现象是答案里冒出「营收=第 1 页」之类莫名其妙的内容 → 原因是抽取时没把版面噪声挑出去 → 还原阶段识别并剔除非正文行，见 [语义分块](./k055-semantic-chunking.md)。
- **只按文本内容去重**：现象是两行恰好同值的真实记录被当成重复删掉，等于悄悄改了原文 → 原因是指纹没带来源维度 → 把文件、页码、行号一并拼进被规范化的内容再算指纹，见 [分块元数据](./k056-chunk-metadata.md) 与 [索引更新](./k063-index-update.md)。
- **跨页表被当成两张表**：现象是后半截数据没有表头，检索回来读不懂 → 原因是没记录「同属一张表」的来源信息 → 每块带表头副本与来源坐标，见 [索引与查询两阶段](./k052-index-query-two-stage.md)。

还要说清一条边界：这套做法不是所有文档都需要。如果资料本来就是一段段通顺的文字、根本没有表格和多栏，老老实实按语义分块就好，硬去还原版面反而把简单事做复杂了；它真正值钱的地方，是内容靠「位置」才读得懂的时候——表格、表单、账单、多栏排版的说明书。另外，原子块里那份「表头副本」要随块一起存，不能只在内存里临时拼一下就丢，否则检索回来又成了光秃秃的数值；这一点可对照 [引用与拒答](./k062-citation-abstain.md) 里「答案要能说清出处」的要求。若想从整体上看检索这一步在整个链路里的位置，可对照 [为什么需要检索增强](./k051-why-rag.md)。

## 三句话小结

版面还原、表格原子化与去重，是把被压扁成一维字串的表格按坐标拼回二维、把表头和每行数据绑成不可再拆的块、再按带来源的内容指纹去掉重复的三步整理。

关键做法是结构与数值用确定性代码原样保留、每行自带列名且表头副本随块存、页眉页脚先剔除、去重的指纹要带来源与版本而不只看内容。

当资料本来就是没有表格、没有多栏的通顺文字时，不必硬套版面还原；但只要内容要靠位置才读得懂，就别在行列关系还没拼回去之前急着切块。
