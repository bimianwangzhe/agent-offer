# 文档解析与清洗：别让脏数据一路混进答案

## 答案里冒出一句「内部制度手册 2024 版」

你搭的知识库回答报销问题时，末尾冷不丁带出一句「第 3 页 内部制度手册 2024 版」，用户一脸茫然。你回头翻原文才发现，每页页眉页脚都被当成正文召回了；还有几段是扫描件识别出来的乱码，方方块块的替换符混在句子中间。更棘手的是，你好不容易写了个清洗脚本把「看着像噪声」的行全删了，结果连「超标部分一律不予报销」这种要紧的警示语也一起没了。

## 先破一个误解

**不是检索算错了分数，是进索引之前的文本就已经脏了，后面全是在噪声里找答案。**

先把两个词分开。解析（parsing）指把文件还原成带结构的文本：标题是哪一级、哪几行属于同一段、表格的行列怎么对齐、阅读顺序是先左栏还是先右栏。清洗（cleaning）指在这份结构化文本上，去掉页眉页脚、导航栏、水印、版权声明、替换符乱码、多余空白，并把编码统一成一种。两者常常被笼统叫「预处理」，但顺序不能反：先还原结构，才知道「第 3 页 内部制度手册」是每页重复的页眉，而不是正文里一句正经话。

为什么脏数据危害这么大？因为检索链路是一路往下游传的：清洗没去掉的东西会占掉切分后的片段名额，会进索引、会被召回、会被拼进上下文、最后可能被模型当成事实写进答案。页眉页脚尤其讨厌，它们在几十页里反复出现，词项统计上显得「很常见」，很容易挤进候选；扫描识别出来的乱码则是纯粹的噪声，既不承载语义又占长度。反过来，清洗过头同样致命：警示语、表头、单位、否定词这些恰恰是答案的限定条件，一旦被当成「格式噪声」删掉，剩下的就是一句没有边界的干净错话。所以清洗的判据不是「看着整齐」，而是「留下的每一句能不能独立表意、删掉的每一句是不是真的无语义」。

版面结构更复杂的表格、分栏、识别内容，需要专门按原子块处理，见[版面还原、表格原子化与去重](./k141-layout-restore.md)；清洗完接着要决定怎么切成片段，见[固定长度切分与重叠](./k054-fixed-chunking.md)。整套材料的顺序可以从[从这里开始](./00-start-here.md)看起。

## 用整理一份旧档案来理解

把一批待入库的文件想成从库房翻出来的一摞旧档案，你要先整理成能给人查阅的抄本。

第一件事是「还原」：把装订顺序理顺，分清哪几页是正文、哪一页是封面目录，把左右分栏的两列文字按各自的意思接起来，别把左栏的半句和右栏的半句拼成一句。这一步就像把散乱的纸页按原样摆好，还不急着扔东西。第二件事才是「清理」：撕掉每页都盖着的登记章、去掉页边的页码与装订码、把复印时蹭上的黑块擦掉、把模糊到认不出的字标出来另行处理。第三件事是「核对」：把「注意」「不得」「仅限」这类带约束的句子单独看一眼，确认没被当成格式碎屑扫掉。

对应关系：登记章与页码是页眉页脚，黑块是水印与装饰线，认不出的字是替换符乱码，装订顺序是阅读顺序，带约束的句子是警示语与表头单位。这个比喻点出了最容易犯的错——很多人一上来就「擦」，结果把两栏文字交错着抄成了一锅粥，或者把「仅限一线城市」这种关键限定当页边小字抹了。整理档案的规矩是先摆正再动手擦，而且擦完要回头核对那些「看着像杂物、其实是内容」的部分。

:::quote
清洗不是把文本变漂亮，是让留下的每一句都能独立表意。删错一句限定条件，比留着一行页眉危险得多。
:::

## 把清洗前后画出来

先看一份文件从进来到能切分，中间经过哪几道处理。

:::figure 从原始文件到可切分的干净文本
@flow
文件读入|版面还原|逐行清洗|结构核对|导出片段
:::

五个节点里，「版面还原」必须排在「逐行清洗」前面；顺序一颠倒，分栏与表格就会在还没认清结构时被按行切碎。

清洗时该留该删，可以列成一张对照清单：

:::figure 清洗时的三类判断
@stack
必删::每页重复的页眉页脚、导航、水印、版权声明
标出::认不出的替换符乱码，单独登记再决定补录
必留::标题层级、表头、单位、否定与警示语
复核::清完随机抽页，比对原文确认没删掉限定条件
:::

第三行是这份清单里最该拿红笔圈住的：表头决定一列数字是什么含义，「不予」「仅限」「超标」决定一句话的适用边界，它们长得都不像正文，却全是正文。

再看两种清洗取向的差别：

:::figure 一刀切清洗，与按结构清洗
@compare
一刀切删噪声::看着整齐|警示语容易被误删|表格被拆散
按结构还原::层级保留|限定条件不动|脏行逐类判定
:::

第二行的「逐类判定」是要点：页眉有页眉的判据（跨页重复、位置固定），乱码有乱码的判据（出现替换符、不可读），表格有表格的判据（成行成列）。用一条「非中文字符太多就删」的规则去套所有行，必然误伤型号、单位和金额。

:::tip 一条立刻见效的规则
清洗脚本一定要留一份「删了什么」的清单，并随机抽几页与原文比对。看不到删了什么，你就永远不知道答案里缺的那句限定条件是不是被自己清掉的。
:::

## 再往深问两层

:::ask 那如果文件是纯文本、没有页眉页脚，是不是就不用清洗了？
:::

还是有得做，只是重点变了。纯文本没有版面还原的负担，但仍有编码不一致、多余空行、行尾空格、从别处粘过来的导航条、以及同一份制度被复制了三份这类问题。尤其「同一段文字出现多次」会让切分后的候选里挤满近似重复的块，把真正有用的片段挤出名额，这属于去重而不是逐行清洗，见[版面还原、表格原子化与去重](./k141-layout-restore.md)。另外别小看「统一成一种中间格式」这件事：把标题层级、段落、表格都规整成同一种带标记的文本，后面的切分器、索引器、溯源展示才能共用一套假设，否则每个环节都要各自猜一遍结构。

:::ask 再深一层：怎么判断一句「看着像噪声」的话到底该不该留？
:::

别靠肉眼和正则长度，靠「它对答案有没有约束作用」。给每一类疑似噪声问三个问题：它是不是跨页重复（是 → 多半是页眉页脚）；它删掉之后，剩下的句子意思会不会变松、变宽（会 → 它是限定条件，必须留）；它是不是某张表、某段代码的组成部分（是 → 按原子块整体保留，不按行处理）。第三问最容易被忽略：表格里单独一行「| 600 | 800 |」确实看不出含义，但它不是噪声，是缺了表头的数据行，正确做法是把表头复制给它，而不是把它删掉。把这三个问题写进清洗规则，再配一组「删了什么」的回归断言，比凭感觉调正则稳得多。清洗做歪了，后面[切分元数据与父块回溯](./k056-chunk-metadata.md)里那些来源与页码也会跟着错位，溯源就无从谈起。

## 一份能跑的对照

下面这段只用标准库，构造一份带页眉页脚、导航、空行、替换符乱码的小原文，写一份按结构判定的清洗函数，再用断言逐条验证「该删的删了、该留的一句没少」。

```python
# clean_doc.py —— 只用标准库，python clean_doc.py
import re

RAW_LINES = [
    "第 3 页        内部制度手册        2024 版",
    "首页 | 目录 | 上一页 | 下一页",
    "",
    "第三章  差旅与报销",
    "",
    "3.1  住宿标准",
    "一线城市每晚 600 元，其他城市每晚 400 元。",
    "注意：超标部分一律不予报销。",
    "",
    "\ufffd\ufffd 扫描识别乱码",
    "第 3 页        内部制度手册        2024 版",
]


def is_noise(line):
    # 按类别判定，而不是「看着乱就删」
    if "第" in line and "页" in line and "内部制度手册" in line:
        return True                       # 跨页重复的页眉页脚
    if line.startswith("首页 |"):
        return True                       # 导航栏
    if "\ufffd" in line:
        return True                       # 替换符乱码
    return False


def clean(lines):
    out = []
    for raw in lines:
        if is_noise(raw):
            continue
        line = re.sub(r"[ \t]+", " ", raw).strip()   # 规整空白
        if not line:
            continue                                  # 丢空行
        out.append(line)
    return "\n".join(out)


if __name__ == '__main__':
    text = clean(RAW_LINES)
    assert "内部制度手册" not in text                # 页眉页脚被清掉
    assert "首页 |" not in text                      # 导航被清掉
    assert "\ufffd" not in text                      # 乱码被清掉
    assert "每晚 600 元" in text                     # 正文留下
    assert "注意：超标部分一律不予报销" in text      # 警示语不能误删
    assert "第三章" in text and "3.1" in text         # 标题层级保留
    assert text.count("每晚") == 2                   # 单位与数值成对保留
    print("通过 7/7 项：噪声逐类清除，正文、标题、警示语与单位保留")
```

1. `RAW_LINES` 是本地构造的一份「脏原文」，页眉页脚出现两次（模拟跨页重复），中间夹着空行、导航条、带替换符 `\ufffd` 的识别乱码，以及一句带「不予」的警示语。
2. `is_noise` 是这份脚本的关键：它按类别判定，每类一条明确理由，而不是用一个「非中文字符占比」之类的模糊规则去套所有行。这也让以后加一类噪声时，只需加一条判据，不影响已有的。
3. `clean` 先用 `re.sub` 把连续空格与制表符压成一个空格、去掉行首尾空白，再丢掉空行。注意规整空白放在「判噪声」之后：页眉那行原样判更容易命中，压完反而可能变形。
4. 六类断言里，前三条验证「该删的删了」，后四条验证「该留的一句没少」——包括标题层级、警示语、以及「每晚」出现两次（说明数值和单位都在，没有被当成格式碎屑切掉）。
5. `if __name__ == '__main__':` 跑完打印通过项数。整套逻辑不读磁盘、不联网、不需要识别服务，替换符是直接用字符写进样例的。

想看得更直观，可以把 `is_noise` 里那条「含内部制度手册」的判据去掉，会看到页眉重新混进结果；或者把警示语那行也加进噪声规则，会看到第 5 条断言立刻失败——它正好演示了「一刀切」为什么危险。真实文件里的页眉形态远比这里多，判断逻辑要按实际版式扩充，但「逐类判定 + 删了什么要留痕 + 抽页复核」这套结构不用变。

## 踩过的坑

- **逐行读取毁掉分栏**：现象是左右两栏的半句被交错拼成一句，答案读不通 → 原因是没做版面还原就按物理行清洗 → 怎么改：先按栏分组还原阅读顺序，再进入逐行清洗。
- **过度清洗删掉限定条件**：现象是「超标不予报销」这类话消失，答案变成没有边界的宽泛陈述 → 原因是用模糊规则把带「注意」「仅限」的短行当噪声 → 怎么改：把警示语、表头、单位、否定词列入必留清单，并写回归断言守住。
- **表格与代码被按长度切断**：现象是召回的数据行只剩「600 800」，不知道是哪两列 → 原因是用固定长度切分处理表格 → 怎么改：表格按原子块整体保留，长表按行拆时每个子块复制表头。
- **编码与替换符不处理**：现象是索引里混进方块乱码，占长度又不出语义 → 原因是识别结果直接进链路，没做替换符登记 → 怎么改：统一编码，出现替换符的行单独标出，另走补录或人工核对。
- **清洗不留痕**：现象是答案变差却查不出少了哪句 → 原因是清洗静默发生，没有记录删了什么 → 怎么改：每份文件输出一份删除清单，随机抽页与原文比对。

## 三句话

文档解析与清洗，是先把文件还原成带层级与阅读顺序的文本，再逐类去掉页眉页脚、导航与乱码的过程。
关键做法是按结构逐类判定、把警示语表头单位列入必留，并留下删除清单做抽页复核。
当材料本来就是干净的纯文本、且没有重复页眉时，只做空白规整与去重即可，不必套一整套版面还原。
