# 15 分钟讲项目的节奏

给你 15 分钟讲一个做过的项目，你打算从第一行代码怎么搭开始，按时间顺序一路讲到收尾。结果讲了十分钟还在说环境怎么配、某个参数怎么调，架构刚开了个头，对方抬手看表：「直接说你做了哪些决定吧。」你慌忙跳到结果，评测怎么测的、出过什么故障、后来改了什么，全没来得及说。

**不是内容不够，是没给这 15 分钟排节奏，让「按时间顺序」替你做了分配。** 讲述顺序不等于做事顺序。听的人要的是决策链，不是流水账；哪一段讲多久、讲到哪里必须收口转下一段，得在开口之前就定好，并且练过。

先把词说清。复盘（retrospective）指事情做完之后回头看：哪里判断错了、后来改了什么、下次会怎么定。交接句指一段讲完时那句预先写好的转场话，用来提醒自己别拖堂。评测（evaluation）指用一批用例批量跑、按指标打分判版本好坏的做法。故障（incident）指运行里出现过的一次具体不对劲，以及怎么定位到哪一步。智能体（Agent）是能自己决定下一步并调用工具的程序。断言（assertion）是程序里一条「必须成立」的检查。这些词先立住，后面排四段时间时才不会把「讲评测」讲成「报数字」。

## 一、生活类比：导游带一条固定路线

想象一位导游带 15 分钟的短途讲解，路线是事先踩过点的：先三分钟站在门口说清这地方为什么这么建、当时受什么限制；再五分钟进到主厅，指着结构讲「为什么用了这套梁柱、没用另一种更省事的做法」；接着五分钟到展柜前，讲当年哪次验收没过、后来怎么查出来的；最后两分钟回到门口，说这次讲解如果重来会怎么调整。每个点讲完，他都用一句固定的话收口：「限制说完了，进去看结构。」

对应关系是：四个参观点对应四段内容，每点的分钟数对应时间预算，那句固定收口对应交接句，「事先踩过点」对应预先练过节奏。**导游不会在门口把 15 分钟全花掉，也不会临时决定先去哪个点；因为他知道听的人要在离开前把四件事都装走。** 讲项目同样：对方要在你停下之前听到约束、取舍、评测与故障、复盘，缺一段，这件作品就少一面。

## 二、四段怎么分才不拖堂

把 15 分钟切成四段：背景与约束三分、架构与关键取舍五分、评测与故障五分、复盘两分。前两段讲「在什么限制下做了什么决定」，后两段讲「怎么知道没选错、出过什么事、后来改了什么」。权重不是随便给的：架构与取舍是对方最想追的部分，评测与故障是证明你真跑过的部分，所以各给五分钟；背景要快，复盘要短，别在这两头把时间吃掉。

:::figure 四段时间预算与各自要交付什么
@stack
背景与约束 三分::说清限制与不碰什么，别铺环境细节
架构与取舍 五分::状态放哪、消息怎么走、没选哪条路
评测与故障 五分::怎么测的、一次故障怎么定位到哪步
复盘 两分::判断错在哪、后来改了什么、下次怎么定
:::

有两个细节值得先说清。第一，顺序不能换：先讲约束，取舍才有对照；先讲架构，评测才知道验的是哪个决定；故障放在评测之后，是因为它本身就是「那条决定在哪种情况下不够用」的证据。第二，每段都要有一句预先写好的交接句，比如「约束讲完了，下面看我怎么在这些限制里选架构」。没有这句话，讲得顺的时候会一直往下淌，等发现超时，后面两段已经被挤没了。三要素怎么组织成句子，见[约束、权衡与可验证结果](./k123-tradeoffs.md)；被追问时怎么一层层接住，见[四层追问链与转行者三问](./k125-followup-chain.md)。

:::ask 那如果讲到架构那段被中途打岔，时间被吃掉两分钟呢？
别从评测和故障里硬砍，优先压缩复盘。复盘是「回头看」，压到只剩一句「最想改的是哪一点」也仍能收住；评测与故障一旦砍掉，对方就失去了判断你有没有真跑过的依据。代码里 `rebalance` 演示的正是这个策略：某段超时，就把多出来的时间从复盘里扣，并重新算一遍各段起点，保证总长还是 15。**压缩要有优先级，别平均摊薄四段。**
:::

:::ask 那如果对方一路追问，根本不让我按四段讲完呢？
那就把四段当成随取随用的抽屉，而不是必须一次性放完的录音。追问落到「凭什么信」时，直接把评测与故障那一段抽出来答；落到「为什么不用更简单的做法」时，抽架构与取舍那一段。练节奏的目的不是死守时间，是让每一段都能独立成块、被点名时立刻拿得出来。**排过节奏的人，被打断也不会散；没排过的人，一被打断就只剩碎句。** 整件作品该有哪几块可讲，见[三个能写进简历的项目](./k122-three-projects.md)。
:::

:::figure 按时间顺序讲与按决策链讲
@compare
按时间顺序::先讲环境配置|十分钟还在铺陈|评测故障常没说到
按四段节奏::先讲限制与取舍|每段有交接句|四件事都留了位置
:::

左边三点是一条下坡：从最不重要的细节开头 → 时间被前面吃掉 → 最该被听的部分没位置。右边三点是一条上坡：先交付决策 → 每段有收口 → 四件事都占住了。差别不在讲得多快，在「开口前有没有把 15 分钟当成一份要分配的资源」。

## 三、把节奏写成能跑的时间表

下面的脚本零依赖、不需要账号、不需要联网。它把四段时间和交接句写成数据，检查总长、顺序、起点累加，并演示某段超时后优先压缩复盘、重算起点。所有分钟数都是本地构造的示例预算。

```python
# k126.py —— 15 分钟讲项目的节奏表（零依赖，python k126.py）
SEGMENTS = ("背景与约束", "架构与取舍", "评测与故障", "复盘")
WEIGHTS = (3, 5, 5, 2)
LINES = {
    "背景与约束": "约束讲完了，下面看我怎么在这些限制里选架构",
    "架构与取舍": "这是取舍，接下来说怎么验证它没选错",
    "评测与故障": "结果和一次故障讲完了，最后说复盘改了什么",
    "复盘": "以上就是整个项目，请提问",
}


def plan(budget=15, weights=WEIGHTS):
    slots, acc = [], 0
    for seg, minutes in zip(SEGMENTS, weights):
        slots.append({"段": seg, "分钟": minutes, "起点": acc})
        acc += minutes
    return slots


def audit(slots):
    problems = []
    if sum(s["分钟"] for s in slots) != 15:
        problems.append("总时长不是 15")
    if [s["段"] for s in slots] != list(SEGMENTS):
        problems.append("顺序被打乱")
    if any(s["分钟"] <= 0 for s in slots):
        problems.append("有段落没分到时间")
    if slots[0]["起点"] != 0:
        problems.append("起点不对")
    return problems


def rebalance(slots, overrun_seg, extra):
    """某段超时，优先压缩复盘，保证总长仍是 15。"""
    out = [dict(s) for s in slots]
    for s in out:
        if s["段"] == overrun_seg:
            s["分钟"] += extra
    for s in out:
        if s["段"] == "复盘" and s["分钟"] > extra:
            s["分钟"] -= extra
    acc = 0
    for s in out:
        s["起点"] = acc
        acc += s["分钟"]
    return out


if __name__ == "__main__":
    passed = total = 0

    def check(label, cond):
        global passed, total
        total += 1
        assert cond, label
        passed += 1
        print("  [通过] " + label)

    slots = plan()
    check("四段总长正好 15 分钟", sum(s["分钟"] for s in slots) == 15)
    check("节奏表无问题", audit(slots) == [])
    check("起点依次累加", [s["起点"] for s in slots] == [0, 3, 8, 13])
    check("每段都有预先练过的交接句", all(LINES[s["段"]] for s in slots))
    check("复盘排在最后", slots[-1]["段"] == "复盘")

    scrambled = [dict(段="复盘", 分钟=2, 起点=0),
                 dict(段="背景与约束", 分钟=3, 起点=2),
                 dict(段="架构与取舍", 分钟=5, 起点=5),
                 dict(段="评测与故障", 分钟=5, 起点=10)]
    check("顺序被打乱能被发现", "顺序被打乱" in audit(scrambled))

    fixed = rebalance(slots, "架构与取舍", 1)
    check("超时后总长仍是 15", sum(s["分钟"] for s in fixed) == 15)
    check("超时后重算起点无问题", audit(fixed) == [])
    print("通过 %d/%d 项" % (passed, total))
```

运行后打印每条断言与汇总：

```text
  [通过] 四段总长正好 15 分钟
  [通过] 节奏表无问题
  [通过] 超时后总长仍是 15
通过 8/8 项
```

逐段解释关键行在做什么：

1. `SEGMENTS` 定四段顺序，`WEIGHTS` 定各自分钟数，`LINES` 给每段配一句交接话。三者分开写，是为了改时间时不动顺序、改措辞时不动预算。
2. `plan` 用 `zip` 把段名与分钟数配对，边走边累加 `acc` 算出每段起点，返回「段 / 分钟 / 起点」三字段的列表。起点即「讲到第几分钟该进这一段」。
3. `audit` 依次检查总时长是不是 15、顺序有没有被打乱、有没有段落分到零分钟、第一段起点是不是零。返回文字问题列表，能点名哪条不对。
4. `rebalance` 先给超时段加时间，再从复盘里扣回同样的量；`s["分钟"] > extra` 这个判断保证复盘不会被扣成零或负数。随后重新累加一遍起点，避免时间表前后对不上。
5. `scrambled` 是故意打乱顺序的样例，用来验证 `audit` 真能发现「复盘被挪到最前」这类错误——这正是讲述里最容易出现的顺序事故。
6. `check` 用 `assert` 兜底，任一结论不符脚本就失败；末尾 `通过 N/N 项` 把「节奏表本身对不对」也变成可复核的一行输出。

:::tip 交接句要真的念出来
写在纸上不算练过。**每段结束就把那句话原样说一遍**，说顺了，拖堂时自己会听见；只靠心里记着「该转了」，讲嗨了照样会一路淌下去。
:::

## 四、踩坑与边界

- **按做事顺序讲**：现象是十分钟还在讲环境怎么配，架构刚开头 → 原因是把做事顺序当讲述顺序 → 怎么改：按四段重排，背景只留限制与排除项，三分钟内必须收口。
- **没有交接句**：现象是讲得顺就一直往下淌，发现超时后面两段已被挤没 → 原因是每段没有预先写好的收口 → 怎么改：给四段各配一句话，讲完原样念出来再转场。
- **平均压缩**：现象是被打岔后四段各砍一点，评测与故障被砍得最狠 → 原因是压缩没有优先级 → 怎么改：优先压复盘，保住评测与故障这两段证据。
- **复盘讲成邀功**：现象是最后两分钟变成「整体挺顺利」，等于没复盘 → 原因是没有具体错判可讲 → 怎么改：准备一条真实的判断失误，说清后来改了什么、下次怎么定。
- **超时不改表**：现象是某段多讲了，后面起点全乱，自己也不知讲到哪 → 原因是时间表没跟着重算 → 怎么改：像 `rebalance` 那样扣回时间并重算各段起点，别带着错表往下讲。

@flow
定四段预算|讲背景与约束|讲架构与取舍|讲评测与故障|复盘并交回提问

图里第一步「定四段预算」在开口之前就完成了，后面四步只是按表走；这也解释了为什么节奏必须预先练过，而不是临场靠感觉把握。四段里牵出的数字怎么站得住，见[数字口径与统计范围](./k124-number-integrity.md)；讲哪件作品、那件作品该有哪些可讲的部分，见[三个能写进简历的项目](./k122-three-projects.md)。若还想从全站入口按篇章顺序回看，可从[从这里开始](./00-start-here.md)进入。

## 五、自检清单

:::check 学完自检
- [ ] 能说出四段顺序与各自分钟数，并解释为什么这样分
- [ ] 能给每段写一句交接话，并真的念出来收口
- [ ] 知道被打岔超时时优先压复盘，而不是平均摊薄
- [ ] 能把四段当成随取随用的抽屉，被点名时立刻抽出对应那段
- [ ] 复盘里准备了一条具体错判，而不是「整体顺利」
:::

是什么：这是把 15 分钟讲述切成四段、配好交接句并预先练过的节奏安排方法。
关键做法：先定四段预算与顺序，每段用固定话收口，超时优先压缩复盘并重算起点。
什么时候不该用：对方明确要自由聊、或只针对一个细节深挖时，别硬按表推进，把对应那段抽出来答即可。
