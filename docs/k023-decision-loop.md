# 决策—行动—观察闭环

## 场景提问

你让一个会调工具的程序去核对一批订单：先查每一单的状态，再决定要不要补发提醒。跑起来却发现，它查完第一单就按「后面大概都正常」写了总结；换一批数据再试，它又把同一个查询连着发了十几次，每一次返回都明明白白写着「这条缺测」，它却像没看见一样，继续查同一条、再查同一条。你翻日志，每一步都有请求、有返回，看起来忙得很，可就是没有往目标挪动半步。明明工具也给了、目标也写了、循环也转了，为什么它既不会换招，也不会收工？

## 破误解

**不是模型不会用工具，是把「调一次工具」当成了「做完一件事」，中间少了把观察接回决策的那根线。**

先把三个词说清。决策，是「根据此刻真正看得见的信息，挑出下一步做什么」，它是一次选择，不是一段解释；行动，是把这个选择真的做出来，比如调用一次工具、改一条记录、发一条通知，行动会产生真实改变，因此有代价、也可能出错；观察，是行动之后外部世界给回来的事实，包括工具的返回值、报错、超时、空结果，它的特点是「不由程序自己说了算」。三者首尾相接才叫闭环（loop，一圈走完回到起点，但手里多了上一圈带回来的新事实）。很多初版实现只有「决策 → 行动」两截：观察被打印到日志里就算交差，从来没有进入下一轮的输入；或者观察确实塞进了输入，却被一大段固定说明和旧记录淹没，决策函数压根没有去读它。这样的程序其实是在开环（open loop）里空转——动作在重复，信息却一点没有积累，于是「查了十几次」和「查了一次」在它眼里没有区别。

这里有个很朴素、也很管用的判定办法：把上一轮的观察删掉，如果下一轮的决策完全不变，那这根线就是断的。反过来说，闭环的价值不在于「转了几圈」，而在于每一圈之后，程序对局面的认识与上一圈不同，因而下一步的选择有可能不同。还要补一句容易被忽略的：闭环不等于「一直循环」。它必须同时带着「什么算做完了」的判据和「最多转几圈」的兜底，否则只是把空转变成了无限空转，日志更长、花钱更多，问题一模一样。为什么有的系统看着像在自主干活、有的只是把固定步骤跑了一遍，分界也在这里，可对照 [工作流与 Agent 的分界](./k022-workflow-vs-agent.md) 和 [Agent 判定标准](./k021-agent-criterion.md)。

## 生活类比

把它想成厨房里给一锅汤调味。靠谱的厨师不会照着菜谱一次把盐全倒进去就端走。他会先舀一勺尝尝——这是观察，舌头告诉他「现在偏淡」；然后心里做个判断「加半勺盐，别动火」——这是决策；接着手真的把盐撒进锅里、搅两下——这是行动，锅里从此和刚才不一样了；最后再舀一勺尝——这是新的一轮观察。淡了就再补一点，刚好就关火出锅。

对应关系要一句句对上：舌头尝到的咸淡，就是工具返回的那段观察，它来自锅、不来自厨师的想象；「偏淡，加半勺」是决策，它必须针对刚才尝到的那口汤，而不是照着第一口的印象；撒盐这个动作是行动，它有不可忽略的后果，盐放多了没法假装没放；而「再尝一勺」必须尝的是**当下这锅汤**，不是把第一口的记录抄一遍。这个比喻还点出了两种最常见的翻车：一是厨师尝完把结果写在便利贴上贴到墙，手却仍按原计划一勺勺猛加盐——观察留了痕，但没接回决策，等于开环；二是厨师尝了一百次也不肯说「够了」，因为没人告诉他什么叫刚好——闭环缺了停止判据。放到程序里，前者是「只打日志不进输入」，后者是「没有完成条件与轮数上限」。还有一层：厨师判断「偏淡」得有个可判定的标准，不能全凭感觉，正如观察要能被程序读出「这是缺测、这是有效值、这是报错」，而不是一段谁也不去解析的自由文本。

## 自绘示意图

:::figure 一轮闭环的四个节点
@cycle
读取当前信息|做出决策|执行动作|收集观察
:::

这张图里最要紧的是那根回箭头：它不是让程序回到「和上一圈一模一样」的状态，而是带着刚收集到的观察回到「读取当前信息」。所以四个节点里，「收集观察」不能省，「读取当前信息」也不能只从上一次复制——两者合起来才构成「圈」。四格各自短，是为了强调它们是四种不同的职责，而不是一个动作的四个说法：把观察和决策混成一格，很容易写成「模型一边想一边就把结果编出来了」，观察就不再是外部事实。

:::figure 一轮闭环必须留下的四样痕迹
@stack
本轮输入::决策时真正看得见的信息，含上轮观察
决策理由::为什么选这个动作，用一句话记下
动作与参数::实际调了什么、传了什么值
观察原文::工具返回或报错，不改写不美化
:::

四格里最容易缺的是「本轮输入」和「观察原文」。前者决定事后能不能回答「它当时到底看见了什么才这么选」，后者决定观察是不是原样进来的——把报错改写成「一切正常」、把缺测摘要成「有数据」，闭环就从根上被污染了，后面再怎么转都是在一个假局面上做选择。这四样东西怎么存、存多久，会在 [循环状态怎么存](./k027-loop-state.md) 里展开；把它们按固定结构记下来而不是拼成一大段文字，可对照 [结构化状态](./k046-structured-state.md)。

:::figure 闭环与开环的差别
@compare
只有动作没有回接::观察只进日志|下轮决策不变|重复同一动作
观察接回决策::信息逐轮变新|能换招能收工|轨迹可复盘
:::

左边不是「没做事」，它做得挺忙，只是每一轮都不比上一轮更懂局面；右边的差别全在「下一轮的决策会不会因为这一轮的观察而不同」。顺带说清一件事：轨迹可复盘不是额外的美观要求，而是闭环能不能被检查的前提——你没法验证一根你看不见的线。

## 层层追问

:::ask 那如果观察确实接回来了，任务还是在绕圈呢？
:::

这完全正常，而且恰恰说明「接回来」只是必要、并不充分。观察进了输入，还得有地方记住「已经试过什么、离目标还差多少」，否则程序可能把「查过 A 且缺测」这件事又忘掉，下轮重新查 A，看起来读了观察，其实没把观察变成状态。所以闭环至少要配三样东西：一份可累加的状态、一条能把观察翻译成「进展 / 没进展」的判据、以及明确的收工条件。举个具体的：查到「缺测」应当记成「A 不可用，换下一个」，而不是记成「查过一次了」；查到有效值应当记成「目标达成，可以结束」。只记「发生过」而不记「意味着什么」，决策照样没依据。这一步怎么做，[循环状态怎么存](./k027-loop-state.md) 讲状态该有哪些字段，[错误如何回喂](./k029-error-feedback.md) 讲失败信息怎么变成下一轮能用的线索，[停止条件](./k028-stop-conditions.md) 讲完成判据与轮数上限怎么定。再往下一层：还要区分「没进展」和「有进展但慢」。如果每轮都在往目标靠近，只是步子小，硬设一个很小的轮数上限反而会把快要做完的任务掐断；如果连续几轮状态一模一样，那就是原地打转，该触发换招或退出。判断的依据是状态有没有变化，不是循环计数到了没有。

:::ask 那如果工具返回本身就是错的，或者压根没返回呢？
:::

这是更贴近真实环境的一问，也是「观察」这个词最容易被神化的地方。观察不等于真相，它只是外部给回来的一段信号；信号本身可能超时、可能为空、可能是「成功」字样配着一份残缺数据、也可能是下游把上次的旧值又吐了一遍。所以闭环里还得有一个「观察可不可信」的闸：拿到返回先做可判定性检查——有没有超时、结构对不对、是不是空值、和本轮动作对不对得上——然后再决定是把它当事实喂给下一轮，还是当成一次失败重新处理。特别要记住：**「没拿到观察」本身也是一种观察**。超时之后什么都没有，如果程序把「没有新信息」当成「维持原判断」，它就会安静地卡在原地，比报错更难发现；正确做法是把「未取得有效观察」明确记进状态，让下一轮去重试、换工具或者退出。这类边界在 [工具结果](./k035-tool-result.md) 与 [工具失败](./k040-tool-failure.md) 里有更细的分类；超时之后怎么和下游对账、避免「其实执行了但我以为没执行」，可对照 [超时对账](./k039-timeout-reconcile.md)；而重试为什么可能把同一个动作做了两遍，则要配合 [幂等落盘](./k107-idempotent-persist.md) 的稳标识。还有个反直觉的坑：为了「保证闭环」而无脑重试，其实又退回开环了——每次都拿同一个动作、同一种失败，观察虽然回来了，却从没改变过决策。闭环要求的是「观察改变判断」，不是「失败之后再调用一次」。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，用本地确定性桩模拟一个「按编号查读数」的外部世界，完整演示闭环与开环的差别：闭环每轮把观察交给决策函数，读到缺测就换编号、读到有效值就收工；开环故意丢掉观察，永远重复同一个动作。结尾用一组断言逐条验证「观察是否真的改变了下一轮决策」。复制到任意装有 Python 的机器上直接运行即可，不需要任何第三方包、账号或网络。

```python
from dataclasses import dataclass


@dataclass
class Step:
    """一轮闭环留下的三元组：决策、行动、观察。"""

    round_no: int
    decision: str
    action: str
    observation: str


class World:
    """本地模拟的外部环境：按编号查读数，缺测会明确说出来。"""

    def __init__(self):
        self.readings = {"A": "缺测", "B": "25度", "C": "18度"}

    def act(self, action):
        """执行一个动作并返回观察；动作形如 查:A 或 结束。"""
        kind, _, arg = action.partition(":")
        if kind == "结束":
            return "已结束"
        if kind == "查" and arg in self.readings:
            return self.readings[arg]
        return "未知动作"


CANDIDATES = ["A", "B", "C"]


def decide(history, tried):
    """只依据看得见的观察挑下一步：够好就收工，否则换没试过的编号。"""
    if history:
        last = history[-1].observation
        if last.endswith("度") and last != "缺测":
            return "结束"
    for c in CANDIDATES:
        if c not in tried:
            return "查:" + c
    return "结束"


def run_loop(world, use_observation, max_rounds=6):
    """use_observation=False 时故意丢掉观察，演示开环一直打转。"""
    history = []
    tried = []
    for i in range(1, max_rounds + 1):
        if use_observation:
            decision = decide(history, tried)
        else:
            decision = "查:A"
        action = decision
        observation = world.act(action)
        history.append(Step(i, decision, action, observation))
        key = action.split(":", 1)[1] if action.startswith("查:") else ""
        if key and key not in tried:
            tried.append(key)
        if decision == "结束":
            break
    return history


def main():
    checks = []
    closed = run_loop(World(), True)
    checks.append(("闭环在轮数上限内自行收工", len(closed) == 3))
    checks.append(("闭环最后一步是结束", closed[-1].decision == "结束"))
    checks.append(("每一步都留齐决策行动观察",
                   all(s.decision and s.action and s.observation for s in closed)))
    checks.append(("缺测那一步没有被误当成完成",
                   closed[0].observation == "缺测" and closed[0].decision != "结束"))
    checks.append(("下一轮决策确实读了上一轮观察",
                   decide(closed[:1], ["A"]) == "查:B"))
    checks.append(("观察原文留在轨迹里", closed[1].observation == "25度"))
    open_loop = run_loop(World(), False)
    checks.append(("丢掉观察的开环撞满上限", len(open_loop) == 6))
    checks.append(("开环始终没有真正收工",
                   all(s.decision != "结束" for s in open_loop)))
    checks.append(("闭环比开环少走很多轮", len(closed) < len(open_loop)))
    checks.append(("同一输入重放得到同一轨迹",
                   run_loop(World(), True) == closed))

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `Step` 用 `dataclasses`（Python 标准库里用于快速定义数据类的模块）把一轮固化成四个字段：轮次、决策、行动、观察。刻意把三者并列写进一个结构，是为了让「这一轮到底看见了什么」无法被省略；`@dataclass` 还顺带生成了相等比较，最后一条重放断言才能直接比两条轨迹。
2. `World` 是被调用的外部世界的替身，`readings` 里 A 是「缺测」、B 和 C 是有效读数。`act` 只认两种动作：`查:编号` 返回读数，`结束` 返回「已结束」，其它一律「未知动作」。它被写成完全确定的，不掺随机数，这样每条断言都能手工推算。
3. `decide` 是整个闭环的判据所在：它先看 `history[-1].observation`，末字是「度」且不是「缺测」就判定目标达成、返回「结束」；否则从候选里挑一个还没试过的编号。注意它的唯一输入就是「看得见的历史」和「已试集合」——**观察不在输入里，决策就不可能受它影响**，这正是那根线的落点。
4. `run_loop` 把四个节点串起来：`decide` 出决策，决策即行动，`world.act` 产出观察，`history.append` 把三者一起留痕，然后回到下一轮。`use_observation=False` 时决策被写死成 `查:A`，于是无论返回什么，下一轮都不变——这就是可对照的开环。`max_rounds` 是兜底，防止任何一路无限转下去。
5. `main` 先跑闭环并断言：三步收工、末步是结束、每步三元组齐全、第一步读到「缺测」却没有误判为完成、第二轮观察到「25度」被原样留下。其中 `decide(closed[:1], ["A"]) == "查:B"` 是最直接的一条：只喂「A 缺测」这一步历史，决策就必须换到 B——把观察删掉，这个结果就不成立。
6. 接着跑开环并断言它撞满六轮、始终没有收工、轮数明显多于闭环；再用两个独立的 `World` 实例各跑一次闭环，断言轨迹完全相等，验证整条链路不依赖隐藏状态、可重放。这部分和 [检查点与重放](./k030-checkpoint-replay.md) 是同一套思路。
7. 结尾把每条性质打印成「通过 / 失败」，汇总成 `通过 N/N 项`，并用 `assert passed == len(checks)` 保证任何一条被破坏都会以非零状态退出。`if __name__ == '__main__':` 保证直接运行该文件才执行，被别处导入时不会偷偷跑起来。

有一处要如实说明：这里用「查编号」代替了真实工具、用固定字典代替了真实下游、用一段确定性函数代替了模型决策，全是为了让整条链路不需要联网、账号或第三方包就能独立跑通并手算验证。它演示的是观察回接、状态累积与收工条件的顺序，不是任何具体框架的实现；文中也没有给出任何运行结论。

## 踩坑与边界

- **观察只进日志不进输入**：现象是日志里每次返回都清清楚楚，程序却反复做同一个动作 → 原因是打印与「参与下一轮决策」是两件事，日志给人看、输入给程序读 → 把观察原文作为结构化字段写进下一轮可见输入，并用「删掉观察后决策是否改变」验一遍。
- **把「有返回」当成「有进展」**：现象是每轮都拿到东西，任务却始终没推进，甚至把「缺测」「空列表」当成功 → 原因是没有把观察翻译成「进展 / 没进展」的判据 → 给每类返回定可判定的含义，缺测记成「此路不通、换下一个」，别只记「查过一次」，参考 [错误如何回喂](./k029-error-feedback.md)。
- **没有停止判据，闭环变无限空转**：现象是循环一直转、成本一直涨，最后被外部超时掐断 → 原因是只写了「继续循环」没写「什么算做完」 → 同时设完成条件与轮数上限，并区分「状态没变」和「进展慢」，见 [停止条件](./k028-stop-conditions.md)。
- **早期观察被长轨迹冲掉**：现象是前几轮还挺聪明，越到后面越像在猜，因为最初的关键事实被挤出了上下文 → 原因是把全部历史无脑拼接，没有分层与裁剪 → 把「已试过什么、当前结论、剩余待办」做成结构化状态常驻，原文按需取回，见 [循环状态怎么存](./k027-loop-state.md) 与 [摘要压缩](./k044-summary-compression.md)。
- **重放或重试把动作做了两遍**：现象是明明只该发一次提醒，日志里出现两条，还都「成功」 → 原因是超时后不确定有没有执行，重试又没有稳标识 → 观察要落盘、动作要带幂等标识，超时先对账再决定重试，见 [超时对账](./k039-timeout-reconcile.md) 与 [幂等落盘](./k107-idempotent-persist.md)。

还要分清两件容易混的事：「循环」是形式，「闭环」是性质。一个跑了二十轮、每轮决策都一样的程序，形式上循环得很热闹，性质上仍是开环；反过来，一轮就收工、但这一轮的观察确实决定了收工，也照样是闭环。另外，闭环解决的是「根据结果调整下一步」，它不负责「这一步该不该被允许执行」——那是权限与边界要管的事，见 [权限矩阵与最小权限](./k037-permission-matrix.md)。把两者分开，出问题才不会在「模型怎么又不听话」上瞎猜。

- [ ] 能徒手画出带回箭头的四节点闭环，并指出回箭头带回来的是什么

## 三句话小结

决策—行动—观察闭环，是让程序每做一步都把外部返回的事实带回下一轮判断，使「下一圈比上一圈更懂局面」的最小工作单元。

关键做法是观察原样进入可见输入、把返回翻译成可判定的进展、用结构化状态累积已试与结论，并同时配好完成条件与轮数上限。

当任务的步骤固定、结果不会改变后续选择时，不必硬套循环；但只要一步的结果会影响下一步该做什么，缺了这根回接线就一定会空转。
