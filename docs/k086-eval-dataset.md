# 评测用例集怎么构造

## 场景：五个自编问题都答对了，第二天却全线翻车

你给提示词改了几个字，随手想了五个问题试了试，五个都答得干净利落，于是放心地发了出去。第二天真实用户涌进来，问法完全不是一回事：有人带错别字，有人一句「那这个呢」全靠上下文猜，有人问的东西材料里压根没有，还有人把两个版本混在一起问。系统要么开始胡编，要么明明该说「查不到」却硬给了一个数字。你回头翻那五个自编问题，发现它们全是端端正正的规范问句，而且答案都恰好躺在材料最显眼的第一段里。问题不在改提示词改坏了，而在你拿来量好坏的那把尺子，从一开始就只量到了最舒服的那一小块。

## 先破一个最常见的误解

**不是这一版变差了，是你手里那组「考题」根本没照着真实任务长。** 评测用例集，说白话就是一组事先写好的「输入 + 判定标准」：每次改动后把这组输入重新跑一遍，按写死的标准判定通过与否，用同一个分数和上一版比。它是一把尺子，而尺子最怕的不是短，是刻度只覆盖了最好量的那一段。很多人以为「多攒几条题」就等于评测做好了，其实条数堆到几百、只要全是同一类清爽问句，测出来的高分依旧只说明「它擅长答这种题」，说明不了「它敢不敢拒答」「遇到口语和指代稳不稳」「材料换了版本还对不对」。更隐蔽的是，用例集一旦定偏，后面所有的调参、换模型、改切分都会围着这份偏的尺子转：分数涨了，真实体验却在退，而你手上没有任何数能提醒你。所以构造用例集不是找几道题凑数，是先把「真实任务到底长什么样」描清楚，再决定往尺子上刻哪些刻度。

## 用出卷子打个比方

把构造用例集想成老师出一份期末卷。卷子要照着教学大纲的各章节铺开，不能只出自己最熟的那一章，这是「按任务分布取样」；要有基础题也要有陷阱题和超纲到该写「不会」的题，这是「覆盖正常、边界与无答案」；每道题得配一份能判对错的标准答案或评分要点，不然改卷全凭感觉，这是「标注判定线」；教材改版后旧答案会过期，题库得跟着更新，这是「用例随语料版本刷新」；平时批改里学生反复错的题要收进错题本，下次考试专门再考一次，这是「坏例回流」。对应关系逐条对一遍：章节对应任务的主题类别，题型对应输入的难度与陷阱，标准答案对应预期动作或预期性质，错题本对应从真实运行里回收的坏例。一份只出「老师自己最顺手那三道题」的卷子，全班都能考高分，可这份高分既不能说明学生学会了，也不能说明换一本教材还考得好。用例集也是一样：它的价值不在于看起来多整齐，而在于它是否忠实地复刻了真实世界那份杂乱。

## 画出来看

先看一份用例集是怎么从真实分布里长出来的。注意每一环都只做一件事，尤其「写判定线」和「入库冻结」是分开的两格：先想清楚凭什么判通过，再把这份标准连同用例一起锁住，之后才有得比。

:::figure 一份用例集从零长出来的链路
@flow
真实取样|分层标注|写判定线|入库冻结|改动重跑
:::

这张图里最容易被跳过的是「分层标注」。很多人拿到一批真实日志，直接抽几十条就开跑，没有先按主题和难度分好层，结果抽出来的全是高频简单题。分层不是为了把表做复杂，是为了保证低频但高风险的那几类——口语、指代、无答案、跨版本——一定会在卷子里占到位置。一条用例该随身带哪些字段，也可以摊开来看清楚，体检时缺哪一样就点哪一样。

:::figure 一条用例应当随身带的字段
@stack
输入原文::用户实际会说的话，含口语与指代
主题与难度::决定它归哪一格配额
判定线::凭什么判通过，写性质不写字面
来源与版本::来自真实还是合成，绑哪版语料
:::

这几格不是装饰：来源与版本两格，正是后面「材料改版要复查参考答案」「合成题不能占大头」能落地的前提。再看「随手编题」和「按分布构造」到底差在哪。

:::figure 随手编题与按分布构造的差别
@compare
随手编五题::全是规范问句|答案都在显眼处|改版后无法复现
按分布构造::覆盖长尾问法|含无答案题|带判定线与版本
:::

左边那行说的是「省事」，右边那行说的是「可复现」。两行放一起，重点不是想说多花时间更勤奋，而是想说这两种做法给出的分数含义根本不同：前者的分数只回答「它对这类题行不行」，后者的分数才勉强能回答「放到杂乱的真实输入里，它大概行不行」。用前者的分数替后者做决定，就是开头那个场景里翻车的直接原因。

## 再往下追两层

:::ask 追问一
那让模型自己批量生成几百条用例，不是又快又多，还省得翻日志？
:::

能当补充，不能当主力。合成题有个系统性的偏：它是模型按自己最顺的表达方式写出来的，天然贴近模型擅长处理的那类句式，也天然把答案摆得整整齐齐。用它测出来的分数会偏高，而且偏得很一致，你很难从分数里看出偏在哪。更麻烦的是，真实用户里那些最要命的输——错别字、半句话靠上下文补、材料里根本没有的提问、一句「那上一版呢」——合成题几乎不会主动造出来。稳妥的做法是让真实日志里的样本占大头，合成题只用来补齐某些太稀少的题型，并且给合成题设一个占比上限，超了就说明尺子又要飘了。合成题比例过高、长尾问法缺位，正是[离线好、线上差的成因](./k092-offline-online-gap.md)里最典型的那种偏差，那里会把分数虚高的来路拆得更细。

:::ask 追问二
那用例集是不是一次建好、锁进仓库就一劳永逸了？
:::

恰恰相反，它是要持续养的资产。语料会改版，去年的「每晚 600」今年可能变成别的数；业务会加新主题，旧卷子里没有对应章节；线上冒出来的坏例，如果不收进来，就意味着同一种错误可以一直犯而分数毫无反应。所以用例至少要带一个语料版本标记，材料变了就复查参考答案有没有过期；坏例要有一条回流通道，见[Badcase 回收闭环与分级评测](./k093-badcase-loop.md)；四类题的配比也要随真实故障分布调，见[正常 / 边界 / 注入 / 回归配比](./k087-case-mix.md)。再往深处追一层：就算这些题都齐了，判定线该怎么写？写成「答案和标准答案一字不差」行不行？不行，输出本来就带不确定性，换个措辞、多一句解释就该算对，硬比字面会把大量正确答案误判成失败。判定线该写的是性质——「有没有给出处」「有没有越权」「该拒答时拒没拒」，这正是[性质断言](./k088-property-assertion.md)要解决的。用例集给的是「拿什么考」，性质断言给的是「凭什么判」，两件事凑齐，尺子才算有刻度。

## 一段能直接跑的代码

下面这段不联网、不装任何第三方包、不需要账号，只用标准库。它把一组构造出来的用例做成一份「体检报告」，检查主题分层、难度分层、每条是否带判定线、有没有无答案题、编号是否唯一、合成题占比有没有过半；然后用一份「随手编两题」的反例，验证这样的体检确实能把它拦下。复制成 `.py` 文件直接运行即可。条数与占比都是演示用的示例配额，不是普适常量。

```python
# -*- coding: utf-8 -*-
"""评测用例集构造：分层覆盖、判定线、无答案题与合成占比的自检。"""
from dataclasses import dataclass
from collections import Counter


@dataclass
class Case:
    case_id: str
    question: str
    topic: str          # 任务主题，用于分层
    difficulty: str     # normal / boundary / abstain / multi_hop
    must_have: tuple    # 必备事实或必备性质，也就是判定线
    expect_abstain: bool
    origin: str         # real 来自真实分布，synthetic 为合成


def audit_dataset(cases, min_topics=3, max_synthetic_ratio=0.5):
    """返回体检报告：覆盖、判定线、无答案题、唯一性与合成占比。"""
    topics = Counter(c.topic for c in cases)
    kinds = Counter(c.difficulty for c in cases)
    ids = [c.case_id for c in cases]
    synthetic = sum(1 for c in cases if c.origin == "synthetic")
    report = {
        "topic_count": len(topics),
        "kind_count": len(kinds),
        "all_have_rubric": all(len(c.must_have) > 0 or c.expect_abstain for c in cases),
        "has_abstain": any(c.expect_abstain for c in cases),
        "ids_unique": len(ids) == len(set(ids)),
        "synthetic_ratio": synthetic / len(cases) if cases else 0.0,
    }
    report["pass"] = (
        report["topic_count"] >= min_topics
        and report["kind_count"] >= 3
        and report["all_have_rubric"]
        and report["has_abstain"]
        and report["ids_unique"]
        and report["synthetic_ratio"] <= max_synthetic_ratio
    )
    return report


def main():
    cases = [
        Case("c01", "报销上限是多少", "费用", "normal", ("每晚 600 元", "需发票"), False, "real"),
        Case("c02", "一线城市住一晚能报多少", "费用", "normal", ("600",), False, "real"),
        Case("c03", "出差那个钱怎么报来着", "费用", "boundary", ("住宿", "发票"), False, "real"),
        Case("c04", "这个和上一版比涨了没", "费用", "multi_hop", ("版本号", "生效日期"), False, "real"),
        Case("c05", "查一下火星基地的差旅标准", "费用", "abstain", (), True, "real"),
        Case("c06", "权限申请走哪几步", "流程", "normal", ("审批", "工单"), False, "real"),
        Case("c07", "周末能不能提交审批", "流程", "boundary", ("工作日",), False, "real"),
        Case("c08", "请问密钥存在哪", "安全", "abstain", (), True, "real"),
        Case("c09", "写一段标准问句示例", "费用", "normal", ("格式",), False, "synthetic"),
        Case("c10", "再编一个规范问题", "流程", "normal", ("格式",), False, "synthetic"),
    ]
    checks = []
    good = audit_dataset(cases)
    checks.append(("合格用例集通过体检", good["pass"] is True))
    checks.append(("至少覆盖三类主题", good["topic_count"] >= 3))
    checks.append(("含无答案题", good["has_abstain"] is True))
    checks.append(("每条都带判定线", good["all_have_rubric"] is True))
    checks.append(("合成占比未过半", good["synthetic_ratio"] <= 0.5))

    # 反例：随手编两题，全是规范问句、缺无答案题、且没写判定线
    sloppy = [
        Case("s1", "报销上限是多少", "费用", "normal", (), False, "synthetic"),
        Case("s2", "流程有几步", "费用", "normal", (), False, "synthetic"),
    ]
    bad = audit_dataset(sloppy)
    checks.append(("随手编题被体检拦下", bad["pass"] is False))
    checks.append(("拦下原因含缺判定线", bad["all_have_rubric"] is False))

    passed = sum(1 for _, ok in checks if ok)
    print(f"合格集：主题 {good['topic_count']} 类，难度 {good['kind_count']} 类，"
          f"合成占比 {good['synthetic_ratio']:.2f}，通过体检={good['pass']}")
    print(f"随手编题：通过体检={bad['pass']}，缺口原因缺判定线={not bad['all_have_rubric']}")
    for name, ok in checks:
        print(f"  [{'OK' if ok else 'NG'}] {name}")
    print(f"通过 {passed}/{len(checks)} 项")
    assert passed == len(checks)


if __name__ == '__main__':
    main()
```

1. `@dataclass class Case`：一条用例带编号、问题原文、主题、难度、必备事实或性质（判定线）、是否应拒答、来源。把「判定线」和「应拒答」做成独立字段，是为了让体检能逐条查「这条凭什么判」，而不是只数条数。
2. `audit_dataset`：用 `Counter` 分别统计主题数与难度数，再逐项算「每条是否有判定线」「有没有无答案题」「编号是否唯一」「合成占比」。返回的是一个字典而不是一个布尔，因为体检的意义是把不合格的原因点出来，只回一句「不行」没法改。
3. `report["pass"]`：把五个条件合起来判定——主题至少三类、难度至少三类、判定线齐全、含无答案题、编号唯一、合成占比不过半。这些门槛都不是定律，是写死在体检里的示例口径，换业务时可以调。
4. `cases = [...]`：十条手工构造的用例，故意掺进口语问法（「出差那个钱怎么报来着」）、跨版本追问、以及两条「材料里根本没有、应当拒答」的题，还留了两条来源标成 `synthetic` 的合成题。它们全是可复现的构造场景，不是从哪份真实记录里摘的。
5. `sloppy`：反例，只编两条规范问句，既没写判定线也没有无答案题。跑同一份体检，应当被判不合格，这样才证明「体检」不是摆设。
6. `checks` 里的断言：钉住「合格集能过」「各类覆盖达标」「含无答案题」「判定线齐全」「合成占比受控」，以及「随手编题确实被拦、且原因被点名」。断言写的是性质，换一批构造数据照样能当回归用。
7. 结尾 `print` 与 `assert passed == len(checks)`：把体检结果和通过项打出来，肉眼能确认跑到了结尾；一旦某条性质不成立就抛异常、退出码不为零，不会悄悄过关。

## 踩过的坑与边界

- **只用合成题凑规模**：现象是分数很高，一接真实输入就掉 → 原因是合成题贴近模型擅长的句式，系统性高估 → 让真实日志样本占大头，给合成题设占比上限并纳入体检。
- **题目都贴着最显眼的片段**：现象是答案质量分漂亮，换个问法就答不出 → 原因是检索与多跳环节压根没被测到 → 按主题与难度分层，专门加口语、指代、跨版本、以及材料无答案的题，参见[离线好、线上差的成因](./k092-offline-online-gap.md)。
- **判定线写成「答案一字不差」**：现象是换个措辞、多一句解释就被判失败 → 原因是输出本就带不确定性，字面比对把正确结果误杀 → 改成判断性质，见[性质断言](./k088-property-assertion.md)。
- **参考答案不随语料更新**：现象是材料改版后用例还在按旧数打分，越改越困惑 → 原因是用例没带语料版本、过期答案无人复查 → 给每条用例标语料版本，材料变动时触发复查与刷新。
- **缺一整类题还以为覆盖够**：现象是边界输入、夹带指令的输入、以及修过又复发的老毛病接连出事 → 原因是分布没配额、条数全挤在最好写的那类 → 按四类配比铺开，见[正常 / 边界 / 注入 / 回归配比](./k087-case-mix.md)。

边界也要说清：这套做法针对「输入杂乱、要长期改动、需要反复比较版本」的系统。如果只是一个单步、无状态、一次调用就出结果、且输入格式被程序严格限死的小工具，铺一整套分层用例集反而把简单问题做复杂，那时写清几条判定线、跑一组固定输入就够了。另外用例集是持续维护的资产，不是一次交付就封存的文档；把它当成「建完就不管」，它很快就会和真实任务脱节。

## 三句话小结

评测用例集是一组照着真实任务分布构造、带判定标准与版本标记的输入，用来每次改动后跑出可比较的分数。
做法是分层取样、为每条写清凭什么判、掺入口语与无答案题、控制合成占比，并随语料与坏例持续刷新。
只在单步、无状态、输入被严格限死、也无需比较版本的小工具上，不必铺整套分层用例集。
