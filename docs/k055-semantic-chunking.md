# 语义切分与层级切分：按边界切，小块命中大块作答

## 「该条款按 80% 执行」到底指哪一条

你从一份制度里召回了一段话：「上述标准按 80% 执行，特殊情况除外。」模型照着它答了，用户追问「哪个标准、什么特殊情况」，答案却编不出来源。你翻回原文才明白，这句话前面还有一级标题、一个限定小节和一整张适用条件表；单独拎出来的这个块，把「上述」两个字赖以成立的上下文全丢了。你试着把块放大到整章，召回倒是完整了，却因为整章主题太杂，具体那条限额反而搜不到了。

## 先破一个误解

**不是块不够大，是你让同一块同时承担「被搜到」和「够作答」这两件互相拧着的事。**

先把词说清楚。语义切分指顺着文档自带的边界切——标题、段落、句子、空行，而不是按固定字数硬砍；层级切分更进一步，切的时候保留父子关系：一级标题下有二级标题，二级标题下有段落，段落里再有句子，每个块都记得自己属于哪一层、上级是谁。这样做是为了把两件事分开：检索粒度要小而聚焦，才容易被精确命中；作答粒度要够完整，才带得齐限定条件。让一个块兼两职，必然一边将就一边。

为什么按边界切比按字数切稳？因为自然边界本身就是作者给出的语义单位：一个段落围绕一件事，一个标题下面是一组相关段落，一句话表达一个完整判断。顺着它切，句子不会被劈成两截，指代也不会跨块丢失（至少能在标题路径里找到出处）。更重要的是有了层级，就能玩「小块命中、大块作答」：先用小到一两句话的子块去做匹配，命中之后顺着父子编号回溯到它所属的完整章节，把大块送进生成。检索时看的是精准的小块，生成时看的是完整的大块，两者不必是同一个东西。

还有一层收益是「面包屑」：每个块自带一条标题路径，比如「差旅制度 > 住宿标准 > 一线城市」，这样即便片段脱离了原文档被单独递给模型，它也能判断自己属于哪个制度、哪个版本、适用于哪类城市。没有这条路径，孤立的片段就是一句没有归属的话，模型分不清它是通用规则还是某地的例外。标题路径属于元数据，怎么存、怎么跟着块走，见[切分元数据与父块回溯](./k056-chunk-metadata.md)；与之相对的做法见[固定长度切分与重叠](./k054-fixed-chunking.md)。

## 用一本带目录的手册来理解

把文档想成一本分章分节的手册，把检索想成读者在书里找一条规定。

按字数切相当于拿尺子量，每满若干行就裁一页，不管裁到的是不是一句话的中间；读者翻到这一页，常常只看到半句和一个孤零零的「上述」。按边界切则完全照着书本来：一章是一章，一节是一节，一个自然段是一段，裁出来的每一片本身就讲得通。目录在这里扮演双重角色：一方面它告诉你这一片出自哪章哪节（面包屑），另一方面它给了你「往回翻」的路——你在某一节的细则里找到了那句话，想看清它的适用条件，只要顺着目录翻回整节，前后限定就都在了。

对应关系：章与节是层级，目录条目是标题路径，某一节的细则段落是子块，翻回整节是父块回溯，读者找的那句话是查询。这个比喻点破了「小块命中、大块作答」的日常性：谁查手册不是先在细目里定位，再把那一整节读完？没人会把整本书背下来再回答，也没人只看被裁下来的半句话就敢下结论。

:::quote
检索要的是「一眼能认出是不是这里」，作答要的是「前后条件都在」。层级切分让两者各取所需，不必互相将就。
:::

## 把层级关系画出来

先看一份结构化文档从进到切成两层块，经过哪些动作。

:::figure 从结构化文档到父子两层块
@flow
识别标题|维护标题路径|按段落切子块|登记父子编号|命中后回溯
:::

第二步「维护标题路径」是整条链路的骨架：每遇到一级标题就更新当前路径，之后切出的每个子块都把这条路径带在身上。

一份文档切完后该留下哪些关系，可以列成清单：

:::figure 层级切分留下的四类信息
@stack
标题路径::块自带的定位线索，脱离原文也能判断适用范围
子块::一两句或一段，语义聚焦，专门用来做匹配
父块::完整章节，含限定条件与例外，专门用来作答
父子编号::命中子块后顺着它回填父块的那一根线
:::

第二行与第三行的分工是这套办法的要害：子块只负责「被搜到」，父块只负责「够作答」。把父块也塞进检索索引，等于又退回成大块检索，前面白拆了。

再看两种切法的差别：

:::figure 按字数切，与按边界切
@compare
按字数切::句子常被劈断|指代丢失|粒度只能二选一
按边界切::句子完整|自带标题路径|小块命中大块作答
:::

第二行最后一格是层级切分真正的收益：粒度不再是一个要两头妥协的数字，而是「检索用哪个、生成用哪个」两个可以分别选的东西。

:::tip 一条立刻见效的规则
把父块排除在检索索引之外，只让子块参与匹配；命中子块后按它的父子编号回填父块再送进生成。把这两类块混在同一份索引里，等于自动取消了层级切分的好处。
:::

## 再往深问两层

:::ask 那如果文档根本没有标题、就是一大段流水账，还能按边界切吗？
:::

能，只是边界要降级用。没有标题就退到空行分段、句号断句，再不行就用句子窗口：命中某一句后，把它前后各若干句一起当作上下文补进去。这仍然比按字数硬砍强，因为至少不会把一句从中间切开。标题路径没了，就用别的方式补定位：文档名、章节序号、段落序号、乃至「第几句」，只要能让片段脱离原文后仍可判断归属就行。还有个折中办法叫自动合并：若同一个父节点下被命中的子块足够多，就把整个父节点整体上提送进生成，用命中密度代替显式标题。这些做法形状不同，道理一致——匹配用的单位尽量小，作答时把上下文补回来。

:::ask 再深一层：既然父块要回填，为什么不让检索直接用父块，省掉这一层？
:::

因为大块的语义会被「主题平均」掉。一整章讲的是差旅费，可你的问题只关心「一线城市住宿上限」这一个具体位置；把整章压成一个检索单位，它更像在说「这一章讲差旅」，反而不容易在那句具体答案上被精确命中。小块表征干净、聚焦，命中率高，代价是缺前后限定——而限定条件恰好可以在命中之后补，不必在匹配时就带上。这就是「检索粒度与作答粒度解耦」的实质：用一个便宜的小单位解决「找不找得到」，再用一次编号回填解决「看不看得全」。想确认到底该用多大的子块，别拍脑袋，拿一组固定的评测问题扫几档粒度，看该找的片段回没回来，见[多轮检索与检索质量评测](./k064-rag-eval.md)。回填要靠编号，编号属于元数据，怎么设计才不会在片段被改动后错位，见[切分元数据与父块回溯](./k056-chunk-metadata.md)。整体顺序可以从[从这里开始](./00-start-here.md)顺着看。

## 一份能跑的对照

下面这段只用标准库，识别一份带一级、二级标题的短文档，按段落切出子块并给每块维护标题路径与父级标记，再演示「按父级聚合出大块作答」。

```python
# semantic_chunk.py —— 只用标准库，python semantic_chunk.py
import re

DOC = """# 差旅制度

## 住宿标准
一线城市每晚 600 元，其他城市每晚 400 元。
超标部分不予报销。

## 报销流程
行程结束后七个工作日内提交发票。
发票需与行程单一致。

# 设备规定

## 质保
型号 XJ-2200B 质保三年。
"""


def semantic_chunk(doc):
    chunks, path, body = [], [], []
    seq = 0

    def flush():
        nonlocal body, seq
        if body:
            seq += 1
            chunks.append({
                "id": "s%d" % seq,
                "heading": " > ".join(path),
                "parent": path[0] if path else "",
                "text": " ".join(body),
            })
            body = []

    for line in doc.splitlines():
        s = line.strip()
        if not s:
            flush()                       # 空行就是一个自然边界
            continue
        m = re.match(r"^(#+)\s+(.*)$", s)
        if m:
            flush()                       # 标题前先把上一段收尾
            level = len(m.group(1))
            path = path[:level - 1]      # 按层级截断，再压入本级标题
            path.append(m.group(2))
        else:
            body.append(s)
    flush()                             # 收掉末尾没有空行的一段
    return chunks


if __name__ == '__main__':
    chunks = semantic_chunk(DOC)
    assert len(chunks) == 3                                  # 三个小节各成一块
    assert chunks[0]["heading"] == "差旅制度 > 住宿标准"
    assert chunks[2]["heading"] == "设备规定 > 质保"
    assert "超标部分不予报销" in chunks[0]["text"]           # 段落没被切断
    assert all(c["heading"] for c in chunks)                 # 每块都带面包屑
    assert len({c["heading"] for c in chunks}) == 3

    # 小块命中、大块作答：按父级把子块聚成完整章节
    grouped = {}
    for c in chunks:
        grouped.setdefault(c["parent"], []).append(c["text"])
    big = {k: " ".join(v) for k, v in grouped.items()}
    assert len(big) == 2
    assert "600" in big["差旅制度"] and "七个工作日" in big["差旅制度"]
    assert "XJ-2200B" in big["设备规定"]
    print("通过 9/9 项：按边界切、维护标题路径、父级聚合出完整上下文")
```

1. `DOC` 是本地构造的一份短文档，有两级标题、空行分段，末尾一段不带空行——这个细节是特意留的，用来验证收尾逻辑。
2. `semantic_chunk` 逐行扫描：空行或标题都触发 `flush`，把攒下的正文收成一个块。`re.match(r"^(#+)\s+(.*)$", s)` 认出标题，`len(m.group(1))` 是 `#` 的个数，也就是层级。
3. `path = path[:level - 1]` 之后再 `append` 本级标题，是维护标题路径的关键：遇到二级标题时保留一级路径、压入二级；遇到新的一级标题时把路径截到空，重新开始。这样「设备规定 > 质保」不会错挂到上一章下面。
4. 每个块带四样东西：`id` 编号、`heading` 面包屑、`parent` 父级标记、`text` 正文。`parent` 就是那根回填线，有了它才能做小块命中、大块作答。
5. 后半段把子块按 `parent` 聚合成整章，演示回填的效果：命中「住宿标准」的子块后，顺着 `parent` 能把同章「报销流程」的上下文一并取回。九条断言跑完打印通过项数。

想看得更清楚，可以在 `DOC` 里加一行三级标题 `### 例外`，会看到标题路径自动变成三节；或者删掉一个空行，会看到两个小节被并进同一块——这正是「按边界切」对原文结构敏感的地方，也是为什么解析阶段要把标题层级还原准，见[文档解析与清洗](./k053-doc-cleaning.md)。

## 踩过的坑

- **把父块也塞进检索索引**：现象是精挑的子块没起作用，召回还是整章整章地来 → 原因是父子块混在同一份索引里，大块照样参与匹配 → 怎么改：只让子块进索引，父块另存，命中后按编号回填。
- **标题路径没跟着块走**：现象是片段脱离原文后分不清属于哪个版本、哪个产品 → 原因是切分时只留了纯文本 → 怎么改：每块写进 `heading` 与 `parent`，把定位线索当块的一部分。
- **层级截断写错**：现象是「设备规定 > 质保」被挂到「差旅制度」下面，答案串了章 → 原因是遇到新的一级标题没把旧路径清空 → 怎么改：按标题级别截断路径再压入本级，并用构造文档做断言。
- **既做大量重叠又做父子回溯**：现象是候选里冗余块成堆 → 原因是两种补上下文的手段一起上，付了两遍名额 → 怎么改：二选一，按边界切之后优先用回溯。
- **粒度照抄一个固定值**：现象是换一类文档后召回明显变差 → 原因是自然边界的分布变了，子块忽大忽小 → 怎么改：按内容类型分别定，并在固定评测集上扫粒度。

## 三句话

语义切分与层级切分，是顺着标题、段落、句子这些自然边界切块，并保留父子关系与标题路径的做法。
关键做法是让小块只负责被命中、父块只负责补全上下文，命中后顺着父子编号把大块回填进生成。
当文档本就是无结构的一大段流水账、又不需要区分适用边界时，直接按字数切反而更简单。
