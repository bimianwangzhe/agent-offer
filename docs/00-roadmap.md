# 学习路线：从调 API 到能上岗

网上大部分 Agent 路线图的问题是**按知识点排列，不是按岗位能力排列**。学完「RAG 是什么」并不会让你通过面试，面试官要的是「你做过什么、踩过什么坑、怎么证明它可靠」。

这份路线按「能交付什么」来切分，每个阶段都有验收点。达不到验收点就别往下走。

## 岗位能力模型（先知道终点）

Agent 开发岗（大模型应用开发 / AI 应用工程师 / Agent 工程师）实际考察的是五块：

| 能力 | 面试官怎么问 | 权重 |
|---|---|---|
| 模型与上下文 | 上下文超了怎么办、怎么控制 token 成本 | 高 |
| 编排与状态 | 循环怎么终止、失败怎么恢复、要不要人在回路 | 高 |
| 工具与集成 | 工具调用怎么保证幂等、权限怎么收 | 高 |
| 检索与记忆 | 召回不准怎么定位、长期记忆怎么淘汰 | 中高 |
| 工程与评测 | 怎么证明改了一版没有变差、怎么上线 | **最高（分水岭）** |

> 分水岭在最后一行。能跑 Demo 的人很多，能说清「评测集怎么建、回归怎么卡、线上怎么兜底」的人很少。

## 五阶段

### 阶段 ① 打底（约 1 周）

- 亲手调一次 LLM API：对话、流式输出、结构化 JSON
- 写清 Prompt 的四件事：角色、步骤、Few-shot、输出约束
- 搞懂 token、上下文窗口、temperature、temperature 之外的采样参数

**验收**：不看框架文档，用纯 API 写出一个「读一段文本 → 抽取字段 → 输出合法 JSON」的程序，并能处理模型偶尔吐出非法 JSON 的情况。

### 阶段 ② 核心（约 2~3 周）

- 手写 ReAct 循环：思考 → 选工具 → 执行 → 观察 → 继续
- Function Calling 与 JSON Schema，工具描述怎么写才不误导模型
- 上下文工程：token 预算、压缩、路由、系统提示分层
- 失败模式：死循环、工具报错、模型幻觉参数、超预算

**验收**：不用任何 Agent 框架，手写一个 200 行以内的 Agent，能跑 5 轮以上不崩，且能打印完整轨迹。

### 阶段 ③ 扩展（约 3~4 周）

- RAG 全链路：解析 → 切分 → 向量化 → 混合检索 → 重排 → 生成 → 溯源
- 三层记忆：工作草稿、会话压缩、长期语义召回
- MCP 协议：工具标准化、动态发现、最小权限
- 框架选型：用 LangGraph 重构你手写的那个 Agent，对比前后差异

**验收**：接一份真实文档（不是官网示例），能回答需要跨段落才能答对的问题，并给出引用位置。

### 阶段 ④ 上线（约 2~3 周）

- 三层评测：单元 / 场景 / 回归，先手搓 50 条标注案例
- 链路追踪：每一步的输入输出、耗时、token、成本都能查
- 护栏：提示注入、PII 掩码、输出语法约束、高危动作人工确认
- 成本与稳定性：语义缓存、模型路由、熔断降级、并发与限流
- 部署：容器化、健康检查、灰度与回滚

**验收**：你把阶段 ② 的 Agent 改一版，评测集分数不下降；断掉某个工具，系统能降级而不是崩。

### 阶段 ⑤ 上岗（约 1~2 周）

- 用岗位 JD 反推能力矩阵，补齐自己最弱的一格
- 把项目整理成「背景 → 约束 → 决策 → 数据 → 复盘」的讲法
- 高频考点与追问链演练（见 [09 面试考点](./09-interview.md)）

**验收**：对一个没做过 Agent 的人，15 分钟讲明白你的系统，并且能接住「为什么不直接用某某框架」这类追问。

## 三个可以写进简历的项目

不要写「基于 LangChain 的智能问答」，那类项目烂大街且看不出能力。选下面这种**有工程约束**的：

| 项目 | 核心约束 | 能讲出的亮点 |
|---|---|---|
| 带回归评测的研报助手 | 召回必须可溯源、拒答要有理由 | 评测集设计、引用校验、幻觉兜底 |
| 多工具运维 Agent | 高危动作需人工确认、工具必须幂等 | 状态机、HITL、权限边界、审计日志 |
| 长会话客服 Agent | 上下文会爆、成本要可控 | 上下文压缩、记忆淘汰、缓存与路由 |

每个项目都准备三个数字：单任务成本、成功率（评测集口径）、P95 耗时。**没有数字的项目，在面试里等于没做过。**

## 常见弯路

- **从框架开始学**：换一次版本就得重学，先手写循环再看框架替你做了什么。
- **一上来做多 Agent**：单 Agent 跑不稳时拆成多个，只会把问题乘以 N。上下文容量、职责边界、吞吐三者真出现瓶颈了再拆。
- **只做 Demo 不做评测**：这是最普遍的失败原因，也是最好拉开差距的地方。
- **追新名词**：MCP、上下文工程、编排者模式这类生命周期长的原语值得投；按季度换的模型不值得。

## 时间预算参考

按每天 2 小时投入，总计约 **10~13 周**。已有后端工程经验的人可以压缩阶段 ①，但**不要压缩阶段 ④**——它恰恰是面试区分度最高的部分。
