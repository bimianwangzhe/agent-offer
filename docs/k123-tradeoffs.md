# 约束、权衡与可验证结果

简历上你写「独立开发了智能助手，效果好、响应快」，自己都觉得这句话没什么分量，可又想不出还能补什么。面试时对方顺着问：「限定了什么范围？为什么不用更简单的做法？『效果好』是怎么测的？」三个问题下来，你发现自己一句都答不到点子上——你写的是结论，人家要的是得出这个结论的条件。

**不是文采不够，是把「做了什么」当成了全部，漏了约束、权衡、可验证结果这三样。** 一句「做了智能助手」谁都能写；能让人判断你做过决策的，是「在什么限制下做、为什么没走另一条路、结果怎么核对」。

先把词说清。约束（constraint）指这个项目被明确限死的条件，比如只处理某类输入、只用本地材料、不碰某类动作。权衡（trade-off，也叫取舍）指你在两条都可行的路之间选了一条，并能说清放弃另一条的理由。可验证结果指别人能动手复核的检查或口径，不是「不错、挺快」这类形容词。智能体（Agent）是能自己决定下一步并调用工具的程序。基线（baseline）是用来对照的最简单做法，比如一条固定规则脚本。断言（assertion）是程序里一条「必须成立」的检查，跑不过就报错。这些词先分清，后面才不会把「描述」和「证据」混在一起。

## 一、生活类比：一张写明施工条件的报价单

想象你找人做阳台封窗，收到两份报价。第一份写：「工艺精湛，品质优良，完工快。」第二份写：「只封朝南这一面，不动承重墙；没用整块大玻璃，改用两块可拆的，因为老小区电梯进不去整块；完工后可用水平尺逐段复核，接缝误差当场量。」你几乎不用犹豫就知道该信谁。

第二份之所以可信，是因为它把三样东西摊开了：范围被划死（只朝南、不动承重墙），这是约束；点明了放弃的方案和放弃原因（整块玻璃进不去电梯），这是权衡；给了当场能量出来的检查（水平尺、接缝误差），这是可验证结果。对应关系是：报价单对应简历那句话，施工条件对应项目约束，放弃的那套方案对应没选的技术路，水平尺对应可复跑的检查。**第一份全在讲「我很好」，第二份全在讲「在什么条件下、凭什么这么说」——后者才让人能判断，而不是只能选择信或不信。**

## 二、一句陈述要过三道体检

把类比收成可操作的检查，就是给每句简历陈述过三道：有没有写清约束、有没有点明取舍、有没有给可核对的结果。三道都过，这句话才站得住；缺一道，被追问时就会露空。注意这三道不是让你把句子写长，而是把「凭什么这么说」补进去。

:::figure 一句项目陈述的三要素
@stack
约束::限定范围、排除项与不碰的动作，先划死边界
取舍::点明没选哪条路，以及为什么没选它
可验证结果::给能复跑的检查或口径，不用形容词
:::

三要素有个常见误区：把它们写成三句并列的好处，而不是一条因果链。真正有说服力的顺序是「因为被这些限制卡住 → 所以没走那条更显眼的路 → 于是用这个能复核的检查确认没选错」。约束决定了取舍，取舍决定了该验什么；反过来先喊结果再补理由，读起来就像给结论找说辞。三件作品各自卡在不同限制上，见[三个能写进简历的项目](./k122-three-projects.md)；本篇管的是把其中每一件写成不心虚的一句话。

:::ask 那如果那个场景其实没什么限制，就是个通用助手呢？
那更该老实写出来，而不是硬编一条限制。可以写「输入限定为构造的固定用例、不接真实账号」这类真实存在的边界；如果确实什么都没限，就说明「没做范围收窄」，并把它当成一条待改进项写进复盘。**约束的价值是可核对，不是显得严谨；编一条不存在的限制，比不写更伤可信度。**
:::

:::ask 那如果「不选另一条路」根本没比较过，只是随手用了一种做法呢？
那就别假装做过权衡。临时补一个「相比之下」很容易被一句「另一条你跑过吗」问穿。诚实的做法是现在补一次对照：把最简单的基线（比如一条固定规则脚本）也跑一遍，说清在哪些用例上它够用、在哪些用例上不够用，权衡就有了依据。**没比较过的选择不叫取舍，叫习惯；补一次对照就能把它变成能讲的决定。** 对照用的数字怎么写才站得住，见[数字口径与统计范围](./k124-number-integrity.md)。
:::

:::figure 空泛陈述与三要素陈述
@compare
只写做了什么::智能助手一句话|没有限制条件|结果全靠形容词
写清三要素::范围先划死|取舍有对照|结果能复跑
:::

左边三点是连锁的：只有标签 → 说不出条件 → 结果只能靠形容词撑。右边三点也是连锁的：范围划死 → 取舍才有对照物 → 结果才能被人复核。两种写法差的不是字数，是「别人能不能据此判断你做过决策」，以及被追问时你拿不拿得出证据。

## 三、把三要素写成能跑的体检程序

下面的脚本零依赖、不需要账号、不需要联网。它给一句自然语言陈述做三要素体检，指出缺哪几项；用来演示「空泛句」和「改写句」的差别，结论完全由本地构造的输入决定。

```python
# k123.py —— 简历陈述的三要素体检（零依赖，python k123.py）


def audit_text(text):
    """只给一句自然语言，检查约束、取舍、可验证结果是否都写了。"""
    return {
        "有约束": any(k in text for k in ("限于", "只处理", "不超过", "范围限定")),
        "有取舍": any(k in text for k in ("不选", "相比", "改为", "而不是")),
        "可验证": any(ch.isdigit() for ch in text),
    }


def verdict(text):
    r = audit_text(text)
    gaps = [k for k, v in r.items() if not v]
    return len(gaps) == 0, gaps


if __name__ == "__main__":
    passed = total = 0

    def check(label, cond):
        global passed, total
        total += 1
        assert cond, label
        passed += 1
        print("  [通过] " + label)

    vague = "做了一个智能助手，效果不错"
    good = ("范围限定单库 300 条固定工单，不选多智能体而是改为单循环，"
            "随文断言 11/11 通过可现场重跑")
    check("空泛陈述三项全缺", not verdict(vague)[0] and len(verdict(vague)[1]) == 3)
    check("改写后的陈述三项齐全", verdict(good)[0])
    check("能点名空泛陈述缺约束", "有约束" in verdict(vague)[1])
    check("改写后确实写了取舍", audit_text(good)["有取舍"])
    check("改写后确实给了可复跑口径", audit_text(good)["可验证"])

    half = "范围限定单库工单，做了单循环"
    check("只写约束不够，仍被拦下", not verdict(half)[0])
    check("缺口精确到缺哪两项", set(verdict(half)[1]) == {"有取舍", "可验证"})
    print("通过 %d/%d 项" % (passed, total))
```

运行后打印每条断言与汇总：

```text
  [通过] 空泛陈述三项全缺
  [通过] 改写后的陈述三项齐全
  [通过] 只写约束不够，仍被拦下
通过 7/7 项
```

逐段解释关键行在做什么：

1. `audit_text` 把三要素做成三个布尔：约束看有没有「范围限定 / 只处理」这类划界词，取舍看有没有「不选 / 相比 / 改为」这类对照词，可验证看有没有数字。它只是个粗糙的文本体检，用来逼你把三样都写出来，不代替真实核对。
2. `verdict` 把三项里为假的收进 `gaps`，返回「是否全过」和「缺哪几项」。能点名缺哪一项，比只给一个不通过更有助于改句子。
3. `vague` 是典型的空泛句，三样都没有；`good` 把范围、放弃的路、可重跑的断言都写进一句话，三项齐全。两句是本地构造的对照样例，不涉及任何真实测量。
4. `half` 只写了约束、没写取舍和结果，专门演示「补了一半还是不够」；对应前面的判断：三要素缺一不可，不是凑够两条就能过。
5. `check` 用 `assert` 兜底，任一结论不符脚本就失败；末尾 `通过 N/N 项` 把「体检器本身对不对」也变成可复核的一行输出。
6. 注意 `可验证` 只检查有没有数字，这是演示用的弱条件；真实写法要给出能现场重跑的检查与统计范围，别让一个孤零零的数字蒙混过关。

:::warn 别把体检器当成写作模板
代码里的关键词只是提醒，不是目标。**把「范围限定」四个字凑进去却说不清到底限了什么，比不写更容易被追问穿。** 三要素要落在真实条件上，关键词只是顺带出现。
:::

## 四、踩坑与边界

- **只喊结果**：现象是「效果好、响应快」，被问「怎么测的」答不上 → 原因是把结论当成了陈述，没给可核对口径 → 怎么改：换成能重跑的检查，并说明统计范围与时间窗。
- **编造限制**：现象是为了显得严谨写了一条项目里根本不存在的约束，一追就露 → 原因是把约束当修饰词而不是事实 → 怎么改：只写真实存在的边界，没有就如实说没做范围收窄。
- **假装有取舍**：现象是写「相比之下更优」，却从没跑过另一条路 → 原因是把习惯包装成决策 → 怎么改：补一次基线对照，说清另一条在哪些用例上够用、哪些上不够用。
- **结果孤零零一个数字**：现象是写了百分比却没说分母是什么、统计了哪些用例 → 原因是数字没有口径 → 怎么改：像写「分子 / 分母 + 范围 + 时间窗」那样补全，见[数字口径与统计范围](./k124-number-integrity.md)。
- **三样写成三句好处**：现象是约束、取舍、结果各吹一句，读不出因果 → 原因是没有串成链 → 怎么改：按「被什么限制 → 所以没走哪条路 → 于是验什么」的顺序重写。

:::figure 从空泛句到三要素句
@flow
写初始陈述|查约束|查取舍|查可验证结果|改写并复核
:::

图里从第二环到第四环是同一句话的三次体检，任何一环为假就回到「改写并复核」。把这张图练熟，被一层层追问「凭什么这么说」时才知道该往哪补；追问的层次展开见[四层追问链与转行者三问](./k125-followup-chain.md)。整段讲述怎么排进有限时间，见[15 分钟讲项目的节奏](./k126-project-pitch.md)。

:::quote
「做了智能助手」是标签；「被什么限制卡住、所以没走哪条路、于是怎么核对」才是一句能让人判断你做过决策的话。
:::

## 五、自检清单

:::check 学完自检
- [ ] 能说出三要素，并解释为什么缺一不可
- [ ] 能把「效果好」改写成带范围、对照、可复跑检查的一句话
- [ ] 知道没比较过的选择不能写成取舍，要先补基线对照
- [ ] 能识别「编造限制」「假装有取舍」这两类反例
- [ ] 知道孤零零的数字不算可验证结果，还得补口径
:::

是什么：这是用约束、权衡、可验证结果三要素，把项目陈述从标签改写成可判断句子的方法。
关键做法：按「被什么限制 → 没走哪条路 → 怎么核对」串成因果链，每项都落在真实可复核的条件上。
什么时候不该用：只有一句跑通示例、说不出真实边界也没做过对照时，别硬套三要素，先补事实再写句子。
