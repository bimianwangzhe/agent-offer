# 四层追问链与转行者三问

你把自己做过的项目讲了一遍，架构、用了什么、结果如何都说到了，自认为挺完整。对方却接着往下问：「你说自己实现了循环，状态具体放哪？」「你说效果能达标，能现场复现给我看吗？」「运行里出了错，你怎么定位到是哪一步？」一层比一层深，你发现自己第一层还能答，第二层开始含糊，第三层基本只能说「应该没出问题」。

**不是讲得不流利，是你只准备了「是什么」，没准备被追的那条决策链。** 面试追问从来不是随机加难，而是顺着「是什么 → 怎么做的 → 凭什么信 → 怎么定位问题」一层层往下压；转行背景还会多压三问，专门区分「跑通过示例」和「做过工程」。

先把词说清。追问链指面试官沿着同一件作品逐层深入的一组问题，前一层答不上，后面的层就到不了。轨迹（trace）指一次运行里按顺序记下的完整记录，包含每轮选了什么动作、工具结果、状态变化。复现指按同一份输入和记录，把结果重新跑出来。断言（assertion）是程序里一条「必须成立」的检查。智能体（Agent）是能自己决定下一步并调用工具的程序。RAG 是 Retrieval-Augmented Generation（检索增强生成）的缩写，指先检索材料、再拼进上下文作答的做法。日志（log）是运行过程中留下的可查记录。这些词第一次出现都给了白话，后面直接用不再重复。

## 一、生活类比：修车师傅被车主连问四句

想象车主要把车留给一位师傅修，他不放心，于是连问四句。第一句「这是什么毛病」——师傅答「电瓶亏电」，这是「是什么」。第二句「你打算怎么弄」——师傅说「先测电压、再查充电线路、最后决定换不换」，这是「怎么做的」。第三句「我凭什么信你真弄过」——师傅把检测单、旧件、刚打出来的读数摆出来，这是「凭什么信」。第四句「要是开两天又坏了，你怎么查」——师傅说「按那天的检测顺序倒回去，看是哪一段读数先不对」，这是「怎么定位问题」。

对应关系是：车主的四句对应追问链四层，检测单和读数对应轨迹与断言，「按检测顺序倒回去」对应按日志回放。**只答得出第一句的师傅，车主不会把车留下；因为第一句谁都能说，后面三句才证明他真动过手、并且出了事能兜住。** 转行者被多压的三问也是同一个意思：凭什么信你做过、和只会调接口的人差在哪、出了错怎么定位——问的都是「你是不是只把别人的示例跑通了一遍」。

## 二、四层怎么一层层压下来

四层不是四个并列话题，是一条必须连续走通的链：先说清它是什么、边界在哪；再讲怎么做的，状态放哪、怎么收尾；然后拿出能现场复现的证据；最后说明运行里出错怎么定位到具体一步。断在哪一层，后面就到不了。代码里那个 `depth_of` 正是按「从第一层连续往下，跳一层就断」来算深度的。

:::figure 四层追问链分别要答什么
@stack
是什么::说清定义与边界，先别急着报技术名
怎么做的::状态放哪、消息怎么走、怎么判定完成
凭什么信::轨迹、断言、回放，能现场复现给人看
怎么定位问题::按日志倒查，指出是哪一步先不对
:::

转行者三问可以逐一挂到这四层上：「凭什么信你做过」压在第三层，要的是轨迹与可复跑的断言；「和只会调接口差在哪」压在第二层，要的是状态、终止条件、取舍这些自己定的部分；「怎么定位问题」正好是第四层。三问不是额外刁难，是把四层里最容易被含糊带过的两三层单独拎出来再问一遍。怎么把「怎么做的」讲成有取舍的决策而不是名词清单，见[约束、权衡与可验证结果](./k123-tradeoffs.md)；证据里的数字怎么写才站得住，见[数字口径与统计范围](./k124-number-integrity.md)。

:::ask 那如果我第一层就答得很细，把架构全抖出来，是不是能少被追几层？
恰恰相反。第一层堆太多实现细节，会让「是什么」和「怎么做的」糊在一起，对方反而会追问「那你先一句话说清它到底解决什么」。分层回答的价值是让每一层都有明确落点，方便对方按需往下压。**该简则简、被追再展开，比一口气全倒出来更稳。** 而且跳层还会触发补问：你没说边界，对方就得先回头问边界，链反而变乱了。
:::

:::ask 那如果第三层「凭什么信」我确实拿不出现场能复现的东西呢？
别硬说「肯定没问题」，那会把前两层一起拖下水。诚实的做法是把证据缺口说清：哪些检查跑了、哪些情况还没覆盖、打算怎么补上。更稳的办法是从第一天就留轨迹——循环写完的当天就把「每轮动作、工具结果、状态变化」的格式定下来，评测、排障、答辩都吃这份数据。**第三层不是临场变出来的，是平时留出来的。** 留痕怎么支撑版本对比，见[状态共享、冲突处理与失败恢复](./k120-shared-state.md)。
:::

:::figure 停在浅层与走通四层
@compare
只答第一层::报了技术名|状态说不清|出错只能猜
走通四层::边界先讲明|证据能复现|按日志定位
:::

左边三点是一条下坡：只报名词 → 讲不出状态与完成判定 → 没有留痕，出错只能靠猜。右边三点是一条上坡：边界清楚 → 证据可复跑 → 定位有路径。差别不在口才，在「有没有为后三层提前准备过东西」。

## 三、把追问深度写成能跑的检查器

下面的脚本零依赖、不需要账号、不需要联网。它用关键词判断一段回答走到了第几层（跳层即断链），检查转行者三问是否被覆盖，并给出「断在这层时下一句该问什么」。回答文本全是本地构造的样例。

```python
# k125.py —— 四层追问链与转行者三问的深度检查（零依赖）
LAYERS = ("是什么", "怎么做的", "凭什么信", "怎么定位问题")
KEYS = {
    "是什么": ("定义", "边界", "是什么", "负责"),
    "怎么做的": ("循环", "状态", "分派", "实现", "字段"),
    "凭什么信": ("轨迹", "断言", "回放", "复现", "证据"),
    "怎么定位问题": ("排查", "定位", "日志", "哪一步"),
}
QKEYS = {
    "凭什么信你做过": ("轨迹", "断言", "回放", "复现"),
    "和只会调接口差在哪": ("状态", "终止", "取舍", "自己实现"),
    "怎么定位问题": ("排查", "定位", "日志", "哪一步"),
}
PROMPTS = (
    "先说清它是什么、边界在哪",
    "那具体怎么做的，状态放在哪",
    "凭什么信你做过，能现场复现吗",
    "运行中的系统出了错，你怎么定位到哪一步",
    "四层都答到了，可以收",
)


def depth_of(answer):
    """追问链必须从第一层连续往下，跳一层就算断链。"""
    hit = [L for L in LAYERS if any(k in answer for k in KEYS[L])]
    reached = 0
    for L in LAYERS:
        if L in hit:
            reached += 1
        else:
            break
    return reached


def covered_questions(answer):
    return [q for q, keys in QKEYS.items()
            if any(k in answer for k in keys)]


def next_ask(depth):
    return PROMPTS[min(depth, len(PROMPTS) - 1)]


if __name__ == "__main__":
    passed = total = 0

    def check(label, cond):
        global passed, total
        total += 1
        assert cond, label
        passed += 1
        print("  [通过] " + label)

    shallow = "就是一个客服机器人，用了框架搭的"
    mid = "它是什么：带循环的工单助手；怎么做的：自己写了状态字段和终止条件"
    deep = ("是什么：工单助手；怎么做的：自己实现状态与终止条件；"
            "凭什么信：有轨迹回放与断言可复现；"
            "怎么定位问题：按日志定位到哪一步")

    check("只说用了框架，停在零层", depth_of(shallow) == 0)
    check("答到怎么做，停在二层", depth_of(mid) == 2)
    check("四层齐全能一口气答到底", depth_of(deep) == 4)
    check("断在第二层时，下一问是凭什么信", "复现" in next_ask(2))
    check("四层答完给出收尾话术", next_ask(4) == "四层都答到了，可以收")
    check("完整回答覆盖转行者三问", len(covered_questions(deep)) == 3)
    check("空泛回答覆盖不了三问", len(covered_questions(shallow)) == 0)
    check("深度不会超过四层", depth_of(deep) <= len(LAYERS))
    print("通过 %d/%d 项" % (passed, total))
```

运行后打印每条断言与汇总：

```text
  [通过] 只说用了框架，停在零层
  [通过] 答到怎么做，停在二层
  [通过] 四层齐全能一口气答到底
通过 8/8 项
```

逐段解释关键行在做什么：

1. `LAYERS` 把四层写成固定顺序的元组，`KEYS` 给每层挂一组关键词，`QKEYS` 给转行者三问各挂一组关键词，`PROMPTS` 是断在第几层时下一句该问什么。四份都是数据，改问题只动这里。
2. `depth_of` 先算出回答命中了哪些层，再从头逐层数，遇到第一层没命中就 `break`。这就是「跳一层算断链」：哪怕第四层说了「日志定位」，只要第三层没答，深度仍停在二。
3. `covered_questions` 用同样的关键词方式检查三问覆盖情况；注意三问和四层共用一批词（比如「轨迹」「状态」「定位」），正因为它们问的是同一条链的不同侧面。
4. `next_ask` 用 `min(depth, len(PROMPTS) - 1)` 做上界保护，深度到四时返回收尾话术，不会越界。
5. `shallow` / `mid` / `deep` 三段是本地构造的回答样例，分别演示停在零层、二层、四层；`mid` 故意不提证据，好让「断在第二层」这一条能被检验。
6. `check` 用 `assert` 兜底，任一结论不符脚本就失败；末尾 `通过 N/N 项` 把「深度检查器本身对不对」也变成可复核的一行输出。

:::warn 关键词只是演示，别拿它当评分器
真实回答里没写出「轨迹」两个字，也可能讲得很扎实；写满关键词也可能是空话。**这份代码的价值是把「四层要连续、三问要覆盖」这条结构固定下来，具体内容还得靠你逐层准备。**
:::

## 四、踩坑与边界

- **只报名词**：现象是第一层就把框架名、技术名倒一遍，被问「先一句话说清它解决什么」卡住 → 原因是没先立定义与边界 → 怎么改：第一层只答「是什么、边界在哪」，实现细节等第二层被追再展开。
- **跳层作答**：现象是没讲「怎么做的」就先说「效果能达标」，对方回头补问状态放哪 → 原因是链断了还往前跑 → 怎么改：按四层顺序走，前一层没落稳别抢后一层。
- **证据临场凑**：现象是被问「能复现吗」只能说「应该没问题」 → 原因是平时没留轨迹与断言 → 怎么改：循环写完当天定轨迹格式，把每轮动作、工具结果、状态变化留下来。
- **把故障讲成没出过**：现象是回答「没遇到过问题」，第四层直接断 → 原因是把「没出事」当稳妥，反而显得没跑过 → 怎么改：准备一次真实构造的故障，按日志顺序讲清怎么定位到哪一步。
- **三问当刁难**：现象是被转行者三问压到就紧张，答成自证清白 → 原因是没看出三问只是把二三层单独再问一遍 → 怎么改：把三问分别挂回状态与取舍、轨迹与断言、日志定位上，逐条准备。

:::figure 一次追问从第一层到收尾
@flow
先答是什么|讲清怎么做|拿出可复现证据|说清故障定位|四层答完收口
:::

图里第三环「拿出可复现证据」是分水岭：它之前靠讲，它之后靠平时留下的东西。把四层都预演过一遍，才不会在有限时间里被追到第三层就乱；整段讲述的节奏安排，见[15 分钟讲项目的节奏](./k126-project-pitch.md)；要讲的那件作品本身长什么样，见[三个能写进简历的项目](./k122-three-projects.md)。

:::quote
面试追的不是你记住多少名词，是「是什么 → 怎么做的 → 凭什么信 → 怎么定位」这条链能不能一层层走到底。断在哪层，就准备到哪层。
:::

## 五、自检清单

:::check 学完自检
- [ ] 能背出四层顺序，并解释为什么跳一层算断链
- [ ] 能把转行者三问分别挂回四层里的对应位置
- [ ] 第一层能只讲定义与边界，不抢着报技术名
- [ ] 第三层拿得出轨迹、断言这类能复现的证据
- [ ] 准备过一次构造故障，能按日志讲清定位到哪一步
:::

是什么：这是把面试追问看成四层连续决策链、并把转行者三问挂回链上的准备方法。
关键做法：逐层预演「是什么 / 怎么做的 / 凭什么信 / 怎么定位」，平时留好轨迹与断言，别等临场凑证据。
什么时候不该用：对方只做开放式闲聊、没有明确作品可追时，别硬套四层，顺着问题自然答即可。
