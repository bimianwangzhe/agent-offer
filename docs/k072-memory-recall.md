# 召回排序与相关性：别让记忆反过来污染本轮输入

## 场景：本轮只问了个时区，却把半个库都搬了进来

你写召回逻辑时图省事：凡是沾点边的记忆，全取回来一起塞进本轮输入。用户就问了一句「我这边现在几点」，结果输入里塞进了三个月前一条很旧的时区记录、两条内容一模一样的重复条目、还有一句刚存进去的「你好」。回答不但被那条旧记录带偏，可用的位置也被占得差不多，本轮真正要处理的材料反倒挤到了边上。你检查存储，条目都好好的；问题出在「取」这一步没筛、没排、也没限量。

## 先破一个最常见的误解

**不是取回越多越保险，是取回这个动作本身会反过来污染本轮输入。** 每一条被取回的记忆都要占一个位置，也都会被当成「现在该考虑的信息」参与判断。多带一条无关的，就少一个位置留给本轮真正要处理的材料；带进一条很旧又恰好字面相近的，模型很可能把它当成当前成立的前提。所以召回要做的不是「把相关的都找出来」，而是「只把少数几条最该用的摆上桌」：先按相关程度给候选打分，再按分排序，顺手去掉重复，最后用硬上限截断。这里的相关程度说的是「这条记忆跟本轮问题对得上多少」，时效说的是「这条有多新」，两者都是打分用的量，不是结论。把召回结果当结论直接用，和把候选名单当录取名单，是同一种错。

## 用生活里的事打个比方：只能带一张纸进考场

开卷考试允许带一张纸，不许带整本书。你会怎么准备？先把最可能考到的那几条挑出来，按重要程度从上往下写，重复的只留一遍，去年那版旧笔记要么不抄、要么标清楚别照着用，写到纸满为止。对应关系逐条对一遍：那张纸就是条数上限；「挑最可能考到的」就是按相关程度打分；「从上往下写」就是排序；「重复只留一遍」就是去重；「旧笔记别照着用」就是时效衰减；写满即止就是截断。为什么不能「多抄点总没坏处」？纸就一张，抄满了无关内容，真正要用的那条公式反而没地方写；更糟的是抄了一条过时的公式，考场上会直接算错。召回的处境一模一样：额度有限，且带进去的每一条都会被当真。

## 画出来看

先看本轮问题进来之后，候选是怎么被一层层收窄成少数几条的。

:::figure 从候选到带上桌的收窄过程
@flow
本轮问题|给候选打分|按分降序|去重并截断|带少量进上下文
:::

「去重并截断」放在排序之后，是因为先排好序，截断时才不会误把更相关的那条丢掉；而去重要在截断之前做完，否则有限的名额可能被同一条内容的两个副本白白占掉。再看两种取回方式的差别。

:::figure 两种取回方式的差别
@compare
全量取回::占满额度|噪声混入|重复条目还在
排序截断::只带少数|无关不进|按分可控
:::

右边那行「无关不进」不是排序自然带来的，得单独设一道最低相关度门槛：一点都对不上的候选，连打分的资格都不给。少了这道门槛，一条刚写进去、很新但毫无关系的寒暄，完全可能因为时效分高而挤进前几名。

## 再往下追两层

:::ask 追问一
那「越新越该带」这条，是不是可以当主要依据？
:::

不能当主要依据，只能当次要的修正量。纯按时间排，会出现一个很典型的结果：用户刚说了句「你好」，它被存成一条很新的记忆，本轮问的是时区，它却因为「新」被顶到前面；真正相关的那条时区事实反而被挤到后面甚至被截断掉。合理的次序是先看相关程度，相关得上的才进候选，时效只在候选内部做微调：两条都相关时，较新的略微占优。至于「相关」怎么算，可以用本轮问题里的关键词和记忆自带的标签对得上多少来衡量，实现见[长期记忆与向量化存储](./k068-long-term.md)里对相似度召回的讨论；本篇的重点是别让时效反客为主。

:::ask 追问二
那要是一条都对不上，是不是也该勉强凑一条出来？
:::

不该，硬凑比返回空更危险。要对不上，说明这一轮没有可用的记忆，正确做法是明确返回空、由上层按「不知道」或「按通用方式处理」来兜底；勉强挑一条字面最接近的塞进去，只会给一个本来没有依据的判断凭空造出依据。所以除了排序和截断，还得有一道门槛：相关度为零的候选直接排除，取回列表允许是空的。这条性质要写成断言钉住，而不是靠「应该不会那么巧」的侥幸。被取回的条目本身也可能过期、被标错或已被作废，那一层由[遗忘、过期与 TTL](./k073-forgetting.md)和[冲突消解与版本](./k071-conflict-resolution.md)负责；本篇只管「这些候选里本轮该带哪几条」。至于「全存下来为什么也不叫记忆」，可以回到[记忆不是日志](./k065-memory-vs-log.md)再对一遍。

## 一段能直接跑的代码

下面这段只用标准库，不联网、不装包、不需要账号，把「相关度打分 + 时效衰减 + 零相关排除 + 去重 + 硬上限截断」写成两个函数，用构造用例验证四条性质。复制成 `.py` 直接运行会打印取回结果。

```python
def score(item, query, now, half_life):
    """相关性用字面重合度；时效按半衰期衰减，都是确定性计算。"""
    overlap = len(set(item["tags"]) & set(query))
    if overlap == 0:
        return None                       # 无关记忆直接不进候选，避免污染
    relevance = overlap / max(len(set(query)), 1)
    age = max(now - item["stamp"], 0)
    freshness = 0.5 ** (age / half_life)
    return round(0.7 * relevance + 0.3 * freshness, 4)


def recall(items, query, now, top_k=3, half_life=100):
    seen, ranked = set(), []
    for it in items:
        if it["id"] in seen:
            continue
        seen.add(it["id"])
        s = score(it, query, now, half_life)
        if s is None:
            continue
        ranked.append((s, it))
    ranked.sort(key=lambda x: x[0], reverse=True)
    return [it["text"] for _, it in ranked[:top_k]]


if __name__ == '__main__':
    now = 1000
    items = [
        {"id": "M1", "tags": ["时区", "东八"], "text": "用户时区东八区", "stamp": 995},
        {"id": "M2", "tags": ["报告", "PDF"], "text": "报告导出为 PDF", "stamp": 990},
        {"id": "M1", "tags": ["时区", "东八"], "text": "重复：时区东八区", "stamp": 800},
        {"id": "M4", "tags": ["时区"], "text": "很旧的时区记录", "stamp": 100},
        {"id": "M5", "tags": ["寒暄"], "text": "你好", "stamp": 999},
    ]
    query = ["时区", "东八"]
    hits = recall(items, query, now, top_k=2)

    assert len(hits) <= 2                       # 条数硬上限
    assert "重复：时区东八区" not in hits        # 去重：同一 id 只留一条
    assert hits[0] == "用户时区东八区"          # 相关且新的排最前
    # 不相关项即便很新也进不来
    assert "你好" not in recall(items, query, now, top_k=3)
    print("取回：", hits)
    print("通过 4/4 项")
```

1. `score` 第一行算 `overlap`：把记忆自带的标签和本轮问题的关键词求交集，对得上几个就是几个。这是「相关程度」的一种最朴素、可复现的写法。
2. `if overlap == 0: return None`：这就是零相关门槛，一点都对不上的候选直接不进候选集，而不是给个低分混进来。返回空值也让调用方一眼能区分「没分」和「分很低」。
3. `relevance` 与 `freshness`：前者是命中数占问题关键词数的比例；后者用 `0.5 ** (age / half_life)` 做时效衰减——半衰期的白话是「每过这么长一段时间，新鲜度就减半」，`age` 越大这项越接近零。
4. `return round(0.7 * relevance + 0.3 * freshness, 4)`：相关占七成、时效占三成，刻意让时效只当微调，避免「很新但无关」反客为主。两个系数都是构造出来的确定性权重，不代表任何优劣结论。
5. `recall` 里 `seen` 先按 `id` 去重、`s is None` 再排除零相关、`ranked.sort` 按分降序、`ranked[:top_k]` 最后硬截断：四道收窄按顺序叠起来，正好对应示意图那条链。
6. 五条构造数据里故意放了一个重复 `id` 的副本、一条很旧的时区记录、一条很新却无关的寒暄；四条断言分别钉住「条数不超上限」「重复被去掉」「相关且新的排最前」「无关项进不来」，末尾 `print` 打出取回内容供核对。

## 踩过的坑与边界

- **全量取回一起塞进输入**：现象是额度被历史占满、回答被旧记录带偏 → 原因是把「找得到」当成了「都该带」 → 打分、排序、截断三步一步都不能省，且要有硬上限。
- **没有零相关门槛**：现象是问了个无关问题，助手搬出一条旧记忆强行作答 → 原因是最低相关度没设，硬凑出一条最像的 → 相关度为零直接排除，允许返回空，上层按「不知道」兜底。
- **重复条目占掉名额**：现象是同一条事实被存了两遍，取回时两个副本一起占位 → 原因是召回前没按标识去重 → 排序前先去重，别让有限名额被副本浪费。
- **纯按时间排序**：现象是刚存的一句寒暄挤掉了真正相关的时区事实 → 原因是把「新」当成了主要依据 → 相关为主、时效只做微调，且零相关不进候选。
- **把召回结果直接当结论**：现象是一条已过期或已被作废的记忆仍被当成当前事实 → 原因是没分清「候选」和「裁决后的有效值」 → 取回之后再过一遍裁决，见[冲突消解与版本](./k071-conflict-resolution.md)与[遗忘、过期与 TTL](./k073-forgetting.md)。

边界也讲清楚：排序截断是为「记忆条目已经攒出一定规模」准备的。库里就两三条时，全带上也占不了多少，硬套这套打分反而多一层调不动的权重。另外，分数只用来排先后，不用来证明一条记忆为真；真伪得靠来源、时间与裁决，见[写入判定：什么时候该记](./k070-write-decision.md)。

## 三句话小结

召回排序是按相关程度与时效给候选打分、排序、去重并限制条数，只把少数最该用的记忆带进本轮输入。
做法是相关为主、时效为辅，零相关直接排除并允许返回空，取回之后还要再过一遍裁决。
库里只有两三条、或需要完整复现全部历史时，不必套这套打分排序，全带上更直接。
