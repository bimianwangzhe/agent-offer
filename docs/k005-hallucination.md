# 幻觉为什么必然存在：它不是坏了，是接得太像真的

## 一、一个写得比真的还像真的示例

你让它"给这个库写一段示例，用它的批量接口"。它写得有鼻子有眼：函数名、参数顺序、返回值、连一句"注意先初始化客户端"都齐了，读起来跟一份正经示例没两样。你复制去跑，报了个不存在的属性错误——那个批量接口压根没有。你追问"你确定有这个函数吗"，它立刻道歉，改口说"抱歉，该库并未提供"；你再问一次，它又给你换了个同样不存在的名字。

最让人不解的不是它编了，是它明明不知道，为什么还敢写得那么笃定，而且被戳穿之后既不真的去查、也不真的记住。

## 二、先破误解

**不是模型坏了，也不是它"知道却说谎"，是它被训练成"把文字接得像真的"，而"真不真"根本不在它的职责范围内。**

幻觉（hallucination，指生成出看似合理、实际并不成立的内容）这个词容易让人以为是偶发故障，好像调一调就能修好。可只要接上[下一个词预测](./k002-next-token.md)那一步，就会发现它是顺着机制必然流出来的。每一步，模型选的是"这片接在这里最像有人会这么写"，不是"这片我核对过"。当问题落在"某个库的某个函数怎么用"上时，"顺着命名习惯补出一个函数名"在语言上太顺了：见过大量示例代码的人都知道，批量接口大概长什么样、参数大概怎么排、注意事项大概怎么收尾。相比之下，"承认自己不知道"在续写里反而是个不常见的转弯。于是前者被选中的机会天然更高。

关键在于，"像真的"和"是真的"是两套完全不同的评价标准，而模型只被前者训练过。它没有一份可以翻的清单，没有一个能去查的动作，甚至没有"我此刻不确定"这个可靠信号。你追问"确定吗"，那不是让它回看自己的过程，而是开了一轮新的续写：它以"有人被质疑后会怎么答"为起点往下接，接出一段得体的道歉，或者接出一段更笃定的补充，两种都只是又一段顺文。这正好解释了开头那次"道歉完又换个名字编"——它既没认错，也没改正，它只是又写了两段都很像的话。

所以能给出的工程结论只有一句：**真实性必须由系统外部补上**。模型负责把话说顺，系统负责把话坐实——靠一份可信的事实清单、一次真正去取数的动作、一段能指回来源的出处。这也和[采样参数与不确定性](./k004-sampling.md)里那句"参数不是约束"同源：想让"不许编"生效，得写在能强制判定的地方，不能写进一句可以被概率盖过去的话里。

:::tip
模型把话接得像真的，是它尽责完成了本职工作；真不真，得由外面那层来回答。
:::

## 三、生活类比：一位从没去过、却极会写游记的代笔

请一位从没去过那座城、但读过上千本游记的人，替你写一段"我去年在那座城的见闻"。他不会去查地图，也不会说"我没去过"——他太熟悉游记该长什么样了：先写抵达那天的天气，再写一条老街，顺手报一个听起来很地道的巷子名，末了来一句感慨。那条巷子名是他按"老街该配个什么名字"顺出来的，读起来可能比真游记还像真游记。

你若拿着地图问他"这条巷子真在吗"，他也只会顺着"有人被追问时会怎么答"再写一句：可能是笃定地补上"就在钟楼后面"，也可能是一句得体的"抱歉我记混了"。两种都是又一段顺文，不是查证。对应关系可以这样摆：

- 读过的上千本游记，是训练时见过的文本；
- "游记该有的样子"，是语言里的搭配规律；
- 顺出来的巷子名，是凭空生成却很像的实体；
- 不去查地图，是没有外部事实来源；
- 追问后的补充或道歉，是又一轮续写，不是自证；
- 你手里的地图与档案，是系统外部那份可信事实表。

这个类比最该带走的是最后一行的位置：判真假的东西在人外面，不在人嘴里。你不会指望代笔自己声明"我编的"，你会拿地图去对。同样地，别把"请别编""不确定就说不知道"当成验真手段——那只是往原文里加了一句影响接续的话，地图仍然没被翻开。

## 四、画出来：一个"像真的"说法怎么冒出来

先看从问题到那段笃定文字的路径，中间有没有一道核对：

:::figure 一个像真的说法是怎么冒出来的
@flow
收到问题|按语境续写|拼出合习惯的实体|读起来通顺|未必成立
:::

五个节点里，从头到尾没有"查一下"这一环。第三步"拼出合习惯的实体"是全流程最顺的一步，也正是凭空内容诞生的地方；第四步"读起来通顺"是模型真正被要求的标准，第五步"未必成立"则是这个标准管不到的事。链子缺了哪一环，比链子有多顺更要紧。

再把两种"让它别编"的做法摆在一起：

:::figure 两种让它别编的差别
@compare
只加一句提示::更可能不编|仍不是保证|没有核对依据
外接事实核验::草稿先过表|未证实就拦|真假由外部定
:::

左边那行并非全无用处，它确实能把"编"的概率压低一点，问题是它给不出判真假的依据，也无法在编了之后拦住。右边那行把判定权挪到了外面：草稿先过一张表，表里查不到的就明确拦下。两张图叠起来，结论很清楚——幻觉不是靠"提醒"消除的，是靠"外面有个能对账的东西"兜住的。

## 五、顺着追问两层

:::ask 那如果我在提示里写"不确定就说不知道"，是不是就能挡住？
:::

只能压低，不能挡住。这句话的作用是让"说不知道"这条接续的概率抬高一点，可它仍是概率：一旦遇到模型"觉得"十分顺的实体，那条顺路照样会被选中。更根本的是，"我是不是不确定"这件事，模型本身没有可靠依据——它没有一个能翻的清单，也就无从判断自己此刻究竟知不知道。于是"不确定就说不知道"常常变成一句漂亮的自我要求，落地时既不触发、也无从验证。这也是为什么[下一个词预测](./k002-next-token.md)里那句"改的是分数，不是开关"值得反复念：写在文字里的请求，改的是分数。

:::ask 那如果接一个真能查证的工具，是不是就万无一失了？
:::

方向对了，但别急着宣布万无一失。把真实性从模型挪到外部，确实是把判定权放对了地方，可要守住三处。第一，那份外部清单或那个查证动作本身得可信、还得覆盖到被问到的东西；表里没有的实体，再合理的草稿也只能判"未证实"。第二，核验结果得真能拦住输出，而不是只当个"参考意见"摆在旁边——草稿若照样原样发出，那道核验等于没接。第三，得说清判真假的是谁：下面这段代码会让你看到，同一段草稿，只要往事实表里补一条，就能从"拦截"变成"通过"，草稿一个字没改。换句话说，真假是那张表定的，不是模型定的。至于查回来的结果以什么身份回传、放在这一轮拼装的哪个位置，那是[消息角色与对话拼装](./k007-message-roles.md)要处理的分工。整套思路从哪起步，可以看[从这里开始](./00-start-here.md)。

## 六、跑一段代码，把"外部兜底"摸实

下面这段只用标准库，不联网、不装包、不要账号。它用一个续写桩造出一段很像真的草稿，再用一张外部事实表去核验，看未证实的内容会不会被拦下。所有内容都是构造出来的场景，不含任何真实资料。

```python
import re

# 外部事实表：只有登记在这里的实体才算"有据"。
FACT_TABLE = {
    "北京": "直辖市",
    "上海": "直辖市",
    "杭州": "省会",
}
CLAIM_RE = re.compile(r"([\u4e00-\u9fff]{2,4})建城于(\d{4})年")


def continue_like_model(prefix):
    """续写桩：只按语言习惯往下接，完全不查事实表。"""
    return prefix + " 云栖城建城于1314年。"


def has_support(city, fact_table):
    """外部核验：这个说法有没有事实表支撑。"""
    return city in fact_table


def guarded_answer(prefix, fact_table):
    draft = continue_like_model(prefix)
    m = CLAIM_RE.search(draft)
    if not m:
        return draft, True
    city = m.group(1)
    if has_support(city, fact_table):
        return draft, True
    return "已拦截：草稿含无法核对的实体「%s」" % city, False


if __name__ == '__main__':
    checks = 0
    prefix = "介绍几座城市"

    # 1) 桩照样能编出具体年份，读起来很像真的
    draft = continue_like_model(prefix)
    assert "1314年" in draft and "云栖城" in draft
    checks += 1

    # 2) 模型自己不会标注"我不确定"
    assert "不确定" not in draft and "无法核对" not in draft
    checks += 1

    # 3) 外部核验能从草稿里抽出被凭空造出的实体
    m = CLAIM_RE.search(draft)
    assert m is not None and m.group(1) == "云栖城"
    checks += 1

    # 4) 该实体不在事实表里 -> 判为未证实
    assert "云栖城" not in FACT_TABLE
    checks += 1

    # 5) 接了核验器后，未证实草稿不会原样采信
    out, ok = guarded_answer(prefix, FACT_TABLE)
    assert ok is False and out.startswith("已拦截")
    checks += 1

    # 6) 同一段草稿，只要外部事实表补上该实体，就能通过
    backed = dict(FACT_TABLE)
    backed["云栖城"] = "有据"
    out2, ok2 = guarded_answer(prefix, backed)
    assert ok2 is True and out2 == draft
    checks += 1

    print("通过 %d/%d 项" % (checks, 6))
```

逐段看它在做什么：

1. `FACT_TABLE` 是那张"地图"，只有登记在里面的实体算有据；`CLAIM_RE` 是一条正则（用来按模式找文本的工具），负责从草稿里抽出"某某建城于某年"这类具体说法。二者都在模型外面。
2. `continue_like_model` 是续写桩：只管把话接顺，`prefix` 后面补一个地名和年份，完全不查表。它对应流程图里第三步"拼出合习惯的实体"。
3. `has_support` 只做一件事——拿抽出的实体去事实表里查在不在。判真假的依据全在这一行，模型没参与。
4. `guarded_answer` 把两半接起来：先出草稿，抽出说法，查得到就放行、查不到就返回"已拦截"并给出 `False`。注意它不修改草稿，也不指望草稿自己改口，而是由外面这层决定采不采信。
5. 断言一、二钉住现象：桩照样能编出具体年份（很像真的），而且不会自己标注"我不确定"。断言三、四确认核验能抽出那个实体、且它确实不在表里。
6. 断言五验证拦截生效；断言六最值得琢磨——把该实体补进事实表后，同一段草稿原封不动就通过了。草稿没变，变的是外面那张表，这正说明判真假的是外部依据。

要守住一条边界：这里所有地名、年份、表项都是为演示现编的，不代表任何真实资料，也不构成对任何系统的结论。它只演示机制。顺带也能看出，核验的质量完全取决于那张表可不可信、全不全——表里缺一条，合理的东西也会被拦；表里混进一条错的，胡编的东西也会放行。这正是把真实性外置之后，该由工程去维护的那部分。

## 七、踩坑与边界

- **把幻觉当偶发故障去调参**：现象是调了温度、换了说法，照样编 → 原因是它是机制的自然结果，不是随机抖动 → 接受它会发生，把力气花在外部核验上。
- **靠"请别编"当约束**：现象是提示写得很硬，仍冒出不存在的名字 → 原因是那只是抬高概率的一句话 → 改成草稿过表、未证实就拦的代码路径。
- **让模型自证**：现象是追问"确定吗"得到一段笃定补充或得体道歉，之后照编 → 原因是追问只开了新一轮续写 → 用事实表、查证动作或出处去核，别用自述。
- **接了核验却没真拦**：现象是核验结果摆在一旁，草稿照样原样发出 → 原因是核验没进入放行判定 → 让核验的返回值直接决定采信、重做还是降级。
- **外部表没人维护**：现象是该拦的没拦、不该拦的拦了 → 原因是表本身缺项或混入了错误 → 给表定来源、版本与更新规则，把"表里有什么"当真数据来管。

## 九、三句话小结

幻觉是模型把话接得太像真的的必然结果，真不真不在它的职责范围内。
要紧的做法是在系统外面备一份可信依据，让草稿先过核对、未证实就拦，而不是靠一句提醒。
当你需要能打包票的事实、或需要可核对的出处时，别把模型的顺文当答案，用外部依据去定真假。
