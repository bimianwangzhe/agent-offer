# Trace / Span / TraceId 与日志脱敏

## 一、场景提问

一个任务报错了，你去翻日志，发现同一次请求留下的记录散在好几个地方：入口服务有一行「收到请求」，工具服务有一行「参数校验失败」，模型调用那边又有一行「超时重试」。三行都带着时间戳，可你没法确定它们到底是不是同一次任务——几个请求几乎同时进来，时间挨得极近。更糟的是，为了「方便排查」，有人把用户输入原样打进了日志，里面带着联系号和证件号；现在这批日志要导出给另一个团队分析，谁都不敢直接给。你既需要把散落的步骤串成一条能回溯的链，又得保证链上不挂着不该留的东西，可这两件事看着是互相拧着的：记得越细越好查，也越容易漏出去。

## 二、破误解

**不是给每条日志编个号就能串起来，也不是「展示的时候把敏感字段遮一下」就算脱敏；前者要靠一个贯穿全程的追踪标识和明确的父子片段，后者必须在写进日志之前就把内容处理干净。**

先把三个词说清，它们管的是三个不同尺度。Trace（追踪，一次任务从发起到结束的完整过程，是一条由许多步骤组成的链）回答「这一整趟是什么」；Span（片段，追踪里一段有明确起止的操作单元，比如一次工具调用、一次模型请求、一次重试）回答「其中某一小段做了什么、花了多久」；TraceId（追踪标识，同一次任务里所有片段共享的那个唯一编号）回答「这些散落各处的记录凭什么算同一趟」。三者是「一条链 / 链上的段 / 把段串起来的号」，缺一样都会出问题：只有一堆日志行没有 TraceId，并发一来就串味；有 TraceId 却不分 Span，能查到「这次任务失败了」，却定位不到是哪一步慢、哪一步错；分了 Span 却不记父片段标识，嵌套的调用就摊成一张平表，看不出「这次重试属于哪次工具调用」。

再说明脱敏（Redaction，把日志里的敏感内容在落盘前替换或删掉）为什么必须是「写入前」而不是「读取时」。日志一旦写下去，就会被复制到备份、导出、检索索引、排查截图里；展示界面上打个星号，只挡住了那一处视图，底下的原文还在，任何一条旁路都能读到。所以脱敏的落点在「事件产生的当场」，而且得覆盖所有写入口：用户输入、工具返回、报错堆栈、模型自己复述出来的内容，一个都不能漏。这里有个真实的张力：脱敏太狠，把订单号、参数值、时间全遮了，轨迹就没法排查；脱敏太松，等于没做。分寸在于分级——能标识「哪一笔」的非敏感编号保留，能直接对应到个人的信息替换成占位，需要比对「两次输入是否相同」时用定长指纹而不是原文。字段层面该记哪些由 [Trace 该记什么](./k094-trace-fields.md) 定，用什么形式逐行写、怎么按序拼回是 [结构化日志与轨迹回放](./k095-structured-log.md) 的事，这一篇专门管「层级怎么串」和「写入前怎么遮」。

## 三、生活类比

把它想成一次住院就诊。你挂号时拿到一个病历号，从看诊、验血、拍片到取药，每一项单据上都印着同一个号；医生开的每一张检查单还有自己的单号，写明「属于哪次就诊、由哪个科室开的、几点开始几点出结果」，拍片里若又分了「拍片」和「阅片」两道手续，阅片单还会挂在拍片单下面。最后归档时，病历上把身份证号、联系电话打码，只留下诊断必需的信息——而且是在归档那一刻就打码，不是等以后有人来调阅时才临时拿纸盖住。

对应关系很具体。「病历号」是 TraceId，跨科室、跨环节都原样带着，凭它把散落的单据归成同一次就诊；「一次就诊的全过程」是 Trace；「每张检查单」是 Span，有起止、有归属、有执行方；「阅片挂在拍片下面」是父片段标识带来的层级；「归档前打码」正是写入前脱敏。这个类比还点出两处要害。第一，打码不能把「诊断结论、用了什么药、哪一项异常」也一起涂掉，否则病历就没用了——脱敏要保住可排查性，只遮能定位到个人的部分。第二，如果各科室各编各的号、不沿用挂号时那个病历号，月底想拼出「这位患者这趟到底做了什么」根本不可能，只会得到一堆互不相关的单子。

再补一层：病历号还得是唯一且稳定的。两位患者拿到同一个号，两人的检查结果会混在一起；同一个人复诊却换了个不相干的号，前后的记录又接不上。放到系统里就是「标识要全局唯一、且在同一条链路里原样传递」，这正是后面要展开的部分。

## 四、自绘示意图

:::figure 一次请求从入口到归档的追踪链
@flow
入口生成标识|层层向下传递|各步开片段|写入前脱敏|归档可按号回溯
:::

五格里最容易被省掉的是「层层向下传递」。标识只在入口生成一次，下游服务、异步任务、子进程都得沿用同一个，谁自己另起一个，这条链就从那里断开。「写入前脱敏」被放在归档之前而不是之后，是刻意的位置：一旦归档，内容就开始被复制，再想补救已经晚了。

:::figure 一个片段该带与不该带的
@stack
追踪标识::同一次任务全程共享，跨进程原样传递
片段标识::这一段自己的唯一编号，供别人挂到它下面
父片段标识::指出谁包含自己，空值表示这是根片段
名称与类别::可枚举的动作名，便于聚合与筛选
起止与耗时::用单调序号或时刻记下开始与结束
脱敏标记与载荷::写明是否已处理，载荷只留非敏感内容
:::

六行里「父片段标识」是层级的来源：有了它，平铺的记录能还原成一棵树，才看得出「重试属于哪次调用」。「脱敏标记」让读日志的人一眼知道这条能不能放心打开，它不是权限控制本身，真正的拦截要落在 [代码内护栏](./k106-guardrail-in-code.md)。「起止与耗时」用单调序号而不是墙上时间，是因为并发时多个片段可能挤在同一秒，靠时间戳排不出先后，这一点和 [结构化日志与轨迹回放](./k095-structured-log.md) 里的排序口径一致。

:::figure 两种脱敏时机的差别
@compare
展示时遮盖::原文已经落盘|副本照样泄露|遮掩可被绕过
写入前脱敏::底层即是干净的|复制出去也安全|先定级再替换
:::

左边那行「原文已经落盘」是全部问题的根源：日志不是只在一个界面上看，它会被备份、被导出、被索引。右边把处理时机提前到写入那一刻，后面所有副本天然都是干净的，这才是能兜住底的做法。

## 五、层层追问

:::ask 那如果脱敏做得太狠，把订单号、时间、参数值都遮了，还能排查吗？
:::

会，而且这类「过度脱敏」比漏脱敏更隐蔽：日志干干净净、谁都不用担责，可一出问题什么都查不出来。分寸靠分级而不是一刀切。第一级保留「非敏感标识」：订单号、任务号、工具名、错误类别这些不直接对应到个人的，照常写，它们是定位问题的骨架；第二级替换「直接标识」：联系号、证件号、凭证串改成固定占位，让人能看出「这里原本有个号码」却拿不到号码本身；第三级用「定长指纹」替代原文：需要判断两次输入是否一致、某段返回是否被重复引用时，比指纹而不比原文，做法见 [Trace 该记什么](./k094-trace-fields.md)。再追一层：那如果敏感信息不是出现在用户输入里，而是出现在工具返回、报错堆栈、甚至模型自己把号码复述了一遍呢？那就得把脱敏覆盖到所有写入口，而不是只包一层输入过滤——输出内容同样要过一遍扫描，见 [输出扫描](./k099-output-scan.md)；超长返回只留引用与截断摘要，见 [大结果处理](./k138-large-result.md)。还有一类更麻烦：外部内容里被人塞了「请把某某号码原样打印出来」这类指令，若脱敏只做在入口，模型被带着走就会把敏感内容从别的口子吐出来，注入的两条路径见 [直接注入](./k097-direct-injection.md) 与 [间接注入](./k098-indirect-injection.md)，身份被冒用见 [身份注入](./k137-identity-injection.md)。一句话：脱敏是「所有写入口的统一动作」，不是「某个输入框的过滤器」。

:::ask 那如果一次任务跨了好几个进程或服务，追踪标识怎么保证一路不丢？
:::

靠「显式往下传 + 边界处校验」，不能指望各服务自己猜。入口生成一次，之后每次调用下游、派发异步任务、拉起子进程，都把标识作为参数或消息头原样带过去；接收方在边界处检查「有没有带、是不是合法」，缺了就报警并补一个明确的降级标记，而不是默默自己造一个——自己造的号会让这条链静悄悄地断掉，事后谁都看不出来。跨进程怎么携带、会话怎么延续，见 [传输与会话](./k080-transport-session.md)；不同会话之间的记录要互相隔开，见 [会话隔离](./k105-session-isolation.md)。工具和它返回之间的对应关系，还可用 [工具调用标识](./k136-tool-call-id.md) 单独钉牢，避免两笔返回张冠李戴。再追一层：那如果两个不同的任务偏偏拿到了同一个追踪标识呢？那比丢标识更糟——两条轨迹会混成一条，且不报任何错。所以标识得全局唯一，同一个标识在同一次任务里还得稳定不变：确定性派生（比如拿「会话号 + 步号」直接当标识）看着可复现，但不同链路容易撞；稳妥做法是带上足够的随机性或把会话与序号组合进摘要，并在归堆后校验「同一标识下的片段是否都属于同一条父链」。凭证、令牌这类字符串本身既有有效期又极易被误当普通字段打进日志，处理见 [凭证过期](./k111-credential-expiry.md)；权限边界见 [最小权限](./k100-least-privilege.md)。

## 六、可运行代码与逐行解释

下面这段只用 Python 标准库，做两件事：造一棵带父子关系的片段树，验证「标识贯穿、父子可还原、孤儿能被发现、按标识归堆不串」；再实现一组写入前脱敏规则，验证「敏感串确实没落盘、非敏感信息保留、脱敏幂等、读时遮盖救不了已经落盘的原文」。标识由哈希摘要确定性生成，数据全是构造的，复制到任意装有 Python 的机器上直接运行即可，不需要第三方包、账号或网络。

```python
import json
import re
import hashlib
from dataclasses import dataclass, field, asdict
from collections import defaultdict

RULES = [
    (re.compile(r"sk-[A-Za-z0-9]{6,}"), "<凭证>"),
    (re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)"), "<证件号>"),
    (re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)"), "<手机号>"),
]


def redact(text):
    """写入前脱敏：按规则把直接标识换成固定占位，其余原样保留。"""
    for pat, tag in RULES:
        text = pat.sub(tag, text)
    return text


def make_id(seed):
    """用 SHA-256 摘要把任意文本压成定长、可复现的短标识。"""
    return hashlib.sha256(seed.encode("utf-8")).hexdigest()[:8]


@dataclass
class Span:
    trace_id: str
    span_id: str
    parent_id: str
    name: str
    start: int
    end: int
    redacted: bool = False
    attrs: dict = field(default_factory=dict)


class Tracer:
    """生成一条追踪树：标识只在入口造一次，子片段一律沿用。"""

    def __init__(self, trace_id):
        self.trace_id = trace_id
        self.spans = []
        self._n = 0
        self._clock = 0

    def _tick(self):
        self._clock += 1
        return self._clock

    def start(self, name, parent_id="", raw=""):
        self._n += 1
        sid = make_id(self.trace_id + "/" + name + "/" + str(self._n))
        clean = redact(raw)
        sp = Span(self.trace_id, sid, parent_id, name, self._tick(), 0,
                  redacted=(clean != raw),
                  {"input": clean} if raw else {})
        self.spans.append(sp)
        return sp

    def end(self, sp):
        sp.end = self._tick()
        return sp


def orphan_ids(spans):
    """找出父片段标识指向不存在编号的孤儿片段。"""
    ids = {s.span_id for s in spans}
    return [s.span_id for s in spans if s.parent_id and s.parent_id not in ids]


def group_by_trace(spans):
    g = defaultdict(list)
    for s in spans:
        g[s.trace_id].append(s)
    return dict(g)


def build_tree():
    raw = "用户 13800000000 证件 11010119900101123X 凭证 sk-abc123def 查订单 A1024"
    t = Tracer("tr-" + make_id("session-7"))
    root = t.start("handle", raw=raw)
    plan = t.start("plan", root.span_id)
    call = t.start("tool_call", root.span_id)
    retry = t.start("retry", call.span_id)
    t.end(retry)
    t.end(call)
    t.end(plan)
    answer = t.start("answer", root.span_id, raw="订单 A1024 已发货，联系 13900000000")
    t.end(answer)
    t.end(root)
    return t, raw


def main():
    t, raw = build_tree()
    spans = t.spans
    root = spans[0]

    other = Tracer("tr-" + make_id("session-9"))
    other_root = other.start("handle")
    other.end(other_root)

    checks = [
        ("标识可复现且不同输入不撞", make_id("x") == make_id("x")
         and make_id("x") != make_id("y")),
        ("联系号没有落进载荷", "13800000000" not in root.attrs["input"]),
        ("证件号没有落进载荷", "11010119900101123X" not in root.attrs["input"]),
        ("凭证串没有落进载荷", "sk-abc123def" not in root.attrs["input"]),
        ("非敏感的订单号被保留", "A1024" in root.attrs["input"]),
        ("脱敏幂等", redact(redact(raw)) == redact(raw)),
        ("发生过脱敏的片段带标记", root.redacted is True),
        ("没传原文的片段不带标记", spans[1].redacted is False),
        ("读时遮盖救不了已落盘的原文",
         "13800000000" in raw and "13800000000" not in redact(raw)),
        ("同一追踪树共享同一个标识",
         all(s.trace_id == t.trace_id for s in spans)),
        ("片段编号在树内唯一", len({s.span_id for s in spans}) == len(spans)),
        ("没有孤儿片段", orphan_ids(spans) == []),
        ("插入孤儿能被检查发现", len(
            orphan_ids(spans + [Span(t.trace_id, "ghost", "no-such-parent",
                                     "ghost", 1, 2)])) == 1),
        ("片段都有起止且结束晚于开始",
         all(s.end > s.start for s in spans)),
        ("按追踪标识归堆后两条任务不串",
         len(group_by_trace(spans + other.spans)) == 2),
        ("整棵树可序列化留痕", json.loads(json.dumps(
            [asdict(s) for s in spans])) == [asdict(s) for s in spans]),
    ]

    passed = sum(1 for _, ok in checks if ok)
    for name, ok in checks:
        print(("通过 " if ok else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `RULES` 是三条脱敏规则，用标准库 `re` 编译好：凭证串、十八位证件号、十一位联系号各对应一个固定占位。两侧的数字边界 `(?<!\d)` 与 `(?!\d)` 是刻意加的，避免长数字串被短规则从中间误匹配。
2. `redact` 逐条替换，其余内容原样保留。它就是「写入前」那个动作本身——注意它返回的是已经干净的字符串，调用方拿到的从来不是原文。
3. `make_id` 用 `hashlib.sha256` 把种子压成八位十六进制短标识。SHA-256 是一种把任意长度文本映射成定长摘要的算法，同样输入必得同样输出，因此标识可复现、可手工核对，又不会把会话原文带进标识里。
4. `Span` 用 `dataclasses` 定义一段片段：`trace_id` 是全程共享的追踪标识，`span_id` 是这一段自己的编号，`parent_id` 指出谁包含它（空串表示根），`start` / `end` 是逻辑起止，`redacted` 是脱敏标记，`attrs` 只装载荷。父标识这一列就是层级能还原出来的全部依据。
5. `Tracer` 是造树的工具。`trace_id` 只在 `__init__` 里给一次，之后每个 `start` 都沿用同一个，绝不重新生成；`_tick` 用单调自增的逻辑时钟记起止，避开墙上时间精度不够的问题；`start` 里先把 `raw` 交给 `redact`，再决定 `redacted` 标记和载荷内容——原文在进 `Span` 之前就已经被处理掉了。
6. `build_tree` 造一棵五节点的树：根是 `handle`，下面挂 `plan`、`tool_call`、`answer`，`tool_call` 下面再挂一个 `retry`。这个嵌套正是「重试属于哪次调用」的答案；另有 `other` 用不同标识造第二条任务，用来验证归堆不会串。
7. `orphan_ids` 收集所有「父标识指向不存在编号」的片段，`group_by_trace` 按标识归堆。前者是层级完整性检查，后者是并发不串味的检查，两者都是读日志那一侧该做的校验。
8. `checks` 十六条断言分四组：标识确定性与不撞；三类敏感串确实没进载荷、非敏感订单号保留、脱敏幂等、标记正确；层级性质（共享标识、编号唯一、无孤儿、能抓到故意插入的孤儿、起止合法、两条任务分成两堆）；以及「读时遮盖救不了已落盘原文」这条对照和整树可序列化留痕。结尾 `assert` 保证任何一条性质被破坏都会以非零状态退出。

有一处要如实说明：这里的脱敏规则只覆盖了三种构造出来的串，用固定占位代替了真实分级策略，用内存列表代替了跨进程传递与持久化，全是为了让「标识贯穿、父子可还原、写入前遮干净」这条链路不需要联网、账号或第三方包就能独立跑通并手工核对。它演示的是层级结构与脱敏时机的关系，不是任何具体日志组件或合规方案的实现。

## 七、踩坑与边界

- **各服务各编各的号**：现象是同一次请求的记录分散在几处、拼不到一起，并发时还互相串 → 原因是追踪标识只在入口有、往下传时丢了 → 入口生成一次，跨进程、异步、子进程原样传递，边界处校验缺失即报警，见 [传输与会话](./k080-transport-session.md)。
- **只记平表不记父片段**：现象是能查到「这次失败了」，却看不出哪一步慢、哪次重试属于哪次调用 → 原因是片段之间没有父子关系 → 每段带上父片段标识，让平铺记录能还原成树，回放与检查点见 [检查点与重放](./k030-checkpoint-replay.md)。
- **展示时才打星号**：现象是界面上看着干净，导出的文件、备份、检索索引里原文全在 → 原因是脱敏做在了读取侧，而日志早被复制到多处 → 把处理提前到写入当刻，覆盖输入、返回、报错与模型复述所有写入口，输出侧见 [输出扫描](./k099-output-scan.md)。
- **一刀切全遮掉**：现象是日志谁都能看，可出了问题什么都查不出来 → 原因是把非敏感标识也一起涂了 → 分级处理：编号、工具名、错误类别保留，直接标识替换，需比对时用定长指纹，隐私边界见 [记忆与隐私](./k074-memory-privacy.md)。
- **脱敏标记被当成护栏**：现象是日志里明明记了「已脱敏」，越权与注入照样发生 → 原因是把一条描述性字段误当成了拦截动作 → 标记只说明「这条能不能放心读」，真正的拦截落在 [代码内护栏](./k106-guardrail-in-code.md) 与 [最小权限](./k100-least-privilege.md)。

还要划清两条边界。第一，层级结构解决的是「散落的记录怎么串、怎么定位到某一段」，它不负责「这一段该记哪些字段」——那是 [Trace 该记什么](./k094-trace-fields.md) 的事，也不负责「怎么按序拼回整条轨迹」——那是 [结构化日志与轨迹回放](./k095-structured-log.md) 的事；三者叠起来，才支撑 [结果评测与轨迹评测](./k089-trajectory-eval.md) 里对过程是否合理的判断。第二，脱敏是隐私侧的动作，不是安全侧的全部：它防的是「不该留的留下来了」，防不住「该挡的动作没挡住」，后者要靠权限、沙箱与人工确认，见 [最小权限](./k100-least-privilege.md) 与 [人在回路与高风险确认](./k102-human-in-loop.md)。而标识本身若被两个任务复用，前面所有校验都会失效，所以「唯一且稳定」永远是第一位的。

## 九、三句话小结

Trace / Span / TraceId 与日志脱敏，是用一个贯穿全程的追踪标识把散落的步骤串成带父子关系的树，同时在写入日志之前就把敏感内容分级处理干净。

关键做法是标识只在入口生成一次并层层原样下传、每个片段记下父标识与逻辑起止、归堆后校验孤儿与是否串味，脱敏覆盖所有写入口且保留非敏感骨架与定长指纹。

当任务只跑在单个进程里、既无并发也无嵌套、且输入完全不含敏感信息时，不必硬套这套层级与分级；但只要记录会跨环节分散、或内容会被复制到别处，缺了标识与写入前脱敏就一定会出事。
