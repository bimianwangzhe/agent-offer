# 大模型到底在干什么

先问一个几乎所有新手都遇到过、但很少有人认真想过的问题：

**你让它写一个库里的函数，它写得有模有样，你一跑——`AttributeError`，那个函数压根不存在。它为什么能编得这么像真的？**

常见的解释是「模型产生了幻觉」。但「幻觉」只是给现象起了个名字，没告诉你原因，更没告诉你该怎么防。这一篇我们把这件事彻底拆开，你会发现后面所有工程手段——输出校验、上下文工程、工具调用、评测——都是从同一个源头推出来的。

## 一、先破误解：它不在查资料，也不在「思考」

很多人心里有个隐含画面：模型背后连着一个巨大的知识库，你问一句，它去库里检索，找到答案，整理一下返回给你。

**这个画面是错的**，而且会让你后面每一步判断都错。

真实情况是：模型在做一件极其单调的事——**给它一段已经写好的文字，它猜下一个最可能接上的字（准确说是 token），把猜出来的字补到末尾，然后再猜下一个，如此反复，直到它猜出一个「该停了」的字。**

:::figure 一次回答，其实是同一件事重复了几百遍
@cycle
已有文字|猜下一个词|补到末尾|再猜下一个
:::

就像手机输入法的联想，只不过它读过的内容多得多，联想能力也强得多。你打「今天天气」，输入法给「真好」；模型给「真好，适合出去走走」——**机制是一样的，只是规模不同**。

:::ask 顺着这个画面想一步
如果它只是在「接着往下写」，那当你问「xx 库的 yy 函数怎么用」时，它并没有去翻文档，它只是在续写一段「看起来最像『有人在用这个库』的文字」。那么它编出一个不存在的函数，是意外吗？
:::

不是意外，**是必然**。因为「编一个符合命名习惯的函数名」在概率上比「承认自己不知道」更顺畅。它没有被训练成「不知道就说不知道」，它被训练成「把文字接得像真的」。

:::quote
幻觉不是模型坏了，是模型**太尽责地完成了它的本职工作**：把话接得像真的。至于真不真，不在它的职责范围内。
:::

这句话直接给出工程结论：**真实性必须由你在系统里补上**，靠模型自觉是不可能的。后面讲的工具调用、检索增强、输出校验，本质都是在给这个「续写机器」外接一个事实来源。

## 二、从「猜词」推出四件事

一旦接受这个机制，很多原本要背的概念就都能自己推出来了。

### 1. 为什么有「上下文长度」限制

模型每次猜下一个词，都要把**前面所有文字**重新读一遍。这段文字就是上下文（context）。读得越长，计算越贵、越慢，而且注意力会被摊薄。所以每次调用都有长度上限，超了要么截断、要么报错。

:::figure 上下文就是「模型这一眼能看到的东西」
@stack
系统提示::你是谁、能干什么、不许干什么，每轮都要带上
历史对话::前面聊过什么，越积越长
工具清单::这轮可以选哪些动作
工具结果::刚查回来的真实数据
用户当前问题::这一次要处理的事
:::

注意这五块是**拼在一起一次性塞进去的**，不是分五个字段传的。这解释了一个非常常见的新手 bug：聊了二十轮之后突然变笨、变慢、开始胡说——不是模型退化了，是**前面塞的东西太多，把当前问题挤到边缘了**。

### 2. 为什么按 Token 计费

既然计算量取决于「读了多少 + 写了多少」，那按字数收费就是自然的。输入和输出都算钱，而且**输出通常更贵**。

这里有个反直觉但很实用的结论：

:::tip 省钱的第一招不是换便宜模型
是**别把没用的东西塞进上下文**。很多系统每一轮都把完整历史、全部工具说明、整份文档重发一遍，成本是白白翻倍的。怎么裁剪、怎么压缩，是后面[上下文工程](./07-context.md)整篇要解决的问题。
:::

### 3. 为什么同一个问题，两次答案不一样

猜词是按概率挑的。如果挑的时候留了一点随机性（这个旋钮常叫「温度」），同一段前缀就可能走出不同的续写。温度调到 0，会稳定很多，但**不是绝对确定**，因为底层计算本身也有浮点误差和调度差异。

工程上要接受一个前提：

:::warn 别拿确定性断言去测非确定性输出
「断言输出等于某句话」的单元测试在这里必然是脆的。要测的是**结构、约束和性质**：是不是合法 JSON、必填字段在不在、有没有超出允许的取值范围、有没有引用不存在的编号。具体怎么写，见[评测](./11-eval.md)。
:::

### 4. 提示词为什么有用

提示词不是「给模型下命令」，更像是**给续写定开头**。你写「你是一个严谨的审计助手，只依据给定材料回答，材料不足时明确说不知道」，等于把续写的开头放在了一个「严谨审计」的语境里，后面接出严谨回答的概率自然变大。

但概率变大 ≠ 一定发生。所以提示词是**提高胜率的手段，不是保证**。保证要靠校验和兜底。

## 三、那它为什么还能写代码、还能推理

这是最容易被问住的一层，得诚实回答。

因为两件事叠加：

1. **它读过海量真实代码和推理过程**，这些模式被压缩进了参数里。写「打开 csv、逐行读、算平均值」这种套路，本质上和续写「今天天气真好，适合……」没有区别，只是模式更长。
2. **上下文够长时，它能在一次回答里「边写边看自己写过的内容」**。前面写下的变量名，后面能接着用；发现写错了，还能在后续文字里自己改口。这看起来像思考，其实是「把推理过程也一并续写出来了」。

:::figure 所谓「推理」，是把自己写过的中间步骤也当成上下文
@stack
问题::用户提出一个多步任务
中间步骤::模型把拆解过程写成文字，等于给自己搭台阶
结论::顺着台阶接出最终答案
校验::这一步模型做不了，得由你的系统补上
:::

这就解释了为什么「让它一步步想」常常有效——**它是在用输出给自己制造更多上下文**。但也解释了为什么它错了会一路错下去：台阶搭歪了，后面全顺着歪的走。

:::quote
模型能生成推理过程，但不能验证推理过程。**生成和验证必须分开**，这是 Agent 系统里最重要的一条分工。
:::

## 四、把机制变成工程清单

把上面四条落到代码上，就是这份教程后面所有篇章的提纲：

| 机制带来的事实 | 系统里必须补的东西 | 对应篇章 |
|---|---|---|
| 只负责「像真的」，不负责「是真的」 | 外接事实来源 + 答案溯源 | [检索增强](./08-rag.md) |
| 上下文有上限且越聊越挤 | 预算表、裁剪、压缩、预检 | [上下文工程](./07-context.md) |
| 输出带随机性 | 输出契约、校验、重试、降级 | [让输出稳定下来](./03-structured-output.md) |
| 不会验证自己的推理 | 独立的评测集与断言 | [评测](./11-eval.md) |
| 只能生成文字，不能真的动手 | 工具层 + 权限 + 幂等 | [工具调用](./06-tool-calling.md) |
| 每一步都可能跑偏 | 循环、终止条件、人工中断 | [手写第一个 Agent 循环](./05-agent-loop.md) |

## 五、动手：40 行看清「多步生成会累积偏差」

下面这段不联网、不装包、不申请任何账号。它用一个极小的「词表 + 概率」模拟一次续写，让你亲眼看到三件事：概率采样怎么工作、温度怎么影响稳定性、以及**为什么步数越多越容易跑偏**。

```python
# next_token.py —— 零依赖，python next_token.py
import random, math

# 一个玩具「模型」：给定上一个词，返回若干候选及其倾向分数
TABLE = {
    "<开始>": [("今天", 5), ("根据", 2), ("抱歉", 1)],
    "今天":   [("天气", 5), ("系统", 1), ("无法", 1)],
    "天气":   [("真好", 5), ("报错", 1)],
    "真好":   [("适合", 4), ("但是", 1)],
    "适合":   [("出门", 5), ("重启", 1)],
    "出门":   [("<结束>", 9)],
    "根据":   [("材料", 5)],
    "材料":   [("第 3 条", 4), ("第 99 条", 2)],  # 注意：不存在的编号也是候选
    "第 3 条": [("符合", 5)],
    "第 99 条": [("符合", 5)],  # 编造的编号，看起来和真的一模一样
    "符合":   [("<结束>", 9)],
    "抱歉":   [("材料不足", 5)],
    "材料不足": [("<结束>", 9)],
    "系统":   [("报错", 5)],
    "无法":   [("确认", 5)],
    "确认":   [("<结束>", 9)],
    "报错":   [("<结束>", 9)],
    "但是":   [("<结束>", 9)],
    "重启":   [("<结束>", 9)],
}

def sample(cands, temperature):
    """温度越低越保守；温度 0 时永远选分数最高的那个。"""
    if temperature <= 0:
        return max(cands, key=lambda x: x[1])[0]
    scores = [math.log(s + 1e-9) / temperature for _, s in cands]
    m = max(scores)
    weights = [math.exp(v - m) for v in scores]
    r = random.uniform(0, sum(weights))
    for (w, _), ww in zip(cands, weights):
        r -= ww
        if r <= 0:
            return w
    return cands[-1][0]

def generate(temperature=0.0, max_steps=8, seed=None):
    if seed is not None:
        random.seed(seed)
    cur, out = "<开始>", []
    for _ in range(max_steps):
        nxt = sample(TABLE.get(cur, [("<结束>", 1)]), temperature)
        if nxt == "<结束>":
            break
        out.append(nxt)
        cur = nxt
    return "".join(out)

print("温度 0（最保守）:", [generate(0.0, seed=i) for i in range(3)])
print("温度 1.2（放开）:", [generate(1.2, seed=i) for i in range(6)])
print()
print("注意 '第 99 条'：它和 '第 3 条' 长得一样可信，")
print("但它是词表里凭空多出来的候选 —— 这就是幻觉的最小模型。")
```

跑一遍，你会看到温度 0 时三次输出完全一致，温度 1.2 时开始出现「报错」「但是」「第 99 条」这类分支。重点看最后两行的提示：

> 模型给出的每个候选，**在它自己看来都是合理的**。它没有一个内部开关能标出「这条是我编的」。

所以系统必须有一个模型之外的东西来判定真假——要么查库，要么校验编号是否存在，要么让工具去执行后把真实结果喂回来。这就是下一篇开始要做的事。

:::check 学完这一篇，你要能回答
- 用一句话说清「幻觉为什么必然发生」，不许用「模型算错了」这类说法。
- 为什么「聊了二十轮之后变笨」通常不是模型退化？
- 温度调到 0 之后，能不能用 `assert output == "xxx"` 写测试？为什么？
- 「生成和验证必须分开」这句话，在你的系统里分别由谁负责？
:::

## 小结

:::figure 这一篇的推导链
@stack
一个机制::反复猜下一个最可能的词
四个推论::有上下文上限 / 按量计费 / 输出随机 / 提示词只是定开头
一条分工::模型负责生成，系统负责验证与兜底

别背概念，记住那张「接着往下写」的图就够了。以后每遇到一个模型行为，先问一句：**「如果它只是在续写，这个表现合不合理？」** 大部分困惑会当场消失。
