# 相似度度量对齐

## 一、同一批数据，换了个算法结论就翻了

你搭好一个语义检索，索引里存着一堆向量，查询也转成了向量，剩下就是「算个相似度排个序」。你随手用了两段向量逐项相乘再求和的点积，跑出来第一段排最前。同事接手时觉得「余弦更标准」，把代码改成夹角的余弦，结果排序整个换了个样，本来靠前的那段掉到了后面。数据没动、向量没动，只换了一个「怎么算相近」，结论就翻了。你怀疑其中一种写法有 bug，可两种都是教科书上的公式，谁也没算错。

## 二、先破这个把公式当万能的误解

**不是某个公式写错了，也不是向量坏了，而是你把三种不同的「相近」当成了同一个东西，却没问过手里的向量是按哪种口径训练出来的。**

先把三个主角摆清楚，它们都衡量两段向量「有多近」，但近的含义不同。余弦相似度（Cosine Similarity，看两个向量夹角的接近程度，只比方向、不看长度）；点积（Dot Product，两段向量逐项相乘再求和，既受方向影响，也受向量长度影响）；欧氏距离（Euclidean Distance，把两段向量当成空间里两个点，量它们之间的直线远近）。这里还有个前提动作叫归一化（Normalization，把向量缩放到单位长度，使每个向量的长度都变成 1）。三者不是「哪个更准」的关系，而是「在不同前提下等价或不等价」的关系：向量都归一化了，点积和余弦给出的排序一致；向量长度参差不齐时，点积会被「又长又同向」的向量拉偏，余弦却不会。这些向量怎么来的、为什么是稠密的一串实数，[Embedding 与向量化](./k129-embedding.md) 讲过；本篇只盯最后一步：该用哪把尺子去量。

## 三、把它想成量两支箭「像不像」

打个比方：桌上有几支箭，每支有「指向哪个方向」和「有多长」两个属性。现在要挑出和目标箭最像的几支，有三种量法。余弦只比方向：管你是长箭短箭，只要指得几乎同一个方位就算最像；点积既看方向又看长度：一支方向对、又特别长的箭会因为「长」被额外加权，哪怕它指得没那么正；欧氏距离则把箭尖当成点，量两个箭尖之间的直线距离——方向一致但一支很长一支很短，箭尖照样隔得远，所以也会被判成「不太近」。

这里有一一对应关系：一段文本等于一支箭；向量的方向等于它编码的语义倾向；向量的长度等于这个数值串的整体幅度；查询向量等于手里那支用来比对的箭；而「召回哪几段」等于按某种量法挑出最像的几支。

这个类比一下就点破了那个翻盘的下午。你的向量如果没归一化，各支箭长短不一，用点积就等于偷偷奖励了「长箭」，排序被长度带偏；换成余弦，长度被除掉，只剩方向，结论自然不同。两种都没算错，只是问的问题不一样。更关键的一层：向量模型在训练时是按某一种量法被「教」出来的——有的模型产出单位向量、明确配余弦或点积，有的则不然。你手里的箭到底是「只该比方向」还是「长度本身有意义」，得听模型的口径，不该自己拍脑袋换。用错尺子，等于拿一把按英寸刻的尺去读按厘米标注的图。

## 四、两张图看清三把尺子的关系

取查询向量|确认模型口径|选定度量|逐段算分|按分排序
:::

第一张图里，「确认模型口径」夹在取向量和选度量之间，是本篇真正想加进去的一步。很多人直接从「取查询向量」跳到「选定度量」，凭习惯挑一个公式；正确顺序是先问「这些向量是归一化的吗、模型推荐哪种量法」，再定用哪把尺。度量不是随手选的偏好，是对齐模型口径的结果。

:::figure 归一化与否对三种度量的影响
@compare
向量未归一化::点积被长度拉偏|余弦只看方向会与点积排序不同|欧氏距离也受长度干扰
向量已归一化::点积等价于余弦|方向决定相近|三种度量排序趋于一致
:::

第二张图把前提摆明。同样三种公式，在「未归一化」和「已归一化」两行里表现完全不同：归一化之后，点积和余弦等价，长度这个干扰项被消掉，三把尺子基本指向同一个结论；未归一化时，含长度的量法会被幅度带偏，彼此拉开的差距正是那次排序翻盘的原因。

## 五、顺着追问把边界推出来

:::ask 那如果我统一把所有向量都归一化一下，是不是三种度量随便用都行？
:::

在「排序」这件事上基本可以：归一化后点积等于余弦，欧氏距离的平方也能化成与余弦只差一个单调变换的形式，所以按分数从高到低排，三者给出的名次通常一致。但有两个不能随便的地方。其一，「分数」本身不再等价：余弦落在 -1 到 1，欧氏距离是个非负长度，点积在归一化后也落在 -1 到 1，可它们的数值含义不同。如果你拿这个分数去设阈值（比如「相似度大于 0.8 才采纳」），换度量却不重定阈值，就会系统性误判——阈值是跟着具体量法标定的，不可跨度量照搬。其二，归一化不是没有代价的免费操作：有些模型产出的向量长度本身携带信息（比如幅度反映某种置信程度），一刀切归一化会把这层信息抹掉。所以要不要归一化，仍得回到「模型是怎么被训练的」这个前提，而不是为了省事统一处理。

:::ask 再追一层：那如果我把「要不要归一化」和「用哪种度量」拆成两个可配置项，是不是更灵活？
:::

方向看着灵活，实则是把一个必须成对固定的约定拆成了两半，反而更容易配错。真正的风险不是「选了哪个公式」，而是「写入索引时用的是一套口径、查询时用的是另一套」：入库时向量按余弦口径存，查询侧却按未归一化的点积算，两边尺度对不上，分数自然乱套。这种错最阴险，因为程序不报错、结果照样返回，只是悄悄变差。稳妥做法是把它收口成一个「度量契约」：模型标识、是否归一化、用哪种度量、阈值多少，四样绑成一份配置，写入侧和查询侧都从这一份读，启动或检索前先校验两边一致。再往深一层，即便度量完全对齐，算出来的「相近」也只是语义相近，不等于任务相关、更不等于事实正确：「支持退货」和「不支持退货」的向量夹角可能极小，纯靠距离会把意思相反的两段当成一回事。所以度量对齐解决的是「别在错误的尺度上比」，它不负责「比出来的东西对不对」——后者要靠重排、引用校验与业务规则，这也是 [混合检索与 RRF 融合](./k058-hybrid-rrf.md) 之后还要做重排的原因。把分数对齐了就以为答案可靠，是把两个层次的问题混成了一件。

## 六、用一段可运行代码把「对齐」演出来

下面这段不联网、不装任何第三方包，用几组本地构造的向量，演示未归一化时点积会被长度拉偏、归一化后点积与余弦等价、以及跨度量照搬阈值会误判。

```python
import math

def dot(x, y):
    return sum(a * b for a, b in zip(x, y))

def norm(x):
    return math.sqrt(sum(a * a for a in x))

def cosine(x, y):
    nx, ny = norm(x), norm(y)
    if nx == 0 or ny == 0:
        return None
    return dot(x, y) / (nx * ny)

def euclidean(x, y):
    return math.sqrt(sum((a - b) ** 2 for a, b in zip(x, y)))

def unit(x):
    n = norm(x)
    return [a / n for a in x] if n else list(x)

def rank(vecs, scorer, reverse=True):
    scored = [(scorer(v), name) for name, v in vecs.items()]
    return [name for _, name in sorted(scored, key=lambda t: t[0], reverse=reverse)]

def main():
    query = [1.0, 1.0]
    # a 方向正但短，b 方向略偏却很长，c 方向正且长度中等
    vecs = {
        "a": [1.0, 1.0],          # 与查询同向，短
        "b": [3.0, 2.0],          # 方向略偏，但幅度大
        "c": [1.2, 1.1],          # 方向较正，长度中等
    }

    dot_rank = rank(vecs, lambda v: dot(query, v))
    cos_rank = rank(vecs, lambda v: cosine(query, v))

    # 归一化后：点积与余弦等价
    uvecs = {k: unit(v) for k, v in vecs.items()}
    uq = unit(query)
    udot_rank = rank(uvecs, lambda v: dot(uq, v))
    ucos_rank = rank(uvecs, lambda v: cosine(uq, v))

    # 归一化的向量里，点积值与余弦值数值上一致
    same_value = all(abs(dot(uq, v) - cosine(uq, v)) < 1e-9 for v in uvecs.values())

    # 跨度量照搬阈值：余弦 0.9 的门槛套到未归一化的点积上会误判
    cos_a = cosine(query, vecs["a"])
    dot_b = dot(query, vecs["b"])
    threshold_misused = (dot_b > 0.9)   # 拿点积去比余弦门槛，几乎必然为真

    results = []
    results.append(("未归一化时点积把长向量 b 排第一", dot_rank[0] == "b"))
    results.append(("余弦按方向把同向的 a 排前列", cos_rank[0] == "a"))
    results.append(("未归一化时点积与余弦排序不同", dot_rank != cos_rank))
    results.append(("归一化后每个向量长度为 1", all(abs(norm(v) - 1) < 1e-9 for v in uvecs.values())))
    results.append(("归一化后点积排序等于余弦排序", udot_rank == ucos_rank))
    results.append(("归一化后点积数值等于余弦数值", same_value))
    results.append(("欧氏距离在归一化向量上非负可算", euclidean(uq, uvecs["b"]) >= 0))
    results.append(("余弦阈值照搬到点积会误判", threshold_misused is True))

    passed = sum(1 for _, ok in results if ok)
    for name, ok in results:
        print(("通过" if ok else "未通过") + "：" + name)
    print("通过 {}/{} 项".format(passed, len(results)))
    assert passed == len(results)

if __name__ == '__main__':
    main()
```

逐段看关键行在做什么：

1. `dot` / `norm` / `cosine` / `euclidean` 用标准库 `math` 实现四种基本运算，全是纯函数、纯本地，不依赖任何外部服务。`unit` 做归一化，把向量缩到长度 1。
2. `vecs` 是刻意构造的三段向量：`a` 与查询同向但短，`b` 方向略偏却幅度大，`c` 居中。这组数据就是「长度会带偏点积」的最小复现——它不编造任何真实结果，只是可推算的构造场景。
3. `rank` 按给定度量算分并排序，返回名次列表。用它分别跑点积和余弦，得到两份名次。
4. 关键断言在 `main` 前半：未归一化时 `dot_rank[0] == "b"`（长向量被点积推到第一）而 `cos_rank[0] == "a"`（余弦只看方向），两份名次不同——这正是开头那个「换个算法结论就翻」的可运行版本。
5. `uvecs` 把三段向量归一化后，再跑点积与余弦，断言两者排序相同、且数值在误差内相等（`same_value`）。这就把「归一化后点积等价于余弦」从一句话变成了可验证的事实。
6. `threshold_misused` 演示最后一层坑：余弦的 0.9 门槛拿去卡未归一化的点积值（这里是 5.0），几乎必然成立，等于把阈值判废。八条断言合起来钉住一句话：**度量要连同归一化与阈值一起对齐，不能只对齐公式。**

:::tip
把「模型标识、是否归一化、用哪种度量、阈值多少」绑成一份配置，写入侧和查询侧都从它读。别把「要不要归一化」和「用哪个公式」拆成两个可随意组合的开关。
:::

## 七、踩过的坑与它的边界

- **随手挑公式**：现象是换一种相似度排序就翻盘 → 原因是没先确认向量是否归一化、模型按哪种口径训练 → 先定模型口径，再选度量，让度量成为对齐的结果而非偏好。
- **未归一化用点积**：现象是又长又同向的段落总排前面 → 原因是点积把向量幅度也算进了分数 → 要么按模型要求改用余弦，要么先归一化再用点积。
- **两边口径不一致**：现象是入库好好的、查询侧分数悄悄变差 → 原因是写入与检索用了不同的归一化或度量 → 用一份共享配置收口，检索前校验两侧一致。
- **阈值跨度量照搬**：现象是「相似度大于 0.8」的门槛突然形同虚设 → 原因是余弦、点积、欧氏距离的数值范围与含义不同 → 阈值跟着具体量法重新标定，不跨度量复用。
- **盲目一刀切归一化**：现象是某些带幅度信息的向量反而变差 → 原因是归一化抹掉了长度携带的置信程度 → 归一化与否听模型口径，别为省事统一处理。

还有边界要说清：度量对齐保证的是「在正确的尺度上比较」，它和「比出来的东西对不对」是两层。语义相近不等于事实正确，也不等于这段材料对当前任务有用；分数最高的候选仍可能是答非所问或意思相反的那段。所以对齐之后还要有重排、引用校验、权限与业务规则去收口。另外，本篇的向量是本地构造的假数据，演示的是三种公式之间的关系，不含任何真实语义或实测结论；真实系统里该用哪种量法，依据永远是产出这些向量的模型所声明的口径。

## 九、三句话小结

相似度度量对齐，是让「用哪把尺子量相近」与向量模型的训练口径、归一化状态、分数阈值保持一致的一套约定。

关键做法是先确认模型口径再定度量，把模型标识、是否归一化、度量方式、阈值绑成一份共享配置让写入与查询两侧同读，并在检索前校验一致。

当向量长度本身携带业务含义、或模型明确要求保留幅度时，别为图省事一刀切归一化，按模型声明的口径来。
