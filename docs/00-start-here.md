# 写给想转 Agent 开发的你

先问你一个特别实在的问题：**你打开招聘软件，搜「Agent 开发」，看到那串要求的时候，第一反应是什么？**

我猜是「完了，我得先把大模型学一遍」。然后你去搜学习路线，得到一张密密麻麻的清单：Transformer、注意力机制、微调、向量数据库、检索增强、多智能体、上下文工程、评测、部署…… 收藏，关掉，第二天再打开，还是不知道第一步该敲什么。

这不是你不自律，是**那张清单只把名词堆在一起，没告诉你它们之间是什么关系、哪个必须先会、学会了能解决什么问题**。就像别人给你一张「螺丝、扳手、电路、外壳」的清单，你依然装不出一台机器。

这一篇我们把顺序理出来：从「模型到底在干什么」这一个最底层的问题出发，一层一层往上，把要掌握的知识点按「后面这一层必须踩在前面那一层上」的顺序排好。

## 一、先破一个误解：这不是一门新语言

很多人把「转 Agent 开发」想象成「转 Go」或者「转算法」——从头学一套全新的知识体系，学完了再去找工作。于是陷入长达半年的准备期。

实际上这个岗位的日常，更像**后端工程师接了一个不太老实的下游服务**。

传统后端里，你调一个接口，传对参数，它给你一个确定的结果；参数错了，它给你一个明确的报错。而现在这个「下游」换成了一个会自己理解、会自己发挥、偶尔还会一本正经编造的模型。你原来那套工程本事——**拆流程、定契约、做校验、加日志、限重试、控权限、写回归测试**——一项都没作废，反而全变成了核心竞争力。

:::figure 同样一个需求，传统后端和 Agent 开发的差别
@compare
传统后端::入参固定|结果确定|错了抛异常|流程写死在代码里
Agent 开发::输入是自然语言|输出要校验|错了会编一个|流程在运行时才决定
:::

看出来了吗？变的不是「要不要做工程」，而是**你要多处理一层不确定性**。所以：

:::quote
Agent 开发不是「学会调模型」，是「把一个不确定的组件，装进一个确定的系统里」。
:::

这句话是整份教程的主线。后面每一篇，本质上都是在回答「不确定性从哪儿冒出来，怎么把它关回笼子里」。

## 二、这个岗位每天到底在干什么

我们不列岗位 JD 里的漂亮词，直接看一个真实需求从提出到交付，你要经手哪几件事。

假设产品说：「做一个能自动回答内部制度问题的助手，答案必须能查到出处，不许瞎编。」

:::figure 一个 Agent 需求的完整链路
@flow
听懂需求|拆成可控步骤|接上真实数据|定好输出契约|写评测集|线上兜底
:::

看着平平无奇，但每一格都会冒出「模型不确定」带来的坑：

- **听懂需求**：用户问「我去年没休的年假还能不能折现」，这句话里有时间、有前提、有隐含的制度版本，模型很可能直接跳过前提就答。
- **拆成可控步骤**：哪些动作可以由模型自己决定，哪些必须写死？把整条流程交给模型，是最常见也最贵的新手错误。
- **接上真实数据**：模型不知道你们公司今年的制度，得让它去查；查回来的内容怎么塞进上下文、超长了怎么办、查不到怎么办。
- **定好输出契约**：答案里必须带出处段落编号，模型经常忘。你得能校验、能重试、能降级。
- **写评测集**：改了一版提示词，怎么证明没变差？靠「我感觉好像好一点了」是不行的。
- **线上兜底**：模型超时、返回乱码、用户问了越权内容、有人恶意套话、账单半夜暴涨——这些都得在你写代码时就想好。

:::tip 一句话定位
这个岗位 20% 的时间在和模型打交道，**80% 的时间在给模型擦屁股、搭护栏、写回归**。这恰恰是转行者的机会：这 80% 全是通用工程能力。
:::

## 三、你现在的经验值多少

别急着从零开始。对照一下，你大概率已经会一大半了：

| 你原来的背景 | 已经具备的 | 需要补的 | 最容易踩的坑 |
|---|---|---|---|
| 后端 / 服务端 | 接口设计、幂等、事务、日志、权限、限流 | 模型调用特性、上下文预算、评测方法 | 把模型当普通 RPC，不做输出校验 |
| 前端 / 客户端 | 状态管理、流式渲染、交互体验 | 服务端编排、工具设计、安全边界 | 只做漂亮界面，忽略失败态与超时态 |
| 算法 / 数据 | 检索、向量、评估指标、离线实验 | 工程化、可观测、成本与延迟 | 沉迷调参，不做可回归的评测集 |
| 测试 / 运维 | 用例设计、故障注入、监控告警 | 模型行为的不确定性、提示注入 | 用确定性断言去测非确定性输出 |
| 完全新手 | 无 | 全部 | 一上来就学框架，跑通 Demo 就以为会了 |

:::ask 停下来想一分钟
你最近做过的项目里，有没有「调用了一个不完全可靠的第三方，然后为它写了一堆兜底」的经历？把那段经历翻出来——那就是你面试时最值钱的故事，只需要把「第三方」换成「模型」。
:::

## 四、从不会到会：要掌握的知识点，一层层往上踩

网上路线图爱按「入门 / 进阶 / 实战」贴标签，看完你还是不知道具体要会什么。我们换个办法：**把知识点按依赖关系排成六层，后一层一定要用到前一层**。每一条点开都是网站上的一篇完整正文，照着顺序往下走就行。

:::figure 六层知识点：每一层都踩在上一层上
@stack
模型与调用::先搞清楚模型在猜什么、一次请求怎么发、输出怎么变得可信
Agent 循环::在调用之上加一个「自己决定下一步」的循环，管住状态与终止
工具与上下文::让循环能调用真实工具，并管住越聊越长的上下文
检索、记忆与框架::接外部资料、留住跨轮信息、看懂框架替你做了什么
评测与可靠性::用用例集证明改动没变差，用护栏兜住攻击与成本
项目与表达::把前面全部串成能演示的系统，并讲清楚每个取舍
:::

### 第 1 层 · 模型与调用

先别碰「Agent」这三个字。你得先知道手里这个组件到底是什么脾气。

- 模型在做的事是**反复猜下一个词**，由此推出幻觉为什么必然发生、上下文为什么有长度上限、为什么按 token 计费、为什么参数调到 0 也照样不稳定 → [大模型到底在干什么](./01-how-llm-works.md)
- 一次请求拆成哪五块：地址、鉴权、消息体、参数、返回；怎么写超时、指数退避、成本打印，让调用在抽风时也不崩 → [第一次调用：把一次请求拆成五块](./02-first-call.md)
- 「请只输出 JSON」为什么根本没用；把校验从模型手里收回来，做语法、结构、语义三层契约，加上自动纠正与果断降级 → [让输出稳定下来](./03-structured-output.md)

**这一层学完的标志**：给你任意一个模型服务，你能写出一份带重试、带成本、带输出校验的调用骨架，且模型返回乱码时程序不会崩。

### 第 2 层 · Agent 循环

有了可信的调用，现在才谈得上 Agent。核心问题是：**谁来决定下一步做什么**。

- 判断是不是 Agent 只有一条标准——流程是在运行时由模型决定的，还是写死在代码里的；以及一个更重要的问题：什么时候坚决不该用 → [什么是 Agent：一条线划清边界](./04-what-is-agent.md)
- 用纯标准库手写 200 行循环：状态怎么存、四个终止条件、错误怎么回传给模型、幂等怎么保证、检查点与轨迹回放怎么留 → [手写第一个 Agent 循环](./05-agent-loop.md)

:::warn 别从框架开始
框架会替你把循环、状态、工具分发全包了。你要是先用框架跑通 Demo，就永远不知道这些环节存在，出了问题只能改提示词碰运气。**先用纯代码手写一遍 200 行的循环，之后再看任何框架，你都能一眼看出它替你做了什么、以及什么时候它在帮倒忙。**
:::

**这一层学完的标志**：不装任何第三方包，你的程序能自己挑工具、观察结果、再决定下一步，直到把一件多步任务做完。

### 第 3 层 · 工具与上下文

循环能转了，接着要解决两件事：让它**真的碰到世界**，以及别让它**越聊越贵、越聊越笨**。

- 工具不是「函数列表」，是一份契约：参数怎么设计才不让模型编、权限矩阵怎么收、副作用怎么防重复、危险动作怎么二次确认 → [工具调用：让文字安全地碰到真实世界](./06-tool-calling.md)
- 「聊了二十轮突然变笨」的完整解法：一张上下文预算表、四层结构、三种压缩策略、预检路由与前缀缓存 → [上下文工程：Agent 真正的命门](./07-context.md)

**这一层学完的标志**：给循环接三个真实工具，带参数校验与幂等键；长对话能自动压缩，账单不再随轮数失控。

### 第 4 层 · 检索、记忆与框架

模型不知道你的私域资料，也不会自动记住上一轮说过什么。这一层补上「外部知识」和「框架认知」。

- 从「为什么整份文档塞进去必然更差」开始，手写切分、双路检索、业务重排、溯源校验与拒答阈值 → [检索增强：让答案带得出出处](./08-rag.md)
- 「把聊天记录全存下来」不叫记忆，叫日志：三层记忆、写入判定、冲突消解、召回与遗忘权 → [记忆系统：以及什么时候坚决不该记](./09-memory.md)
- 不点名任何产品，只讲共性：框架替你接管了哪六件事、工具协议解决与不解决什么、什么时候它们在帮倒忙 → [框架与工具协议：它们到底替你做了什么](./10-framework.md)

**这一层学完的标志**：助手能查自己的文档、答案带得出处、材料不足时会明确拒答；别人给你一个框架，你能说清它替你做了什么。

### 第 5 层 · 评测与可靠性

到这里系统「能跑」了，但离「敢开给别人用」还差一整层。这一层全是区分「做过 Demo」和「做过系统」的知识点。

- 三层评测、一份从 30 条起步的用例集、性质断言而非文本断言、能卡住发布的回归门禁 → [评测：怎么证明改了一版没变差](./11-eval.md)
- 间接提示注入为什么提示词挡不住、四类攻击面、最小权限矩阵、成本炸弹与四重预算 → [安全与护栏：让系统敢开给别人用](./12-safety.md)
- 本地跑通和敢开放之间隔着的十项显式化：幂等落盘、结构化日志、超时降级、健康检查、指标、灰度与回滚 → [从 Demo 到上线：差的不是部署](./13-production.md)

**这一层学完的标志**：改任何一版，你都能用评测集证明没变差；超时、乱码、越权、恶意套话、账单暴涨，每一种都有兜底。

### 第 6 层 · 项目与表达

知识点全部学完，最后要能把它们串成作品，并且在 15 分钟里讲清楚。

- 不写「基于大模型开发了智能助手」，写约束、权衡与可验证的结果；三个项目各带架构、代码骨架、评测口径与追问预判 → [三个能写进简历的项目](./14-projects.md)
- 面试官追的不是知识点，是你的决策链：四条高频追问链逐层拆解、转行者专属三问、15 分钟讲项目的节奏 → [面试追问链：把项目答到第四层](./15-interview.md)

**这一层学完的标志**：三个项目能演示，随便从哪一层追问进去，你都能答到第四层，并说清当初为什么不选另一条路。

三个「不要」，比时间表更重要：

1. **不要收集教程**。这一份就够，缺的是动手，不是资料。

## 六、第一天就能做的一件事

别等「准备好」。现在复制下面这段，存成 `check.py` 跑一下。它不联网、不申请任何账号，只做一件事：把你机器上跑后续所有代码需要的能力检查一遍。

```python
# check.py —— 零依赖环境自检，直接 python check.py 即可
import json, sys, time, hashlib
from pathlib import Path

def ok(label, cond, hint=""):
    print(("  [OK]   " if cond else "  [FAIL] ") + label + ("" if cond else "  -> " + hint))
    return cond

print("Python:", sys.version.split()[0])
results = []

results.append(ok("版本 >= 3.9", sys.version_info >= (3, 9), "建议升级到 3.10+"))
results.append(ok("标准库 json 可用", isinstance(json.loads('{"a":1}'), dict)))
results.append(ok("标准库 hashlib 可用", len(hashlib.sha256(b"x").hexdigest()) == 64))
results.append(ok("当前目录可写", Path(".").is_dir()))

# 模拟一次「带超时与重试」的调用骨架，后面每一篇都会用到它
def call_with_retry(fn, times=3, base_delay=0.05):
    last = None
    for i in range(times):
        try:
            return fn()
        except Exception as e:
            last = e
            time.sleep(base_delay * (2 ** i))
    raise RuntimeError("重试 %d 次仍失败: %s" % (times, last))

attempt = {"n": 0}
def flaky():
    attempt["n"] += 1
    if attempt["n"] < 3:
        raise OSError("模拟网络抖动")
    return {"answer": "通了", "round": attempt["n"]}

r = call_with_retry(flaky)
results.append(ok("重试骨架正常", r["round"] == 3 and r["answer"] == "通了"))

print("\n通过 %d/%d 项。" % (sum(results), len(results)))
if all(results):
    print("可以开始了 -> 下一篇：大模型到底在干什么")
else:
    sys.exit(1)
```

跑完你会看到 `通过 6/6 项`。这段代码里已经藏着后面反复出现的三个习惯：**带超时和退避的重试、结构化返回、以及可断言的验收**。整份教程就是在这一点点骨架上长出来的。
