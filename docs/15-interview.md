# 面试追问链：把项目答到第四层

先还原一个很常见的面试现场：

> 「你项目里怎么处理幻觉的？」
> 「加了检索增强，答案能带出处，还做了输出校验。」
> 「那如果检索回来的内容本身就是错的呢？」
> 「……」
> 「如果模型引用了一个不存在的编号，你怎么发现？」
> 「……」

不是不会，是**只准备到了第一层**。面试官问的从来不是「你知不知道这个概念」，而是「**这条决策链你能往下走几层**」。

:::quote
八股能答到第一层，做过项目能答到第二层，踩过坑并修好能答到第三层，**能说清「为什么这么选、代价是什么、什么情况下会改」才到第四层**。
:::

## 一、先破误解：追问不是刁难，是在验证你有没有真做过

看这张模型：

:::figure 四层追问，每层要的证据不同
@stack
第一层 是什么::概念、组件、流程 → 背过就能答
第二层 怎么做::代码结构、参数、阈值 → 写过就能答
第三层 出问题怎么办::失败模式、排查顺序、踩过的坑 → 只有线上跑过才答得出
第四层 为什么::取舍、代价、什么条件下会换方案 → 做过设计决策才答得出
:::

准备方法也随之明确：**别再攒知识点，按「问题 → 我的做法 → 出过什么事 → 为什么选它」四格去整理每个模块**。下面四条链，就是覆盖面最广的四条。

## 二、追问链 ①：幻觉与溯源

| 层 | 典型问法 | 该拿什么接住 |
|---|---|---|
| 1 | 怎么防止模型瞎编？ | 外接事实来源 + 输出契约 + 语义校验三层 |
| 2 | 输出契约具体校验什么？ | 语法清洗、字段/类型/枚举、引用编号是否存在；自纠最多 2 次 |
| 3 | 检索回来的内容本身过期/矛盾呢？ | 元数据带生效年份与废止标记，重排里用**代码**判版本，不靠提示词；版本歧义返回 `need_clarify` |
| 4 | 为什么版本规则放重排、不放提示词？ | 提示词只提高胜率，事实判定必须确定性；代价是要维护元数据，换来的是可审计、可回归 |

**第四层的加分补刀**：主动补一句「我们特意不追求答全，材料不足就拒答——**能拒答比答得全更重要**，因为幻觉事故大多来自弱相关时硬答」。

## 三、追问链 ②：循环、终止与幂等

| 层 | 典型问法 | 该拿什么接住 |
|---|---|---|
| 1 | Agent 循环怎么实现的？ | State + 组装上下文 + 决策 + 执行 + 观察，四个终止条件 |
| 2 | 凭什么停？ | 目标达成 / 轮数 / 调用数 / 耗时，生产再加金额与人工中断 |
| 3 | 只设轮数会出什么事？ | 「一轮里调 40 次工具」「一个接口卡 60 秒」两类真实事故；工具重复执行会下两单 |
| 4 | 幂等为什么必须落盘？ | 内存缓存进程重启即失效；落盘 + 过期时间才有跨重启保证；代价是多一次存储读写 |

**第四层的加分补刀**：「我们把错误转成观察结果写进轨迹，而不是抛异常——**失败是一次观察**，模型看到『数据源超时』才会改查别的路。这个设计让排障任务的完成率明显变好，也带来一个代价：轨迹会变长，所以上下文层要做摘要压缩。」

一句话里同时有**决策、结果、代价**三样东西，第四层就稳了。

## 四、追问链 ③：上下文与成本

| 层 | 典型问法 | 该拿什么接住 |
|---|---|---|
| 1 | 聊久了变笨怎么办？ | 不是模型退化，是上下文膨胀；预算表 + 分层 + 摘要 |
| 2 | 预算怎么分？ | 固定层 / 状态层 / 近期轨迹 / 当前输入 / **给输出预留** |
| 3 | 压过头会怎样？ | 模型开始重复做已做过的事、结论和前文矛盾 → 补结构化状态字段，不把原文塞回去 |
| 4 | 为什么当前问题放最后、稳定规则放最前？ | 离模型越近权重越高；稳定前缀固定还可复用缓存，既提效果又省钱 |

**第四层的加分补刀**：「换更大窗口的模型能缓解但治不了根——**贵、注意力稀、而且很多内容本来就不该带**。我们的顺序是先减工具数量、再压早期历史、再裁工具结果，最后才考虑换模型。」

## 五、追问链 ④：安全与护栏

| 层 | 典型问法 | 该拿什么接住 |
|---|---|---|
| 1 | 怎么防提示注入？ | 提示词挡不住，护栏建在模型之外 |
| 2 | 具体哪几道？ | 来源标记、最小权限、危险动作二次确认、输出扫描、四重预算 |
| 3 | 输入扫描能当放行判据吗？ | 不能，误报漏报都有，只用于标记并触发更保守策略；真正兜底是权限与预算 |
| 4 | 安全设计的目标怎么定义？ | 「**模型被完全带偏时，损失仍有上界**」；上界由权限、预算、确认决定，不由提示词决定 |

**第四层的加分补刀**：「权限级别由本地注册信息决定，不信远端工具自己声明的『只读』——因为一个标错级别的远端删除接口，就能被低角色调到。」

:::tip 四条链有个共同结构
**第一层答组件，第二层答实现，第三层答事故，第四层答取舍。** 准备时按这个模板把每个模块过一遍，比背一百道题有用。
:::

## 六、最出彩的三个「反直觉加分点」

面试官听多了「我们用了 Agent / 用了某某框架」，下面三句会立刻不一样：

1. **主动说「这里不该用 Agent」**：八成确定性请求走固定流程，只有多意图、需跨系统查证的才进循环，所以延迟与成本可控。
2. **主动说「哪里没做好」**：只设轮数上限时踩过「一轮狂调工具」的坑，后来补了调用数与金额两道闸。
3. **主动说代价**：手写循环换来了可审计与可恢复，代价是检查点和幂等要自己维护；讲清代价，说明你是在做工程选择而不是追新。

:::warn 别把「反直觉」演成抬杠
这三句的前提都是**你能立刻拿出对应的代码、评测数据或事故记录**。没有证据的「我做了取舍」，比不说更伤。
:::

## 七、转行者专属三问

这三问几乎必问，提前准备好，别临场编：

| 问题 | 别这么答 | 这么答 |
|---|---|---|
| 「你不是科班，为什么能做？」 | 「我学得快」 | 「我原来做后端，天天处理不可靠下游：超时、幂等、权限、日志、回归。这个岗位八成是给模型搭这套壳，我原来的经验直接能用，补的是模型特性与评测方法。」 |
| 「为什么转方向？」 | 「原来方向没前景」 | 讲一个具体触发点（比如做过一次接模型的需求，发现难点全在工程化），再讲你为它做了什么（这份 10 周路线 + 三个跑通的项目）。 |
| 「项目是不是自己做的？」 | 反复强调「是」 | 直接打开轨迹回放、评测报告、检查点文件，现场讲一次「某个 bug 是怎么从日志定位到代码第几行」。**可复现的过程比保证更有说服力。** |

:::quote
转行不是减分项，**「把原有工程能力翻译成这个岗位的语言」才是你要展示的东西**。这份教程从头到尾都在做这个翻译。
:::

## 八、简历整体怎么改（转行版）

| 板块 | 建议 |
|---|---|
| 开头三行 | 一句定位 + 一句最强项目 + 一句可验证结果，别写「熟练掌握」清单 |
| 项目经历 | 两个主项目写深（五段式），第三个一笔带过；**按岗位相关度排，不按时间排** |
| 技术栈 | 按「能力」分组：循环与状态 / 工具与权限 / 上下文与检索 / 评测与上线，而不是罗列名词 |
| 原有经历 | 保留，但用这个岗位的语言重写：把「接口幂等 / 限流 / 故障排查」写清楚 |
| 不写 | 「了解」「接触过」「参与」这类虚词；没跑过的技术；编出来的数字 |

## 九、15 分钟讲项目的节奏

:::figure 讲一个项目的分配
@stack
0~2 分::场景与硬约束，一句话说清「不能出什么事」
2~6 分::架构图，边画边说数据流，别念技术名词
6~10 分::两个关键决策，每个都带上「为什么不选另一个」和代价
10~13 分::评测与一次真实事故，展示轨迹/日志/数字
13~15 分::主动说不足与下一版，把话题引到你准备最充分的地方
:::

最后两分钟是**你唯一能主动控制面试走向的窗口**，别用来收尾客套，用它把话题引到你最想被问的那条链上。

## 十、临走前的准备清单

- [ ] 三条主追问链，每条都能不假思索答到第四层
- [ ] 至少一个「踩坑 → 定位 → 修复 → 补评测用例」的完整故事
- [ ] 能现场打开的轨迹回放 / 评测报告 / 检查点文件
- [ ] 一个「这里不该用 Agent」的判断例子
- [ ] 所有数字都能说清「多少条、什么指标、怎么测的」
- [ ] 转行三问各准备了一段 40 秒的回答
- [ ] 15 分钟讲法掐表练过两次

## 小结：整份教程收个尾

:::figure 十六篇其实是同一条线
@stack
一个机制::模型只在反复猜下一个词
一条分工::模型负责生成，系统负责验证与兜底
一副骨架::状态 / 循环 / 工具 / 上下文 / 预算 / 轨迹
三道保障::评测、护栏、上线工程
一个结果::能交付、能答辩、能复盘
:::

回到第 00 篇那句话：**Agent 开发不是「学会调模型」，是「把一个不确定的组件，装进一个确定的系统里」**。十六篇里所有代码、所有图、所有清单，都是这一句话的展开。

如果你只记住三件事：

1. **先手写循环，后碰框架**——知道框架替你做了什么，才谈得上选型。
2. **生成和验证必须分开**——真实性、安全性、成本上限，一样都不能指望模型自觉。
3. **按「能交出什么」排学习顺序**——收藏教程不会让你通过面试，跑通 `check.py`、写完那 200 行循环、攒够 30 条评测用例会。

这份知识库会持续更新。读的时候别按顺序背，挑你当前卡住的那一篇，把里面的代码跑一遍、改成自己的场景、再补一条评测用例——**那就已经是你的项目了**。

:::quote
从「调通一个 Demo」到「敢开给别人用」，中间隔的不是更聪明的模型，是你亲手搭起来的那层壳。
:::
