# 检索排序指标与 RAG 四项核心指标

## 场景提问

你把检索接进了问答系统，挑了几个自己顺手的问题试了试，感觉「都能搜到」，就打算交差。可一放到真实提问里就露馅：有的问题明明有答案，系统却答「没找到」；有的问题搜回来一堆看着相关的段落，答案却张冠李戴，把别的年份的数字安了上去；还有的回答写得流畅漂亮，仔细一核对，里面那句关键的结论在检索回来的材料里根本找不到出处。你想改进，却说不清到底该动哪一环——是搜索没捞对、是排序把相关文档压在了后面、还是生成时自己编了话。更让人犯难的是，你说「效果还行」，别人问「行到什么程度、比上一版好在哪」，你只能答一句「感觉不错」。明明每个环节都在跑，怎么连「好不好」都没法说清？

## 破误解

**不是模型生成得不够好，是你把「检索排得怎么样」和「答案写得怎么样」混成了一句话来评价，两层都没被单独量过。**

先补两个第一次见会发懵的缩写。RAG 是检索增强生成（Retrieval-Augmented Generation），白话就是「先从资料库里捞相关片段，再让模型照着这些片段写答案」这套办法；@K 里的 K 指「排序结果的前 K 条」，比如「前 3 条」就写作「@3」。整个链路其实是两截：前半截是检索，把候选片段排个序；后半截是生成，照着排回来的片段写答案。这两截会各自出问题，而且互相掩盖——检索没捞对，生成再努力也写不出正确答案；检索捞对了，生成仍可能不看材料自己编。用一句话笼统地说「效果不错」，等于把两截的账记在了一起，出了问题自然定位不到该动哪一环。

于是评价要分成两组尺子。第一组量的是「排序」，也就是前半截：精确率@K（Precision at K，前 K 条里相关片段占多大比例，衡量「捞得准不准」）、召回率@K（Recall at K，全部相关片段里前 K 条捞回了多少，衡量「漏没漏」）、命中率（前 K 条里至少有一条相关就记命中）、倒数排名（第一个相关片段出现在第几位，得分就是几分之一）、以及 MRR（Mean Reciprocal Rank，平均倒数排名，把多条查询的倒数排名取平均）。再往细里还有 NDCG（Normalized Discounted Cumulative Gain，归一化折损累计增益），它不只数「相关不相关」，还承认相关也分等级、且排在越靠后越该被打折——这个我们后面用代码手算一遍。

第二组量的是「生成」，也就是后半截，通常从四个面看：上下文相关性（检索回来的片段里，跟问题真相关的占多少）、上下文召回（标准答案需要的那些事实，被检索片段覆盖了多少）、答案忠实度（答案里每一句，能不能在检索片段里找到依据，衡量有没有臆造）、答案相关性（答案里切题的句子占多少，衡量跑没跑题）。注意这四项和第一组的排序指标不在一个层面：排序好只说明「该给的片段给到了」，四项才回答「给到之后有没有被好好用」。这两组尺子必须分开算，才能把「捞错了」和「写错了」分开，见 [检索增强评测](./k064-rag-eval.md) 与 [三层评测](./k085-three-level-eval.md)。

## 生活类比

把它想成开卷考试。前半截相当于考前给你发一叠资料：老师从一整间资料室里挑出一叠纸递到你手上。精确率问的是「你手里这叠纸，有多少张是真用得上的」；召回率问的是「答这道题真正需要的那几张，你手里凑齐了没有」；倒数排名问的是「第一张能用上的资料，是这叠纸的第几张」——要是压在最底下，翻到它之前你已经浪费了半天。NDCG 则更较真：它不但看用不用得上，还给「特别关键」和「沾点边」分了等级，并且认为「关键资料压在最后」比「放在最上面」要吃亏。

后半截相当于你照着资料写答卷。上下文相关性看「老师递来的纸里有没有夹一堆无关的」；上下文召回看「标准答案要的三个论据，资料里是不是都给了」；答案忠实度看「你写下的每句话，能不能在资料里指出处」——哪怕资料齐了，你自己添了一句资料里没有的话，忠实度就要扣分；答案相关性看「你写的到底是不是这道题问的」，洋洋洒洒写了一堆却跑题，也算不上好。

对应关系再收一句：排序那组尺子量的是「发资料的人」，四项指标量的是「写答卷的人」。最要紧的一点在这里显出来——这两拨人完全可能各错各的：资料发得又准又全（排序指标全绿），考生却照样能抄都不抄、凭印象编一句（忠实度为零）；反过来，考生再老实，资料里压根没给关键那张纸（召回不足），他也只能干瞪眼。所以只夸「搜得准」或只夸「答得顺」都不算数，得两拨人的账分开记。这就是为什么改动之后要能回答「这次到底是哪一截变好了」，而不是笼统一句「感觉更准了」。

## 自绘示意图

:::figure 一次评测从排序到定位的顺序
@flow
取回候选排序|标注相关集合|算排序指标|算四项指标|定位改进点
:::

五格串成一条评测流水线，关键在「标注相关集合」和「算四项指标」这两格：前者是排序指标的地基，没有「哪些片段真相关」这个标注，精确率、召回率都无从算起；后者是生成质量的独立一摊，不能因为排序分高就跳过。最后一格「定位改进点」是整条线的目的——量分不是为了打分，是为了知道下一步该动检索还是动生成。

:::figure 生成链路的四项指标
@stack
上下文相关性::检索片段里与问题相关的比例，衡量捞得准不准
上下文召回::标准事实被检索片段覆盖的比例，衡量漏没漏
答案忠实度::答案每句能在片段找到依据的比例，衡量有没有臆造
答案相关性::答案里切题陈述的比例，衡量跑没跑题
:::

四行里最容易被忽略的是「上下文召回」和「答案忠实度」。前者专治「资料看着都有用、可关键那条没给」；后者专治「答案读着很顺、可有一句是自己编的」。这两样恰恰是「感觉不错」这种印象式评价最容易放过的地方。

:::figure 两种评价姿势的差别
@compare
只给一个总分::捞错与写错混在一起|臆造照样可能高分|改完不知动哪
两层分开各量::排序与生成分别打分|能定位是捞错还是写错|改进有落点
:::

左边是把整条链路压成一个「还行 / 不行」，省事但没法指导改动；右边多花一点标注与计算的功夫，换来的是「哪一截拖了后腿」有据可查。二者差距不在算法多聪明，而在有没有把两截的账分开。

## 层层追问

:::ask 那如果排序指标全绿——精确率、召回率都很高，是不是就能说明答案没问题了？
:::

不能，这恰恰是两组尺子必须分开的最强理由。排序指标只保证「该给的片段排在了前面」，它一句也没保证「模型照着这些片段写了」。模型完全可能把片段搁在一边，凭自己的印象补一句材料里没有的结论，或者把片段里的数字张冠李戴——这时候精确率、召回率照旧漂亮，答案却不可信。要看住这一层，得单独量答案忠实度：把答案拆成一条条陈述，逐条去检索片段里找依据，找不到依据的就算臆造，见 [引用与拒答](./k062-citation-abstain.md) 与 [数字完整性](./k124-number-integrity.md)。

再往下一层：那如果只看「命中率」这个最简单的指标，前几条里有一条相关就记一分，是不是够用了？不够。命中率对「相关文档排第几位」几乎不敏感——关键片段排在第一条和排在第九条，只要都进了前 K，它都算命中；可对生成来说，排得越靠后，越可能被后面的无关片段挤掉注意力、或干脆在截断时被切掉。所以要补倒数排名和 NDCG 这类「看位置」的指标，见 [重排](./k061-rerank.md)；多路召回时排序怎么合并，可对照 [混合检索与倒数排名融合](./k058-hybrid-rrf.md) 和 [稠密检索与稀疏检索](./k057-dense-sparse.md)。一句话：命中率只答「有没有」，位置类指标才答「够不够靠前」。

:::ask 那如果这四项指标都要人一条条标注，成本太高，有没有更省力的落地办法？
:::

这一问把话题从「量什么」推到了「怎么持续量」。四项里，「上下文相关性」「答案忠实度」「答案相关性」确实都依赖某种判断：这句话切不切题、能不能在片段里找到依据。省力的办法不是不标，而是把标注做成可复用的资产——攒一批「问题 + 标准答案需要的事实 + 哪些片段相关」的构造样例，每次改动都跑同一批，比较分数有没有退步，见 [评测数据集](./k086-eval-dataset.md)；能用确定性规则判的（比如「答案里出现的数字是否都在片段里出现过」）就写成断言，别交给主观感觉，见 [属性断言](./k088-property-assertion.md)；确实需要判断语义的，再考虑让一个评判角色按固定尺度打分，见 [裁判模型](./k090-llm-judge.md)。关键在于这批评测样例要稳定、要能重复跑，改一版提示词或换一套召回策略后，分数是升是降一目了然。

再往下一层：那分数降了，怎么知道是「真退步」还是「这批样例恰好变难了」？所以要给分数设一条可守护的线：把某一版的分数记成基线，之后任何改动要过一道回归门禁，跌破阈值就不许发布，见 [回归门禁与基线](./k091-regression-gate.md)；对反复出错的那几类问题单独归档、盯着它们有没有被修好，见 [坏例闭环](./k093-badcase-loop.md)。还要留一条更细的账：一次失败到底是走错了步骤，还是某一步工具结果不对，得靠过程记录来分，见 [轨迹评测](./k089-trajectory-eval.md)。把「量分—设线—复跑—定位」串起来，指标才从一次性的数字变成能长期用的仪表盘；而这一切的前提，仍是先有 [索引与查询两阶段](./k052-index-query-two-stage.md) 那样把检索和生成拆清楚的链路。

## 可运行代码与逐行解释

下面这段只用 Python 标准库，把「四个排序指标 + 四项生成指标」全部用可手算的构造数据实现一遍，结尾用一组断言逐条验证数值。相关集合、相关等级、标注都是手工构造的定值，每个分数都能用纸笔推算、完全可复现；复制到任意装有 Python 的机器上直接运行即可，不需要任何第三方包、账号或网络。它演示的是各指标的定义与彼此独立，不是任何真实评测组件的实现。

```python
import math


def precision_at_k(ranked, relevant, k):
    """精确率@K：前 k 条里相关文档所占比例。"""
    if k <= 0:
        return 0.0
    hit = sum(1 for d in ranked[:k] if d in relevant)
    return hit / k


def recall_at_k(ranked, relevant, k):
    """召回率@K：前 k 条捞回了全部相关文档的几分之几。"""
    if not relevant:
        return 0.0
    hit = sum(1 for d in ranked[:k] if d in relevant)
    return hit / len(relevant)


def hit_at_k(ranked, relevant, k):
    """命中率@K：前 k 条里至少有一条相关就记 1 分。"""
    return 1.0 if any(d in relevant for d in ranked[:k]) else 0.0


def reciprocal_rank(ranked, relevant):
    """倒数排名：第一个相关文档在第几位，得分就是几分之一。"""
    for pos, d in enumerate(ranked, start=1):
        if d in relevant:
            return 1.0 / pos
    return 0.0


def mrr(queries):
    """平均倒数排名 Mean Reciprocal Rank：多条查询取平均。"""
    if not queries:
        return 0.0
    return sum(reciprocal_rank(r, rel) for r, rel in queries) / len(queries)


def dcg(gains):
    """折损累计增益：位置越靠后，同一份相关性被打折越多。"""
    total = 0.0
    for i, g in enumerate(gains, start=1):
        total += (2 ** g - 1) / math.log2(i + 1)
    return total


def ndcg_at_k(ranked, gains, k):
    """归一化折损累计增益：实际排序增益 / 理想排序增益，落在 0~1。"""
    actual = [gains.get(d, 0) for d in ranked[:k]]
    ideal = sorted(gains.values(), reverse=True)[:k]
    denom = dcg(ideal)
    return dcg(actual) / denom if denom else 0.0


def context_relevance(flags):
    """上下文相关性：检索片段里与问题相关的比例。"""
    return sum(1 for f in flags if f) / len(flags) if flags else 0.0


def context_recall(gold_facts, covered):
    """上下文召回：标准答案需要的事实里，被片段覆盖的比例。"""
    if not gold_facts:
        return 0.0
    return len(set(gold_facts) & set(covered)) / len(gold_facts)


def faithfulness(claims, supported):
    """答案忠实度：陈述里能在片段找到依据的比例。"""
    return sum(1 for f in supported if f) / len(claims) if claims else 0.0


def answer_relevance(claims, on_topic):
    """答案相关性：陈述里切题的比例。"""
    return sum(1 for f in on_topic if f) / len(claims) if claims else 0.0


def main():
    # 构造：三个相关文档；每个文档一个相关等级（0 不相关，越大越相关）
    relevant = {"d1", "d3", "d5"}
    gains = {"d1": 3, "d2": 0, "d3": 2, "d4": 0, "d5": 1, "d6": 0}
    ranked_bad = ["d2", "d1", "d4", "d3", "d5", "d6"]   # 不相关的排最前
    ranked_good = ["d1", "d3", "d5", "d2", "d4", "d6"]  # 相关的排最前

    checks = [
        ("精确率@3 手算为三分之一",
         abs(precision_at_k(ranked_bad, relevant, 3) - 1 / 3) < 1e-9),
        ("好排序精确率@3 为满分",
         precision_at_k(ranked_good, relevant, 3) == 1.0),
        ("召回率@3 手算为三分之一",
         abs(recall_at_k(ranked_bad, relevant, 3) - 1 / 3) < 1e-9),
        ("召回率@6 捞回全部相关",
         recall_at_k(ranked_bad, relevant, 6) == 1.0),
        ("召回率随 K 增大不下降",
         recall_at_k(ranked_bad, relevant, 6)
         >= recall_at_k(ranked_bad, relevant, 3)),
        ("差排序命中率@1 为零", hit_at_k(ranked_bad, relevant, 1) == 0.0),
        ("差排序命中率@3 为一分", hit_at_k(ranked_bad, relevant, 3) == 1.0),
        ("差排序倒数排名为二分之一",
         reciprocal_rank(ranked_bad, relevant) == 0.5),
        ("好排序倒数排名为满分",
         reciprocal_rank(ranked_good, relevant) == 1.0),
        ("两条查询平均倒数排名为零点七五",
         abs(mrr([(ranked_bad, relevant), (ranked_good, relevant)]) - 0.75) < 1e-9),
        ("好排序折损增益归一化为满分",
         abs(ndcg_at_k(ranked_good, gains, 3) - 1.0) < 1e-9),
        ("差排序折损增益低于好排序",
         ndcg_at_k(ranked_bad, gains, 3) < ndcg_at_k(ranked_good, gains, 3)),
        ("折损增益落在零到一之间",
         0.0 <= ndcg_at_k(ranked_bad, gains, 3) <= 1.0),
    ]

    # 生成链路四项：构造一份标注齐全的样例
    ctx_flags = [True, False, True, False]          # 4 个片段里 2 个相关
    gold = ["f1", "f2", "f3"]                       # 答案需要的 3 个事实
    covered = ["f1", "f3"]                          # 片段只覆盖 2 个
    claims = ["c1", "c2", "c3", "c4"]              # 答案 4 句陈述
    supported = [True, True, True, False]           # 3 句有依据，1 句臆造
    on_topic = [True, True, False, True]            # 3 句切题
    four = {
        "上下文相关性": context_relevance(ctx_flags),
        "上下文召回": context_recall(gold, covered),
        "答案忠实度": faithfulness(claims, supported),
        "答案相关性": answer_relevance(claims, on_topic),
    }
    checks.append(("上下文相关性为零点五", abs(four["上下文相关性"] - 0.5) < 1e-9))
    checks.append(("上下文召回为三分之二", abs(four["上下文召回"] - 2 / 3) < 1e-9))
    checks.append(("答案忠实度为四分之三", abs(four["答案忠实度"] - 0.75) < 1e-9))
    checks.append(("答案相关性为四分之三", abs(four["答案相关性"] - 0.75) < 1e-9))
    checks.append(("四项指标齐全", len(four) == 4))

    # 关键性质：排序全绿，忠实度仍可能为零，两层不能互相替代
    checks.append(("排序满分但忠实度仍可为零",
                   precision_at_k(ranked_good, relevant, 3) == 1.0
                   and faithfulness(["x", "y"], [False, False]) == 0.0))

    passed = sum(1 for _, good in checks if good)
    for name, good in checks:
        print(("通过 " if good else "失败 ") + name)
    print("通过 %d/%d 项" % (passed, len(checks)))
    assert passed == len(checks), "存在未通过项"


if __name__ == "__main__":
    main()
```

1. `precision_at_k` 与 `recall_at_k` 是同一件事的两个分母：前者除以 `k`（我给了几条结果），后者除以 `len(relevant)`（本该捞回几条）。前 3 条里命中 1 条相关，精确率是 `1/3`；三条相关里只捞回 1 条，召回率也是 `1/3`——数字碰巧一样，但含义完全不同，代码里两个分母把它们分得清清楚楚。
2. `hit_at_k` 用 `any` 判断「前 k 条里有没有至少一条相关」，`reciprocal_rank` 用 `enumerate(..., start=1)` 找第一个相关文档的位置、返回 `1.0 / pos`，`mrr` 再把多条查询的倒数排名取平均。差排序里第一个相关 `d1` 排第 2，倒数排名 `0.5`；好排序里排第 1，得 `1.0`；两条查询平均即 `0.75`，这些都能纸笔算出来。
3. `dcg` 是折损累计增益（Discounted Cumulative Gain）：对第 `i` 位的等级 `g`，先算增益 `2 ** g - 1`（等级越高增益越大），再除以 `log2(i + 1)`（位置越靠后打折越狠）。`ndcg_at_k` 用「实际排序的 DCG」除以「把全部等级从高到低重排后的理想 DCG（IDCG，Ideal Discounted Cumulative Gain）」，结果落在 0 到 1。好排序的前三条恰好是等级 `3、2、1`，与理想顺序一致，所以归一化后正好是 `1.0`。
4. 四个生成指标都刻意写成「命中数 / 总数」的确定性比例：`context_relevance` 数相关片段占比，`context_recall` 用集合交 `set(gold) & set(covered)` 算标准事实被覆盖了几分之几，`faithfulness` 数有依据的陈述占比，`answer_relevance` 数切题陈述占比。它们没有调用任何模型，判断完全来自传入的标注，因此分数稳定、可复现。
5. `main` 前半段构造一组可手算的排序数据：`relevant` 是三个相关文档，`gains` 给每个文档一个相关等级，`ranked_bad` 把不相关的 `d2` 排在最前、`ranked_good` 把相关的排在最前。第一组十三条断言逐项核对精确率、召回率、命中率、倒数排名、平均倒数排名、归一化折损增益，以及「召回率随 K 不下降」「折损增益落在 0~1」这些该守的性质。
6. 后半段构造一份四项指标的标注样例：4 个片段 2 个相关、3 个标准事实只覆盖 2 个、4 句陈述 3 句有依据、3 句切题，于是四项分别是 `0.5`、`2/3`、`0.75`、`0.75`，逐条断言。浮点比较统一用 `abs(x - y) < 1e-9`，避开二进制小数无法精确表示的问题。
7. 最后一条断言是整段的题眼：即便 `ranked_good` 的精确率@3 是满分 `1.0`，只要把答案陈述的依据全标成 `False`，忠实度就是 `0.0`——用一行代码钉死「排序好不等于答案可信」。结尾 `passed` 统计通过项、逐条打印结果，再用 `assert` 保证任何一条性质被破坏都会以非零状态退出。

有一处要如实说明：这里用手工标注的真假值代替了真实的相关性判断、用六篇文档代替了真实索引、用集合交代替了语义匹配，全是为了让每个分数都能用纸笔推算、不需要联网、账号或第三方包就能独立跑通。它演示的是各指标的定义、算法与「两层彼此独立」这条性质，不是任何真实评测系统或数据集上的结论；代码本身经过逐行静态复核到「复制即跑、逻辑自洽」，并未在此环境里实际启动执行。

## 踩坑与边界

- **只用一个笼统总分**：现象是「感觉还行」说不清好在哪，改完也不知动哪截 → 原因是把检索和生成的账记在了一起 → 排序指标与四项生成指标分开算，见 [检索增强评测](./k064-rag-eval.md) 与 [三层评测](./k085-three-level-eval.md)。
- **只看命中率不看位置**：现象是关键片段排到很后面仍算「命中」，生成时却被截断或淹没 → 原因是命中率对顺序不敏感 → 补倒数排名与归一化折损增益，并把靠后的相关片段往前挪，见 [重排](./k061-rerank.md)。
- **排序满分就以为答案可信**：现象是片段又准又全，答案里却混进一句材料里没有的结论 → 原因是没单独量忠实度 → 把答案拆成陈述逐条找依据，见 [引用与拒答](./k062-citation-abstain.md) 与 [属性断言](./k088-property-assertion.md)。
- **评测样例每次现凑**：现象是这版分数比上版高，其实是题目变简单了，分数没法比 → 原因是没有固定的评测集与基线 → 攒一批可复用的构造样例，改动后都跑同一批并守住回归线，见 [评测数据集](./k086-eval-dataset.md) 与 [回归门禁与基线](./k091-regression-gate.md)。
- **把相关性当非黑即白**：现象是「沾点边」和「正好是答案那段」被算成一样，排序分数失真 → 原因是只用相关/不相关两级 → 引入等级并用折损增益把位置和等级一起算进去，见 [查询改写](./k059-query-rewrite.md) 与 [元数据过滤](./k060-metadata-filter.md)。

还要说清一条边界：这些指标不是「分越高就万事大吉」。它们全都依赖「哪些片段真相关」「哪些陈述算有依据」这些标注，标注本身若偏了，分数再漂亮也只是精确地量错了东西；而一组离线分数也照不到真实提问里的长尾、并发和下游状态，所以分数要当仪表盘用、不当奖状用。另外，精确率和召回率常常此消彼长——多捞几条能提高召回却拉低精确率，取舍得看这一环到底更怕「漏」还是更怕「吵」，见 [索引与查询两阶段](./k052-index-query-two-stage.md)。若想从整体上看清这一截在整条链路里的位置，可对照 [为什么需要检索增强](./k051-why-rag.md)。

## 三句话小结

这套指标，是把「搜得怎么样」和「答得怎么样」拆成两组尺子：前一组量候选片段排得准不准、全不全、靠不靠前，后一组从上下文相关性、上下文召回、答案忠实度、答案相关性四个面查生成链路可不可信。

关键做法是先把「哪些片段真相关」标注清楚，再让每个指标都算成可手算复现的确定性比例，用固定评测集反复跑、分数设基线守住回归线，靠两层分数的差异定位到底该改检索还是改生成。

当系统只是把文档原样返回、根本不生成答案时，四项生成指标里与答案相关的那几项便用不上；但只要会让模型照着片段写话，就别再用一句笼统的「感觉不错」代替分层量分。
